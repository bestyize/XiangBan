<a id="elevator-pitch"></a>
## 简介

吐槽时间：你一定听过 Git 很_强大_，但如果每件事都这么难做，强大有什么用？交互式变基居然需要在编辑器里修改一个 TODO 文件？_开什么玩笑？_ 要暂存文件的一部分，必须用命令行程序逐块处理；如果某个块不能再拆分，却包含不想暂存的代码，还得_手动_编辑晦涩的补丁文件？_真的在开玩笑吧？！_ 有时切换分支时被要求暂存更改，切换并恢复后才发现根本没有冲突，直接检出分支也完全没问题？_这肯定是在开玩笑！_

如果你和我一样只是普通人，听腻了 Git 有多强大，而它在日常使用中却给你带来很大麻烦，lazygit 可能适合你。

<a id="stage-hunks-or-individual-lines"></a>
### 暂存代码块或单独的行

在变更文件上按 `0`，使其差异在主视图中获得焦点。初始选区覆盖整个代码块，因此按 `<space>` 会暂存该块并移至下一个。若只需代码块的一部分，按 `a` 逐行选择，按 `v` 选择一段行。已暂存内容显示在下方窗格。按 `<tab>` 在两个窗格间切换；在下方窗格按 `<space>` 可取消暂存。按 `c` 可在不离开差异视图的情况下提交。

<a id="interactive-rebase"></a>

<a id="changing-directory-on-exit"></a>
### 退出时切换目录

如果在 lazygit 中切换了仓库，并希望退出时 shell 也切换到该仓库目录，请将以下内容添加到 `~/.zshrc`（或其他 rc 文件）：

```
lg()
{
    export LAZYGIT_NEW_DIR_FILE=~/.lazygit/newdir

    lazygit "$@"

    if [ -f $LAZYGIT_NEW_DIR_FILE ]; then
            cd "$(cat $LAZYGIT_NEW_DIR_FILE)"
            rm -f $LAZYGIT_NEW_DIR_FILE > /dev/null
    fi
}
```

然后执行 `source ~/.zshrc`。此后运行 `lg` 并退出时，shell 会切换到你在 lazygit 中所在的目录。如需覆盖此行为，可用 `shift+Q` 而不是 `q` 退出。

<a id="git-flow-support"></a>
### Git flow 支持

如果已安装 [Gitflow](https://github.com/nvie/gitflow)（或 [git-flow-next](https://github.com/gittower/git-flow-next)），Lazygit 支持使用它。要了解 Gitflow 模型的工作方式，请参见 Vincent Driessen 的原始[说明文章](https://nvie.com/posts/a-successful-git-branching-model/)。在 Lazygit 的分支视图中按 `i` 可查看 Gitflow 选项。

## FAQ

<a id="what-do-the-commit-colors-represent"></a>
### 提交颜色代表什么？

- 绿色：提交已包含在 master 分支中
- 黄色：提交未包含在 master 分支中
- 红色：提交尚未推送到上游分支
