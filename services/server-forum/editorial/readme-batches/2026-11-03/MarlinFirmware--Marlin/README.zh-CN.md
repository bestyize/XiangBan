## Marlin 2.1 错误修复分支

**不适用于生产用途。请谨慎使用！**

Marlin 2.1 同时支持 32 位 ARM 和 8 位 AVR 开发板，并增加对最多 9 个协调轴和最多 8 个挤出机的支持。

此分支用于最新 2.1.x 发布版本的补丁，并会定期成为下一个 2.1.x 次版本的基础。

可在[发布页面](https://github.com/MarlinFirmware/Marlin/releases)下载早期版本。

## 示例配置

为你的机器构建 Marlin 之前，需要适用于具体硬件的配置。应要求，供应商会提供机器的完整源代码和配置；但如果想安装较新版本的 Marlin，需要获取更新的配置文件。Marlin 用户贡献了数百种经过测试的配置供你入门。请访问 [MarlinFirmware/Configurations](https://github.com/MarlinFirmware/Configurations) 仓库查找适合你的硬件的配置，并确保选择兼容分支！[Marlin 下载页面](https://marlinfw.org/meta/download/)提供相互兼容的软件和配置包。

## 构建 Marlin 2.1

构建和上传 Marlin 时可使用以下工具之一：

- 免费的 [Visual Studio Code](https://code.visualstudio.com/download)，配合 [Auto Build Marlin](https://marlinfw.org/docs/basics/auto_build_marlin.html) 扩展。
- Marlin 针对 Visual Studio Code 的 [PlatformIO IDE](https://platformio.org/) 扩展进行了构建优化。
- 也可以将 VSCode 与 devcontainer 一起使用：参阅[安装 Marlin（VSCode devcontainer）](https://marlinfw.org/docs/basics/install_devcontainer_vscode.html)。
- 仍可以使用 [Arduino IDE](https://www.arduino.cc/en/main/software) 构建 Marlin：参阅[使用 Arduino 构建 Marlin](https://marlinfw.org/docs/basics/install_arduino.html)。我们希望改进 Arduino 构建体验，但目前首选 PlatformIO。

## 32 位 ARM 开发板

Marlin 兼容大量 32 位 ARM 开发板，它们提供充足的计算能力和内存，使 Marlin 能为现代 3D 打印机提供先进性能和功能。Marlin 的一些较新功能需要使用 32 位 ARM 开发板。

## 8 位 AVR 开发板

Marlin 起源于基于 Arduino 的 8 位开发板时代，我们希望永久支持 8 位 AVR 开发板。32 位和 8 位开发板由同一个适用于所有机器的代码库支持。我们的目标是支持普通爱好者、动手玩家以及旧机器和旧开发板的拥有者，让他们与拥有更新、更高端设备的人一样受益于社区创新。此外，这些老牌 AVR 机器通常也最适合测试和反馈！

## 硬件抽象层（HAL）

Marlin 的硬件抽象层为所有目标平台提供通用 API，使 Marlin 代码可以无系统开销地处理最低层和最高层的运动及用户界面任务，并将所有事件直接绑定到硬件时钟。

每个新的 HAL 都会带来新的硬件选择。Marlin 当前拥有十多个平台的 HAL。AVR 和 STM32 最为知名和流行，ESP32、LPC1768 等也支持多种较少见的开发板。目前 RP2040 的 HAL 处于 beta 阶段；我们希望为 Duet3D 系列开发板增加 HAL。封装 RTOS 的 HAL 是一个值得探索的有趣概念。

你知道 Marlin 包含可在 Windows、macOS 和 Linux 上运行的模拟器吗？加入 Discord，帮助推动这些子项目！

## 贡献补丁

请向 [bugfix-2.1.x](https://github.com/MarlinFirmware/Marlin/tree/bugfix-2.1.x) 分支提交 Pull Request，贡献你的补丁。

- 我们使用 `bugfix-2.1.x` 分支修复错误，并将新功能集成到最新固件中。请谨慎使用！
- 我们维护 `lts-x.x.x` 分支，主要供供应商使用，以便按需为旧版 Marlin 打补丁，保持其功能并修复错误。
- 遵循[代码规范](https://marlinfw.org/docs/development/coding_standards.html)有助于获得维护者认可。
- 请向[问题队列](https://github.com/MarlinFirmware/Marlin/issues/new/choose)提交功能请求和错误报告。用户支持请见上文。
- 添加新功能时，务必向 `buildroot/tests` 添加一个或多个构建测试。添加到 PR 的测试一经推送就会在 GitHub 服务器上运行。如有可能，请先在本地运行新测试，以减少迭代。
  - 本地构建测试：
    - 全部：`make tests-config-all-local`
    - 单项：`make tests-config-single-local TEST_TARGET=...`
  - Docker 中的本地构建测试：
    - 全部：`make tests-config-all-local-docker`
    - 单项：`make tests-config-single-local-docker TEST_TARGET=...`
  - 运行所有单元测试套件：
    - 使用 PIO：`platformio run -t test-marlin`
    - 使用 Make：`make unit-test-all-local`
    - 使用 Docker + make：`make unit-test-all-local-docker`
  - 运行单个单元测试套件：
    - 使用 PIO：`platformio run -t marlin_<test-suite-name>`
    - 使用 make：`make unit-test-single-local TEST_TARGET=<test-suite-name>`
    - 使用 Docker + make：`make unit-test-single-local-docker TEST_TARGET=<test-suite-name>`
- 如果功能可以进行单元测试，请添加一个或多个单元测试。更多信息参阅[单元测试](https://github.com/MarlinFirmware/Marlin/tree/6e03341e0436b076f8339f0f702be18a05f81522/test)文档。
