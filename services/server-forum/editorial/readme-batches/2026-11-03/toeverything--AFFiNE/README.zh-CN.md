## AFFiNE 是什么

[AFFiNE](https://affine.pro) 是一个开源的一体化工作空间，也是组织知识库及更多内容的构建模块的操作系统——包括 wiki、知识管理、演示和数字资产。项目将其定位为比 Notion 和 Miro 更好的替代方案。

## 功能

**容纳各种形式模块的画布，文档和白板现已完全融合。**

- 许多编辑应用称自己为生产力画布，而项目表示 AFFiNE 是少数允许你将各种构建模块放在无边界画布上的产品之一，包括富文本、便签、嵌入网页、多视图数据库、关联页面、形状，甚至幻灯片；这些能力均已提供。

**可协助各种工作的多模态 AI 伙伴**

- 撰写专业工作报告？将大纲变成适合展示的幻灯片？把文章总结为结构清晰的思维导图？整理工作计划与待办任务？或者，仅用一个提示词直接绘制并编写应用和网页原型？项目表示 [AFFiNE AI](https://affine.pro/ai) 可将创造力推向想象力的边界，[Canvas AI](https://affine.pro/blog/best-canvas-ai) 也可生成思维导图用于头脑风暴。

**本地优先与实时协作**

- 我们认同本地优先理念：即使使用云端，你仍在自己的磁盘上拥有数据。此外，AFFiNE 支持 Web 和跨平台客户端之间的实时同步与协作。

**自托管并塑造自己的 AFFiNE**

- 你可以自由管理、自托管、Fork 和构建自己的 AFFiNE。插件社区及第三方模块即将推出。更多动态参阅 [Blocksuite](https://blocksuite.io)，并可了解如何[自托管 AFFiNE](https://docs.affine.pro/self-host-affine)。

## 致谢

“我们塑造工具，此后工具也塑造我们。”许多先行者在这个过程中启发了我们，例如：

- Quip 与 Notion 的“一切皆为模块”理念
- Trello 的看板
- Airtable 与 Miro 的无代码可编程数据表
- Miro 与 Whimiscal 的无边界可视白板
- Remote 与 Capacities 的基于对象的标签系统

这些应用的基础“构建模块”有大量重叠。项目团队认为它们并不开源，也没有像 VS Code 那样供贡献者自定义的插件系统。我们希望构建一个包含喜爱功能并更进一步的工具。

感谢你的关注，我们真诚希望 AFFiNE 能与你产生共鸣！🎵 更多信息请查看 https://affine.pro/。

## 上游项目

我们还要感谢使 AFFiNE 成为可能的开源项目：

- [Blocksuite](https://github.com/toeverything/BlockSuite) - 💠 BlockSuite 是 AFFiNE 背后的开源协作编辑器项目。
- [y-octo](https://github.com/y-crdt/y-octo) - 🐙 y-octo 是原生、高性能且线程安全的 YJS CRDT 实现，是帮助 AFFiNE 客户端／服务器实现“本地优先”功能的核心引擎。
- [OctoBase](https://github.com/toeverything/OctoBase) - 🐙 OctoBase 是 AFFiNE 背后的开源数据库，本地优先且支持协作。它是用 Rust 编写的轻量、可扩展数据引擎。

- [yjs](https://github.com/yjs/yjs) - 为 Web 端状态管理和数据同步实现提供 CRDT 基础支持。
- [electron](https://github.com/electron/electron) - 使用 JavaScript、HTML 和 CSS 构建跨平台桌面应用。
- [React](https://github.com/facebook/react) - 用于 Web 和原生用户界面的库。
- [napi-rs](https://github.com/napi-rs/napi-rs) - 通过 Node-API 使用 Rust 构建编译型 Node.js 插件的框架。
- [Jotai](https://github.com/pmndrs/jotai) - 简单、灵活的 React 状态管理。
- [async-call-rpc](https://github.com/Jack-Works/async-call-rpc) - 轻量级 JSON RPC 客户端与服务器。
- [Vite](https://github.com/vitejs/vite) - 下一代前端工具。
- 其他上游[依赖](https://github.com/toeverything/AFFiNE/network/dependencies).

非常感谢社区提供这些强大而简洁的库，让我们能够更加专注于产品逻辑的实现。我们也希望未来的项目能为大家提供更易用的知识库。
