如果每次都要粘贴同一份检查清单，可以考虑把它整理成 Skill。适合复用的是稳定流程，而不是把某次任务的聊天全文打包进去。

以文档发布前检查为例，技能可以明确：检查标题层级、验证引用链接、列出未核实事实、生成结果报告。输入是文档目录，输出是问题清单；不包含自动发布，除非任务本身明确授权。

Claude Code 与 Codex 的官方说明都使用 SKILL.md 组织技能，但目录位置、发现方式和配置细节应各自核对。技能名称和描述要讲清什么时候用，正文再写步骤；长参考资料分文件存放，避免无关任务也加载整套说明。

可执行脚本要单独审查：会读哪些路径、写哪些文件、是否联网、是否可能覆盖原稿。不要因为脚本被放进技能目录，就默认它可信。

最后用两个例子测试：一个应该触发的发布检查任务，一个只是普通文字问答的任务。前者应产出可核对的报告，后者不该擅自操作文件。只有重复工作足够明确时，技能才会比一段普通提示词更省心。

资料：[Claude Code 技能文档](https://code.claude.com/docs/en/skills)；[Codex 技能文档](https://learn.chatgpt.com/docs/build-skills.md)。
