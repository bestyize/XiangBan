小伴 AI · 手机聊天窗口与全卡片体系

统一 16px 白底细框卡片语法 · 通栏流式排版 · 三合一过程摘要卡 · 交付/提醒/生图/审批/提问/文件变更/方案与异常全覆盖

01 · 作品交付态

同场景优化 · 可交互

通栏流式排版；长消息默认 4 行柔和折叠；三层过程条收敛为单行摘要卡；作品信息和「打开」收进独立交付卡。

02 · 执行中与过程展开

微信绿 / 失败红状态点

过程卡内部分页展示步骤、任务清单与思考摘要；15px 微信绿圆 + 白对勾与红圆 + 白叉号让成败一目了然。

03 · 交互待办与内容卡

提醒 · 生图 · 代码 · 审批 / 提问

顶部可切底栏交互卡：「普通审批 / 高危审批 / 小伴提问」；消息流内置本机提醒卡、生图结果卡与代码块，全部采用同源白底细框。

04 · 变更、方案与异常态

文件变更 · 撤销 · 方案确认 / 续作

覆盖顶部并行任务条、新话题分割线、可折叠文件变更卡、检查点撤销条、额度与截断异常条，以及底部「方案确认 / 中断续作」卡片。

05 · 现行版对照

截图还原 · 痛点参考

左侧小头像挤占宽度；浅粉+粉框气泡偏重；三层状态条叠罗汉；通栏淡粉按钮无卡片边界且紧贴输入框。

统一容器语言

所有消息内卡片与贴底交互卡共用白底 + 1px 发丝框 + 14~18px 圆角 + 轻阴影，告别“实心灰条 / 阴影白卡 / 淡粉通栏”各画各的。

严格控色与语义分工

90% 中性黑白灰；主题色只落每屏核心主按钮与无底星标；成功用微信绿圆 + 白对勾，警示用琥珀，失败与高危用语义红。

贴底待办卡与输入区分层

审批、提问、方案确认、中断续作全部收进独立悬浮卡片（18px 圆角 + 轻投影），不再把两颗裸按钮直接糊在输入框上面。

信息折叠与节奏克制

长用户指令默认 4 行可展开，思考/清单/步骤三合一，文件变更默认紧凑折叠，异常条单行带清晰主操作，把舞台还给对话正文。
