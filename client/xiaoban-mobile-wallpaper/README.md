# 小伴壁纸 Android App

状态：可运行原型。浏览壁纸网站的图片和视频，收藏到本机，下载到手机相册。只访问壁纸网站的公开接口，没有账户，不连接主 API。iOS 不在范围内。

早期版本做过"设为动态壁纸"，在小米/Redmi 的系统壁纸选择器上会被直接丢弃，已放弃这条路线并删除了相关代码。需要设置壁纸时，从相册里选图用系统自带功能。

## 运行

需要 JDK 17+、Android SDK（compileSdk 37），最低 Android 10。在本目录创建不入库的 `local.properties`：`sdk.dir=/path/to/Android/sdk`。工程有独立的 Gradle wrapper（9.6.0），不接入仓库根 Gradle。

```sh
cd client/xiaoban-mobile-wallpaper
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 界面

底部四个 Tab，风格参考小红书：红色主色、白底卡片、双列瀑布流、文字 Tab（样式凭印象还原，不是官方规范）。

瀑布流按每张图片的真实宽高比排版，封面完整显示、不裁切；高度由接口给出的尺寸预先算好，图片加载前后版面不会跳动（已核对封面实际比例与接口声明一致）。只对小于 1:4 或大于 4:1 的异常值设边界。

- 壁纸：网站的图片。顶部分类标签和搜索，下拉刷新，滚到底自动加载下一页。
- 视频：网站的视频，卡片右上角有播放标记。
- 收藏：点卡片右下角的心形收藏，保存在本机的一个 JSON 文件里，不上传，卸载应用后清除。
- 我的：已下载列表（相册中的缩略图，可查看或删除）和设置（清除图片缓存、保存位置、版本）。小伴在这里出场，空状态、加载中、出错时也由它说话。

点卡片进入详情：大图或视频封面、标签、收藏、保存到相册。点图片进入全屏查看，点视频的播放按钮进入全屏播放（见下）。保存时显示"下载中 35% · 38.5 MB / 110.0 MB"，可取消，失败可重试，成功后变为"已保存到相册 · 查看"。

## 全屏查看与播放

- 图片：双指捏合缩放（最大 6 倍）、单指拖动（缩放后，到边缘停住）、双击放大到 2.5 倍并以点击处为中心、再双击还原、单击显示或隐藏关闭按钮、未放大时上下拖动超过屏高 15% 即关闭（背景随拖动变淡）。全屏加载站点提供的较大版本，并以原尺寸解码，放大后能看到真实细节。手势逻辑的算术部分有 JVM 单测，手势接线部分用 Compose 触摸测试在模拟器上验证（捏合、拖动、双击、下拉关闭、点击）。
- 视频：Media3 播放，边下边播，已下载的部分存在磁盘缓存里（上限 512 MB，设置里可清除），循环时不再走网络；进度条、缓冲提示、失败重试、切到后台自动暂停。播放器自带全屏按钮可切横屏。
- 本机相册里已保存的图片和视频也用同一个查看器：在"我的"页点卡片查看，长按出现"在相册中打开 / 删除"。

## 下载与相册

优先使用图片/视频提供方（Pexels、Pixabay 等）的原始链接，失败再用网站自存的备份。流程：请求交付清单 `?prefer=source`；清单里有 `source` 就直接下这个链接；失败（网络、被拦截、返回网页、类型不对、系统解不了码）则用 `resource`（网站自存副本，按清单校验大小和 SHA-256）；网站还没有副本时再请求不带参数的接口让网站现做一份。提供方链接的文件按真实类型判断，不拿它和清单里的哈希比较（那是自存副本的哈希）。旧版网站没有 `source` 字段时，行为与以前完全一致。所有路径都只允许 HTTPS，按文件头确认真实格式（PNG/JPEG/WebP/GIF/BMP/AVIF 图片，MP4/WebM 视频）、确认系统能解码，然后通过 MediaStore 写入相册 `Pictures/小伴壁纸` 或 `Movies/小伴壁纸`。Android 10 及以上不需要存储权限。同样内容（按哈希）不会重复保存。

## 代码

- `data/`：`SiteClient`/`SiteParser` 访问网站并严格解析；`Verified` 边下载边计算哈希并限制大小；`MediaSniffer` 按文件头识别格式；`Gallery` 写入相册和命名；`LocalStores` 保存收藏与下载记录（原子写入）；`Downloader` 串起整个下载流程；`RetryWhenBusy` 在图片主机返回 429 时退避重试。
- `ui/`：Jetpack Compose。`App` 根布局和 Tab，`FeedScreen` 图片/视频流，`Cards` 卡片和瀑布流，`DetailScreen` 详情与保存，`LocalScreens` 收藏页和我的页，`FeedViewModel`/`AppViewModel` 管状态，`PetFace` 把小伴画进 Compose。
- `companion/` 与 `render/`：小伴角色引擎，从桌面版 `src/companion` 移植的纯 Kotlin 实现，现在只用来画头像和空状态。
- 图片加载用 Coil 3，磁盘缓存 256 MB；每个图片主机最多同时 2 个请求。

## 验证

JVM 单测 98 个，另有 7 个模拟器上的 Compose 触摸测试：角色引擎 10；网站协议解析（含站内相对路径补全、拒绝不安全地址）、下载哈希与大小限制、取消清理、文件头识别、收藏与下载记录存储（含旧版收藏文件兼容）、相册命名、数字与封面比例格式、下载进度文案、429 退避。

在 API 36 ARM64 模拟器上走通：冷启动加载瀑布流、分类、详情、收藏、保存到相册（MediaStore 查询到条目，文件在 `Pictures/小伴壁纸/`）、我的页缩略图、设置页、视频保存失败时的提示。发布构建（R8 压缩）可以编译，约 2.7 MB。

视频保存（105 MB，哈希与网站清单一致）、下载中进度与取消（取消后无残留临时文件）、从"我的"页删除（相册、系统索引、应用记录同步清除）在模拟器上验证。真机（Redmi K40）上验证了安装、四个 Tab、图片瀑布流和分类、图片保存到相册。

没有验证：真机上保存视频；搜索输入；功耗；真实网站上的 `?prefer=source`（服务端改动尚未部署，客户端只对着单元测试里的模拟网站验证了这条协议）。

## 已知问题

- 视频是 4K、码率 17~25 Mbps（14~174 MB），而实测手机到网站的速度只有约 1~1.5 Mbps，在线播放会一直缓冲。播放功能本身在模拟器上正常。要改善需要网站提供 720p 左右的预览版本。

- 目前网站的素材全部是横图（抽样 144 条，宽高比 1.25 到 1.9，没有竖图），所以同一列里高度差别有限，错落感不如竖图多的图库。有竖图后瀑布流会更明显。

- 网站的封面和图片直接指向 Pixabay 等第三方地址，国内网络慢，且 Pixabay 会对集中请求返回 429。客户端已做限流和退避，但根治需要网站自己缓存封面。
- 详情页显示的分辨率是素材原始尺寸，实际保存的是网站交付的副本，两者可能不同。
- 网站曾经把素材放在 Pixabay 等第三方地址，现在已改为自己托管（返回 `/uploads/...` 相对路径，应用按网站地址补全）。网站还偶尔对个别素材交付失败，应用会如实显示网站返回的原因。
- 收藏保存的是卡片快照；收藏后网站下架的壁纸，仍会显示快照，点开可能加载失败。
- 没有桌面版的 Canvas 脚本壁纸、订阅清单、更新检查和自启动。

## 大仓开发边界

不导入 `client/xiaoban-desktop-wallpaper` 或其他客户端的源码；网站协议类型由本工程自行维护，字段以 `services/server-xiangban-wallpaper/docs/desktop-api.md` 为准。修改角色行为时同步比较桌面版并运行本工程单测。暂无 CI 工作流。
