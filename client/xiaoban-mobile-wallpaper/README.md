# 小伴壁纸 Android App

状态：可运行原型。浏览壁纸网站的图片和视频，收藏到本机，下载到手机相册。壁纸内容只访问壁纸网站的公开接口；可用邮箱验证码登录小伴统一账号（与桌面版、网站同一个账号），收藏和下载仍只在本机，不连接主 API。iOS 不在范围内。

早期版本做过"设为动态壁纸"，在小米/Redmi 的系统壁纸选择器上会被直接丢弃，已放弃这条路线并删除了相关代码。需要设置壁纸时，从相册里选图用系统自带功能。

## 运行

需要 JDK 17+、Android SDK（compileSdk 37），最低 Android 10。在本目录创建不入库的 `local.properties`：`sdk.dir=/path/to/Android/sdk`。工程有独立的 Gradle wrapper（9.6.0），不接入仓库根 Gradle。

```sh
cd client/xiaoban-mobile-wallpaper
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 界面

底部是白色悬浮胶囊 Tab，浮在内容上方、列表从它下面滚过，列表末尾留出空位不被挡住（自绘圆角线条图标，选中项展开成红色胶囊）。配色对标小红书，全部纯色、不用渐变：主色红 #FF2442（选中、按钮、收藏心形，上面用白字），正文 #333333，次要文字 #999999，提示 #C4C4C4，页面底 #F7F7F7，分割线 #EEEEEE，话题标签用深蓝 #13386C。壁纸、视频和收藏是单列大图卡片（圆角 20dp，标题和尺寸叠在图下方的黑色渐隐遮罩上，右上角收藏按钮）；“我的”页的已下载是双列小图。详情页大图在上，下方白色圆角面板放标题、标签和信息卡，底部是圆形收藏按钮和红色“保存到相册”。

瀑布流按每张图片的真实宽高比排版，封面完整显示、不裁切；高度由接口给出的尺寸预先算好，图片加载前后版面不会跳动（已核对封面实际比例与接口声明一致）。只对小于 1:4 或大于 4:1 的异常值设边界。

- 壁纸：网站的图片。标题栏右侧有“全部 / 竖版 / 横版”切换（请求网站搜索接口的 `orientation=portrait|landscape`，由服务端过滤，和分类、关键词可叠加），下方是分类标签，下拉刷新，滚到底自动加载下一页。视频页同样支持。
- 视频：网站的视频，卡片右上角有播放标记。
- 收藏：点卡片右下角的心形收藏，保存在本机的一个 JSON 文件里，不上传，卸载应用后清除。
- 我的：顶部是账号卡片（未登录显示“登录 / 注册”，点开登录弹窗；已登录显示昵称和邮箱，右侧“退出”需二次确认），然后是已下载和收藏的数量，下面是进入设置页的入口，再下面是已下载列表（相册中的缩略图，可查看或删除）。小伴在这里出场，空状态、加载中、出错时也由它说话。
- 设置：从“我的”页进入，分外观、存储、关于三组。外观里是深色模式（跟随系统 / 浅色 / 深色，选择存在本机，默认跟随系统）；存储里是清除图片和视频缓存、保存位置；关于里是壁纸来源和版本。颜色都在 `ui/Theme.kt` 的 `Palette` 里，浅色和深色各一套，红色主色两边相同。

点卡片进入详情：大图或视频封面、标签、收藏、保存到相册。点图片进入全屏查看，点视频的播放按钮进入全屏播放（见下）。保存时显示"下载中 35% · 38.5 MB / 110.0 MB"，可取消，失败可重试，成功后变为"已保存到相册 · 查看"。

## 账号

登录走统一账号中心 `https://account.xiangban.xyz`（和桌面版同一套），`client_id` 固定为 `xiaoban-mobile-wallpaper`，壁纸服务端和账号中心都已放行这个 ID，服务端无需改动。

- 登录弹窗：居中白色圆角卡片压在半透明遮罩上，右上角关闭；邮箱 + 6 位验证码，验证码框右侧是“获取验证码”（发送后按服务端给的冷却秒数倒计时，默认 60 秒）；红色圆角“登录”按钮，邮箱合法且填满 6 位才可点。未注册的邮箱验证通过后自动创建账号。错误（验证码不对、请求过快、断网）显示在按钮上方，提交中弹窗不可关闭。
- 接口：`POST /api/auth/code/send`、`/api/auth/code/login`、`/api/auth/refresh`、`/api/auth/logout`，字段以 `services/server-account` 为准。
- 登录状态存在应用私有目录 `files/account.json`（原子写入；`allowBackup=false`，不会进云备份）。访问令牌约 30 分钟过期，启动时若剩余不足 2 分钟就用刷新令牌换新（刷新令牌一次一用，返回的新令牌替换旧的）。只有账号中心明确拒绝才会清除登录并提示重新登录，没网时保留登录状态。
- 退出：先清除本机状态，再尽力通知账号中心吊销刷新令牌。
- 目前登录只是身份：应用没有调用壁纸服务端的 `/api/v1/user/me` 或收藏接口，收藏仍只存本机。要做云端收藏需要另行设计迁移和冲突处理。

## 更新与公告

每次冷启动（进程重新创建）各请求一次，失败时不打扰用户。

- 检查更新：`GET /api/v1/desktop/updates?currentVersion=<本机版本>&target=android-arm64`。有更高版本返回 200，没有返回 204；版本比较由服务端按 SemVer 做。有新版本时，设置页“版本”一行标题旁出现红点，右侧显示“当前 → 新版本”，点击用浏览器打开官网下载区 `https://wallpaper.xiangban.xyz/#desktop-downloads`。没有新版本时这一行不可点。安装包在官网后台“App 上架”里按平台 `android-arm64` 上传。
- 公告：`GET /api/v1/desktop/announcements?audience=android`，在官网后台“小伴桌面”页的公告里勾选“Android 客户端弹窗”。弹窗由标题、可滚动的正文、按钮组成：
  - 可跳过：有“取消”和“确定”，返回键和点空白处等同取消。同一条公告（按 `id` + `revision`）只弹一次，弹出时就记下，已读记录存在 `files/announcements-seen.json`，保留最近 200 条；改了内容后 `revision` 变化，会再弹一次。
  - 不可跳过：只有“确定”，返回键和点空白处无效，每次冷启动都会弹，直到后台下架或过期。
  - 多条时必读的排在前面，一条关掉再弹下一条。
  - “确定”总会关闭弹窗；公告配了跳转链接时同时用 `ACTION_VIEW` intent 交给浏览器打开。链接只接受 HTTPS（可带 `#` 片段），其他协议（`intent:`、`javascript:`、自定义 scheme）一律不打开；没有浏览器时提示。
  - 按钮文字不填时用“确定”“取消”。
- 响应里的 `audience` 必须是 `android`：没有升级的旧服务端会忽略这个参数、返回桌面版公告，这时客户端直接丢弃，不会误弹。所以先部署服务端，公告弹窗才会生效。

## 全屏查看与播放

- 图片：双指捏合缩放（最大 6 倍）、单指拖动（缩放后，到边缘停住）、双击放大到 2.5 倍并以点击处为中心、再双击还原、单击显示或隐藏关闭按钮、未放大时上下拖动超过屏高 15% 即关闭（背景随拖动变淡）。全屏加载站点提供的较大版本，并以原尺寸解码，放大后能看到真实细节。手势逻辑的算术部分有 JVM 单测，手势接线部分用 Compose 触摸测试在模拟器上验证（捏合、拖动、双击、下拉关闭、点击）。
- 视频：Media3 播放，边下边播，已下载的部分存在磁盘缓存里（上限 512 MB，设置里可清除），循环时不再走网络；进度条、缓冲提示、失败重试、切到后台自动暂停。播放器自带全屏按钮可切横屏。
- 本机相册里已保存的图片和视频也用同一个查看器：在"我的"页点卡片查看，长按出现"在相册中打开 / 删除"。

## 下载与相册

优先使用图片/视频提供方（Pexels、Pixabay 等）的原始链接，失败再用网站自存的备份。流程：请求交付清单 `?prefer=source`；清单里有 `source` 就直接下这个链接；失败（网络、被拦截、返回网页、类型不对、系统解不了码）则用 `resource`（网站自存副本，按清单校验大小和 SHA-256）；网站还没有副本时再请求不带参数的接口让网站现做一份。提供方链接的文件按真实类型判断，不拿它和清单里的哈希比较（那是自存副本的哈希）。旧版网站没有 `source` 字段时，行为与以前完全一致。提供方链接的文件上限 2 GB（有的 4K 视频有几百 MB，网站不为超过 256 MB 的素材做副本），下载前会检查手机剩余空间是否够用（需要文件大小的两倍，下载和相册里各一份）；网站自存副本仍是 256 MB 上限。所有路径都只允许 HTTPS，按文件头确认真实格式（PNG/JPEG/WebP/GIF/BMP/AVIF 图片，MP4/WebM 视频）、确认系统能解码，然后通过 MediaStore 写入相册 `Pictures/小伴壁纸` 或 `Movies/小伴壁纸`。Android 10 及以上不需要存储权限。同样内容（按哈希）不会重复保存。

## 代码

- `data/`：`SiteClient`/`SiteParser` 访问网站并严格解析；`Verified` 边下载边计算哈希并限制大小；`MediaSniffer` 按文件头识别格式；`Gallery` 写入相册和命名；`LocalStores` 保存收藏与下载记录（原子写入）；`Downloader` 串起整个下载流程；`RetryWhenBusy` 在图片主机返回 429 时退避重试。
- `data/Updates.kt`：更新与公告的解析、弹出顺序、已读记录；`ui/AnnouncementDialog.kt` 是公告弹窗，`ui/Links.kt` 打开链接。
- `data/Account.kt`：账号中心客户端、响应解析（纯函数，有单测）和登录状态存储；`ui/LoginDialog.kt` 是登录弹窗。
- `ui/`：Jetpack Compose。`App` 根布局和 Tab，`FeedScreen` 图片/视频流，`Cards` 卡片和瀑布流，`DetailScreen` 详情与保存，`LocalScreens` 收藏页和我的页，`FeedViewModel`/`AppViewModel` 管状态，`PetFace` 把小伴画进 Compose。
- `companion/` 与 `render/`：小伴角色引擎，从桌面版 `src/companion` 移植的纯 Kotlin 实现，现在只用来画头像和空状态。
- 图片加载用 Coil 3，磁盘缓存 256 MB；每个图片主机最多同时 2 个请求。

## 验证

JVM 单测 135 个（含账号 14 个：响应解析、邮箱校验、刷新时机、登录状态存取；更新与公告 19 个：响应解析、链接白名单、必读与只弹一次的选择、已读记录），另有 7 个模拟器上的 Compose 触摸测试：角色引擎 10；网站协议解析（含站内相对路径补全、拒绝不安全地址）、下载哈希与大小限制、取消清理、文件头识别、收藏与下载记录存储（含旧版收藏文件兼容）、相册命名、数字与封面比例格式、下载进度文案、429 退避。

在 API 36 ARM64 模拟器上走通：冷启动加载瀑布流、分类、详情、收藏、保存到相册（MediaStore 查询到条目，文件在 `Pictures/小伴壁纸/`）、我的页缩略图、设置页、视频保存失败时的提示。发布构建（R8 压缩）可以编译，约 2.7 MB。

视频保存（105 MB，哈希与网站清单一致）、下载中进度与取消（取消后无残留临时文件）、从"我的"页删除（相册、系统索引、应用记录同步清除）在模拟器上验证。真机（Redmi K40）上验证了安装、四个 Tab、图片瀑布流和分类、图片保存到相册。

没有验证：公告弹窗和设置页红点没有在真机上看过（只通过编译和单测，也没有在服务端部署后对着线上走过完整流程）；登录弹窗在真机上看过；真机上保存视频；搜索输入；功耗；真实网站上的 `?prefer=source`（服务端改动尚未部署，客户端只对着单元测试里的模拟网站验证了这条协议）。

## 已知问题

- 视频是 4K、码率 17~25 Mbps（14~174 MB），而实测手机到网站的速度只有约 1~1.5 Mbps，在线播放会一直缓冲。播放功能本身在模拟器上正常。要改善需要网站提供 720p 左右的预览版本。

- 目前网站的素材全部是横图（抽样 144 条，宽高比 1.25 到 1.9，没有竖图），所以同一列里高度差别有限，错落感不如竖图多的图库。有竖图后瀑布流会更明显。

- 网站的封面和图片直接指向 Pixabay 等第三方地址，国内网络慢，且 Pixabay 会对集中请求返回 429。客户端已做限流和退避，但根治需要网站自己缓存封面。
- 详情页显示的分辨率是素材原始尺寸，实际保存的是网站交付的副本，两者可能不同。
- 网站曾经把素材放在 Pixabay 等第三方地址，现在已改为自己托管（返回 `/uploads/...` 相对路径，应用按网站地址补全）。网站还偶尔对个别素材交付失败，应用会如实显示网站返回的原因。
- 收藏保存的是卡片快照；收藏后网站下架的壁纸，仍会显示快照，点开可能加载失败。
- 没有桌面版的 Canvas 脚本壁纸、订阅清单和自启动。更新只提示、不在应用内下载安装。

## 大仓开发边界

不导入 `client/xiaoban-desktop-wallpaper` 或其他客户端的源码；网站协议类型由本工程自行维护，字段以 `services/server-xiangban-wallpaper/docs/desktop-api.md` 为准。修改角色行为时同步比较桌面版并运行本工程单测。暂无 CI 工作流。
