# 小伴语音引擎方案

更新日期：2026-10-23。语音对话的底层能力收进独立模块 `src/voice/`，上层（超级小伴悬浮窗、聊天页朗读）只依赖它暴露的接口，不关心底下用哪条路线。

## 两条路线

| | 级联（标准） | 全双工 + 委托（实时） |
| --- | --- | --- |
| 链路 | 本地识别 → 小伴聊天智能体 → 按句流式合成 | 云端全双工语音模型做前台；要办的事委托给小伴聊天智能体 |
| 目标延迟（说完到听到第一句） | 0.8–1.2 秒 | 0.2–0.5 秒 |
| 离线 / 隐私 | 识别全本地；合成可用系统朗读 | 必须联网，语音上云 |
| 成本 | 低 | 按分钟计费 |
| 定位 | 默认，离线兜底 | 可选的「实时对话」模式 |

调研结论见会话记录：级联仍是生产主流；全双工 + 后台智能体委托（GPT-Live-1、Gemini Live、Seeduplex、Qwen-Omni Realtime、阿里开源的 qwen-audio-agent）已成为通行做法。

## 模块结构

```
src/voice/
  sentences.ts      流式文本按句切分（跳过代码块、去 Markdown），供流式合成使用
  stream-player.ts  按句流式合成与播放：预取下一句、顺序播放、可随时停止
  session.ts        VoiceSession 统一接口与事件（第二期）
  engines/
    cascade.ts      级联引擎：VAD/判停 → 识别 → 聊天 → 流式合成（第二期从 assistant-store 抽出）
    realtime/       全双工引擎与各供应商适配（第三期）
      qwen-omni.ts
    delegate.ts     委托桥：把前台模型的委托转成小伴聊天任务，回传进度与结果（第三期）
```

宿主侧（Rust）：
- `tts_synthesize_part`：合成一句，不打断同一轮里正在合成的其他句子；`tts_cancel` 一次停掉整轮。
- 全局快捷键区分短按与长按，长按发出 `assistant-ptt`（start / end）。

## 云端能力放在小伴 AI 网关（services/server-ai）

所有需要云端供应商的语音能力都经 `server-ai` 提供，客户端不直连供应商、不保存供应商密钥：

- **沿用网关已有机制**：账号中心验签、按「账号 × 产品」记额度、上游密钥只在服务端加密保存、客户端只认档位不认具体模型与供应商。
- **语音合成**：`POST /v1/audio/speech`（按句调用，返回音频流）。档位决定音色与供应商，后台可随时切换（火山、MiniMax、阿里等），逐步替代客户端直连 Edge 的非公开接口；Edge 可作为网关里的一个低价档位继续存在。
- **实时对话**：`GET /v1/realtime`（WebSocket）。网关对客户端只说一种协议（采用 OpenAI Realtime 事件格式，业界最通用），在服务端适配 Qwen-Omni、Seeduplex、GPT-Live 等供应商；按分钟计费、限制单次会话时长。客户端因此只需要一个 `RealtimeEngine`，不再为每家写适配。
- **委托仍在客户端执行**：小伴的聊天智能体在用户电脑上运行（读写本地文件、调用本地工具、走审批），所以前台模型发起的委托以「工具调用」事件经网关转给客户端，客户端执行后把结果经网关回传。
- **延迟**：中转多一跳，网关与供应商同地域部署时约增加 20–50 ms，可以接受。

本地能力留在客户端：麦克风采集与回声消除、VAD / 判停、SenseVoice 本地识别、系统朗读兜底、按句切分与播放、按住说话。用户也可在设置里改用自配供应商，作为不登录或网关不可用时的选项。

## 分期

### 第一期：级联提速 + 按住说话（本次）

1. **按句流式朗读**：大模型一边生成，一边按句号、问号、叹号、换行切句并合成，第一句出来就开始播放，后面的边播边合成（预取 1 句）。原先要等整段回答写完再整段合成。
2. **按住说话**：长按唤起快捷键（≥ 350 ms）开始录音，松开立刻识别并发送；短按仍是唤起 / 收起。录音期间不自动判停发送。
3. **缩短判停**：句尾静音从 0.9 秒降到 0.6 秒；识别后等待合并的宽限从 0.6 秒降到 0.3 秒。
4. **打断即停**：朗读或生成中被说话打断，同时停止朗读和当前生成，避免下一句被挡住。
5. 默认唤起方式改为「等待输入」（不自动开麦），语音靠按住说话或点生命球。

### 第二期：判停与兜底

1. VAD 换成 Silero（约 2 MB），再加 Smart Turn v3（约 8 MB，CPU 约 12 ms，支持中文）做语义判停；两级判停：VAD 预判即开始生成，Smart Turn 确认再播放。
2. 伪流式实时字幕：说话中每约 1 秒对已录音频做一次识别，灰字显示，句末定稿。
3. 合成供应商抽象：小伴 AI 网关 / 用户自配（火山、MiniMax、阿里）/ 系统朗读兜底（macOS `say`、Windows SAPI），逐步替换 Edge 非公开接口。
4. 把级联编排从 `assistant-store.ts` 抽到 `engines/cascade.ts`，对外统一为 `VoiceSession`。

### 第三期：全双工实时模式

1. `server-ai` 新增 `/v1/realtime` WebSocket 中转与按分钟计费，服务端适配 Qwen-Omni Realtime（先接），再接 Seeduplex、GPT-Live-1、Gemini Live；客户端 `RealtimeEngine` 只对接网关这一种协议。
2. 委托桥：前台模型调用 `delegate_task(描述)` → 在小伴聊天智能体里新建或继续任务（沿用工具、审批、会话）→ 进度与结果作为工具结果回传，前台模型播报；用户可随时问进度、取消。
3. 审批与危险操作仍走现有审批卡，不由语音模型代为确认。
4. 设置：「标准（本地优先）/ 实时（云端）」切换、单次会话时长上限；实时模式需要登录并消耗小伴 AI 额度。

## 验收指标

- 级联：从松开按键（或判停）到听到第一句，在常规网络下 ≤ 1.5 秒（第一期）、≤ 1.2 秒（第二期）。
- 打断：朗读中开口说话 0.5 秒内停止朗读。
- 实时：首句 ≤ 0.6 秒；委托任务进行中可以继续对话、询问进度、取消。

延迟与打断需要在 macOS / Windows 实机测量，云端供应商的延迟需在同一网络下对比实测。
