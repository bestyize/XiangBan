# 对话框：听写与语音对话

更新日期：2026-10-23。状态：**设计稿，待确认，尚未实现。** 交互稿见 [chat-voice.html](prototypes/chat-voice.html)（自包含，浏览器直接打开；稿中的对话为模拟内容）。

范围：控制台里的聊天页和新任务页（同一个 `ChatComposer`）。超级小伴悬浮窗的连续对话入口之后按同一套语义跟进，本稿不改它。

## 为什么要拆

现在输入框只有一个麦克风，点一下开始录音、再点一下「结束并发送」（`src/ui/components/ChatComposer.vue`）：

- 它是**一次一句**的录音，回答不会朗读，也没有「连续对话」。
- 说完会直接发送，没有机会先看一眼识别结果。
- 想连续聊只能每句都点一次。

Claude 和 ChatGPT 都把这两件事分成并排的两个入口：**听写**（说的话变成文字，留在输入框里自己确认再发）和**语音对话**（单独的声波图标，进入连续、免提、可打断的模式，点「停止」才退出）。小伴采用同样的拆法。

## 两个入口

输入框底部右侧，从左到右：`模型 · 听写 · 语音对话 | 发送`。

| | 听写 | 语音对话 |
| --- | --- | --- |
| 图标 | 麦克风 | 声波 |
| 悬停提示 | 听写 · 说完留在输入框 | 语音对话 · 连续、可打断 |
| 性质 | 输入手段 | 一种模式 |
| 点一下 | 开始录音，识别结果实时追加到输入框 | 进入语音对话 |
| 再点一下 | 结束录音，文字**留在输入框**，由用户改完发送 | （入口被语音条取代，用「结束」退出） |
| 回答 | 不朗读（沿用「朗读回答」设置） | 一律朗读，边生成边按句读 |
| 麦克风何时关 | 结束录音、发送、切换对话 | 点「结束」、Esc、离开页面、切换对话 |

语音对话入口右上角有一个小圆点，第一次点开后消失，用来告诉老用户这里多了东西。

## 语音对话

进入后，输入框里的文本框和工具行换成**语音条**，其余（对话列表、标题栏）不变：

```
[生命球]  状态文字                    [静音] [结束]
          实时字幕（灰字）
```

标题栏右侧出现「语音对话中」标记。用户说的话以一条带「语音」标记的用户消息进入对话，回答照常流式显示并按句朗读。

### 状态

| 状态 | 生命球 | 状态文字 | 说明 |
| --- | --- | --- | --- |
| 准备中 | 转圈 | 正在启动麦克风… | 首次使用要下载识别模型，沿用现有的进度提示 |
| 正在听 | 呼吸环，随音量起伏 | 正在听 | 灰字实时字幕；没有 15 秒超时 |
| 思考中 | 旋转弧 | 思考中 / 当前工具（如「正在查看文件」） | 回答 0.7 秒内没开始，播一声「好的」，对话里留一行淡色小字说明 |
| 朗读中 | 绿色，均衡器 | 正在朗读 · 直接说话可打断 | 麦克风保持开着，开口（不是「嗯」）就停止朗读和生成 |
| 需要确认 | 橙色 | 需要你确认 | 现有审批卡 / 提问卡，只能点击；麦克风暂停，处理完自动继续 |
| 已静音 | 灰色 | 麦克风已静音 | 只关麦克风，不退出；正在读的话读完 |
| 出错 | 红色 | 麦克风不可用 | 给出原因和「重试」；「结束」回到普通输入框 |

### 规则

1. **不自动退出。** 回答读完自动接着听；只有「结束」、Esc、离开聊天页、切换或新建对话才退出。
2. **审批不由语音代答。** 危险操作、文件写入等仍走现有审批卡，语音模型不代为确认（与 `voice-engine.md` 第三期一致）。
3. **打断沿用已有能力。** 朗读时的回声过滤、打断即停、打断后模型知道用户听到哪里，直接复用超级小伴那一套（见 `voice-engine.md`「级联体感优化」）。
4. **语音对话里没有文本框。** 想打字就点「结束」回到普通输入框；是否加「键盘」按钮见待确认。
5. **读不了就退回文字。** 语音来源失败时同一句改用系统朗读；仍失败则只显示文字，并在语音条上提示一次。
6. **进入条件。** 需要已配置模型、语音识别已启用且麦克风可用；不满足时点击走现有的启用与下载引导，不进入模式。回答进行中两个入口都置灰。

## 实现思路（供审阅，未动代码）

- **共用一套语音会话逻辑。** 超级小伴的连续听、判停后发送、朗读、打断、附和音、打断说明都在 `src/assistant/assistant-store.ts` 里，和悬浮窗状态混在一起。聊天页要用，就按 `voice-engine.md` 早就计划的，抽成 `src/voice/conversation.ts`（输入 `chat` / `asr` / `speech`，输出状态与操作），悬浮窗和聊天页各接一份，避免两处各写一遍。
- **听写**在现有 `toggleVoice` 上改：结束时不再调用 `submit()`，只 `asr.finish()` 并保留文本。
- **语音对话**新增一个组件（语音条），`ChatComposer.vue` 按模式切换文本框与语音条；对话列表不用改，用户的语音消息和普通消息同一种数据，只多一个「来自语音」的标记。
- **每页一个实例。** 聊天页和新任务页各有一份 `ChatComposer`，沿用现在「只有当前显示的页面才开麦」的约束，避免两处同时听。

## 待确认

2. **语音对话一律朗读**，不看「朗读回答」设置；设置只管文字聊天里的手动朗读。
3. 语音条上要不要加「键盘」按钮，临时展开文本框、打字发送后仍留在语音对话里？（本稿：不加，要打字就先结束，保持简单）
4. 范围：先做聊天页和新任务页，超级小伴之后同步；还是两边一起？
