# 小伴桌面界面约定

新增或修改控制台（`src/ui`）里的菜单、弹窗和卡片时遵守本约定。目标是紧凑、一眼能读、同类控件长得一样。已有界面按需逐步对齐，不要求一次改完。

## 菜单

- **一项一行**：高度 32–34px，只放图标（14px 线性）、名称，右侧可放勾选、快捷键或一两个字的提示。不要把说明写成名称下面的第二行小字。
- **说明放悬停提示**：用 `title` 并同时写 `aria-description`，键盘聚焦也能读到。必须让人先看到的警示（例如会丢数据）才留在界面上，并且只留一句、放在对应选项上。
- **同一信息不重复**：当前选中项用勾选表示，不要在菜单顶部再写一遍当前值；路径、全名这类长内容放提示里。
- **宽度**：一般 176–240px，选项只有两三个时取小值；面板不要超过 300px。
- **复用共享类**：优先使用 `control.css` 里的 `xb-menu`、`xb-menu-item`（含 `is-active`、`is-danger`、`xb-menu-hint`、`xb-menu-check`）、`xb-menu-sep`、`xb-menu-label`。需要更小的尺寸时在组件里覆盖尺寸，不要另起一套菜单项样式。
- **危险项**：用主题的危险色（`--ui-danger`），不新增别的强调色；红色只用于真正高风险的选项。

## 独立窗口（大型设置与配置界面的强制规范）

- 桌面版的大型设置、模型/服务商配置及后续新增的复杂编辑、审查、预览界面，默认使用真正的 Tauri 系统窗口，不得以 `NModal`、遮罩或全局焦点锁代替独立窗口。浏览器预览可保留内嵌降级实现。
- 窗口保留系统标题栏和关闭入口，允许拖动、缩放、最大化；不设置会阻止主窗口操作的原生模态关系或页面遮罩。重命名、删除确认等短小确认框可内嵌。
- 首次打开按来源窗口所在显示器的工作区限制大小并居中；恢复旧位置、重复打开、显示器拔出及缩放变化时，必须将包含标题栏的整个外框约束回可用工作区。最小尺寸不得大于可用区域。
- 同一设置窗口、同一服务商配置窗口重复打开时，聚焦已有窗口并保留未保存输入；不同服务商可分别编辑。尺寸与位置持久化时不保存密钥、草稿凭据或窗口间请求内容。
- 标题与关闭操作固定可见，正文滚动，窄窗口内容应重排；不可依赖屏幕外的关闭按钮解除焦点锁。取消、Esc（无子菜单时）及系统关闭均可离开编辑；保存失败保留当前输入，成功后同步到其他窗口。
- 所有窗口跟随应用外观、系统日夜间模式和主题色。跨窗口模型、账户及声音设置更新必须同步，不能各自保留过期状态。
- 独立窗口只获得完成其配置任务所需的命令范围；不得将预览、网页、壁纸等不可信内容升级为控制台权限。当前设置/模型窗口通过原生认证请求队列复用控制台已有的校验；新增命令须同步维护白名单与测试。
- 参考实现：`src-tauri/src/configuration_window.rs`、`src/ui/configuration/`。本次设置和模型配置必须走该入口；不要重新引入桌面版嵌套大弹窗。

## 弹窗与卡片

- 标题加操作即可，不写解释性描述；输入框的占位文字和快捷标签已经够说明用途。
- 主次分明：一个主按钮，其余用次按钮或文字按钮；「跳过」「取消」这类放在角落。
- 一张卡只承载一件事，不把「选择、输入、两个按钮、切换项」平铺在一起；选项用整行列表，自己回答并进列表末尾。
- 可以用键盘完成的选择（数字键、方向键、回车、Esc）要支持，焦点样式和悬停样式一致。

## 颜色与主题

- 颜色一律走 `--ui-*` 主题变量（`--ui-btn`、`--ui-soft`、`--ui-ink`、`--ui-danger` 等），不写死色值；六套主题色下都要能看。
- 设计稿里的主题色用令牌 `t.btn` / `t.soft` / `t.ink`，与代码里的变量一一对应。
