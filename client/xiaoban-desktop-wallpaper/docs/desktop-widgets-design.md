# 小伴桌面｜桌面小组件设计规范

> **Soft Living UI · 柔和生活感设计系统**  
> 版本：V1.0 · 更新：2026-10-19  
> 适用：Windows / macOS 桌面上实际悬浮的小组件、组件库预览与组件配置弹窗。  
> 不适用：整个应用控制台的通用页面样式（参见 [ui-design.md](ui-design.md)）。

## 1. 设计定位

**桌面小组件是“放在桌面上的精致物件”，不是压缩后的应用页面。**

- **功能先于装饰**：一个组件只突出一项核心内容；次要数据按视觉权重递减。
- **家族一致、个体鲜明**：圆角、节奏、排版、可访问性与状态反馈统一；时钟、天气、待办、提醒、股票与木鱼允许使用不同的视觉表达。
- **内容决定材质**：按信息密度和桌面壁纸选择透明、柔和半透明或实体底板；不强迫每个组件都有背景。
- **安静但有生命力**：时间、天气和木鱼可以有克制的动态反馈；默认不持续闪烁、漂浮或无意义地滚动。
- **尊重桌面环境**：高对比度、可缩放、跨显示器与省电时保持可用；不能修改用户壁纸的色彩。
- **直接完成轻任务**：勾选、切换、敲击直接发生在组件内；复杂编辑由弹窗或“桌面组件”配置页承接。

整体气质：温润、明亮、透气、亲切、精确。避免模板化渐变、厚重玻璃拟态、统一强制背景、大面积高饱和装饰。

## 2. 适用边界与当前实现

本文件是**新设计目标**，不是现状实现清单。修改代码时不可将目标描述成已经上线的能力。

- 现有组件容器在 **src/widgets/WidgetSurface.vue**、**window.css**；类型和基础尺寸在 **src/widgets/model.ts**；组件管理入口在 **src/ui/pages/WidgetsPage.vue**。
- 当前组件类型：求签（fortune）、时钟日历（calendar）、天气（weather）、便签待办（notes）、倒数日（countdown）、小白花（flower）及自定义 HTML（custom）。本文重点定义的“提醒、股票、电子木鱼”是拟新增的规范对象；纯时钟可由日历组件派生或成为新变体，不能据此推断已有单独类型。
- 现有持久化材质枚举是 **glass / paper / transparent**；UI 可展示“柔和 / 实体 / 无背景”，但在正式迁移数据结构前应兼容旧枚举和历史配置。
- 当前布局与尺寸由现有数据模型控制（包括组件缩放与显示器位置）。下述 S/M/L 是**未来可扩展的视觉目标尺寸**，不是当前系统已经具备的自动响应式规格。
- 股票数据的来源、更新与授权应遵循 [information-widgets-research.md](information-widgets-research.md)；提醒组件不等同于既有“关怀提醒气泡”，两者在交互与生命周期上应作区分。
- 本次文档更新**不改运行时代码、组件类型、设置结构或构建流程**。

## 3. 设计令牌（Design Tokens）

以 CSS 逻辑像素为单位。数值是推荐值，允许因组件尺寸和桌面缩放调整；不要机械套用到应用控制台。

### 3.1 间距、圆角、阴影

| Token | 推荐值 | 说明 |
| --- | --- | --- |
| spacing-1 / 2 / 3 / 4 / 6 / 8 | 4 / 8 / 12 / 16 / 24 / 32px | 8px 主栅格，4px 局部微调 |
| inset-s / m / l | 16 / 20 / 28px | 小、中、大组件内边距 |
| radius-widget | 24–32px | 独立桌面卡片，不等同于控制台卡片 |
| radius-inner | 12–16px | 内部选项、辅助区块 |
| radius-chip | 8–12px | 小标签、胶囊按钮 |
| shadow-rest | 0 10px 32px rgba(30,35,45,.07) | 实体底板的默认柔和阴影 |
| shadow-hover | 0 14px 36px rgba(30,35,45,.10) | 仅鼠标悬停的轻微增强 |

- 小组件与桌面应用控制台**有独立设计作用域**：不要把小组件 24–32px 的大圆角强制应用于控制台页面、对话框、侧栏。
- 浅色背景尽量通过底色差异组织层次，少用描边。深色背景优先使用表面亮度分层，避免发光描边。

### 3.2 色彩

| Token | HEX | 场景 |
| --- | --- | --- |
| text-primary | #20242B | 主信息 |
| text-secondary | #858A94 | 次级标签 |
| surface-primary | #FFFFFF | 实体卡片 |
| surface-warm | #F8F6F3 | 暖白替代 |
| surface-mist | #E8EBEF | 中性次级区 |
| accent-sky | #87BCE8 | 天气或空气感 |
| accent-mint | #58C59A | 完成状态、轻反馈 |
| accent-apricot | #EFC6A7 | 木鱼、温暖生活类 |
| surface-dark | #1C2227 | 深色卡片 |
| text-inverse | #F5F6F7 | 深色背景主文字 |

**使用规则**：

- 中性色占主要面积，彩色只为内容语义服务；六个组件不必同色，更不能靠“每张卡随机换一种颜色”制造差异。
- 语义色优先服从所在领域习惯。**A 股默认红涨绿跌**；其他市场可按地区、用户偏好切换。除颜色外必须同时显示正负号和数值。
- 装饰插画可使用局部柔和色阶，但不可妨碍阅读；不依靠渐变作为卡片可识别性的唯一手段。
- 透明模式的文字颜色由背景亮度或用户选项控制；深色/浅色主题都必须保有可靠对比度。

### 3.3 字体与层级

| 元素 | 推荐 | 字重/要求 |
| --- | --- | --- |
| 超大数字（时间、温度、计数） | 48–88px | 500–600，等宽数字优先 |
| 小尺寸主数字 | 36–48px | 缩放下保留完整字符 |
| 组件标题 | 18–22px | 600 |
| 正文 / 列表条目 | 14–16px | 400–500 |
| 辅助信息 | 12–13px | 400 |
| 极简角标 | 最低 11–12px | 非关键信息；不作为唯一操作说明 |

优先使用系统 UI 字体（Windows：Microsoft YaHei UI；macOS：PingFang SC；其他平台可用 Noto Sans CJK）；数值启用 **tabular-nums**，避免时钟跳位和行情数值抖动。正文建议 1.4–1.55 行高；长文本截断时保留完整内容的可访问入口。

## 4. 尺寸、密度与组件形态

参考逻辑尺寸（CSS px，不是设备物理像素）：

| 规格 | 建议尺寸 | 信息密度 | 例子 |
| --- | --- | --- | --- |
| S | 180 × 180 | 一个主要读数或一个操作 | 时钟、木鱼、单股 |
| M | 280 × 200 | 主数据 + 简要辅助信息 | 天气、待办摘要、提醒下一项 |
| L | 400 × 300 | 主数据 + 列表或趋势图 | 完整待办、时间轴、多股行情 |

- 尺寸是示例锚点，允许按内容设置不同宽高比；**优先响应式重排，不是把所有字等比例缩小**。
- S 规格可隐藏次要信息，但不可缩小主内容到不可读；M 规格保留 1–3 项摘要；L 规格增加走势图、任务列表或连续事件。
- 列表信息超过可展示上限时呈现“还有 N 项”或进入详情，不应让卡片无限增高。
- 拖拽时保留组件外形，点击内部按钮不应误触拖动；编辑模式应清晰标记可拖拽区域。
- 多显示器、系统缩放及窗口边界变化时，保持内容不裁切，不能丢失操作入口；新尺寸规则不得破坏既有布局数据。

## 5. 材质与桌面融合

| UI 材质名称 | 视觉行为 | 当前枚举兼容 | 适用 |
| --- | --- | --- | --- |
| Transparent 无背景 | 无外框、无卡片阴影；必要时给予轻微文字阴影或对比遮罩 | transparent | 纯时钟、极简倒计时 |
| Soft 柔和 | 有轻量透光感，适度模糊；文字对比仍然明确 | glass | 天气、轻量待办 |
| Solid 实体 | 暖白 / 雾灰 / 深墨纯色为主，稳定分层 | paper（未来可独立主题） | 股票、长列表、提醒 |

**不要在未迁移数据前直接将旧枚举改名**。材质由组件的视觉需要推荐，但必须保留用户手动覆盖能力。

自动推荐策略（未来实现时）：

1. 判断组件**信息密度**和背景风险：有长文本、图表、复杂控件的组件默认 Solid；只有少量大数字的组件可默认 Transparent。
2. 根据桌面图像亮度/复杂度选取文字对比策略；无法安全感知桌面时使用稳定、可读的 Solid 作为保底，不要求读取用户隐私内容。
3. 用户指定的材质优先级高于自动建议；换壁纸不能悄悄清除用户选择。
4. 不允许通过改变壁纸颜色“适配”小组件。

## 6. 六种重点组件规范

### 6.1 桌面时钟 Clock

**焦点：时间。** 主视觉用大数字，日期与星期降至第二层。推荐暖白实体、无背景或具有留白的山峦日光装饰；装饰必须可关闭。

- S：只显示 HH:mm；可选日期一行。M：显示完整日期与简短文案。L：可扩展秒数、双时区或日程摘要，默认不开启。
- 支持 12/24 小时制、秒数开关、字体粗细及日期格式。
- 每分钟刷新；显示秒数时才按秒更新。时区按用户配置，不凭 UI 示例默认为某城市。
- 大数字间距固定，避免时间改变时整体偏移；不使用每秒翻转的高干扰动画。

### 6.2 天气 Weather

**焦点：当前温度与天气状态。** 允许云朵、太阳、雨雪作为主体插画，插画宜干净柔和，不遮挡文字。

- S：城市、温度、当前天气。M：增加体感、最高/最低温。L：增加 3 日概览（未来几日预报不与当前体感混淆）。
- 主温度应是第一视觉层级；插画不大于主读数的信息权重。
- 点击城市打开城市切换；点击预报区域进入详情；失败时提供刷新。
- 明确城市、数据更新时间、来源及加载/过期/失败状态；无数据显示“—”，不得用演示数字伪装实时天气。
- 动态云层和雨雪只在可见、允许动画时播放，优先低功耗。

### 6.3 待办 Todo

**焦点：今天还需要完成什么。** 采用轻量清单，不做复杂项目管理面板。

- S：任务数量与下一件事。M：3 条以内待办及完成进度。L：4–6 条清单，更多内容进入详情。
- 标题、进度和“添加”入口位置稳定；勾选区域清晰，已完成条目弱化而非立即消失。
- 支持新增、勾选、编辑、删除；删除需有撤销机制或适当确认，不能误触。
- 展示有意义的空状态（如“今天的事都完成了”），不占用整张卡的空间。
- 键盘焦点、鼠标与触控板都应可操作；文本过长两行截断并支持查看全文。

### 6.4 提醒 Reminder

**焦点：时间顺序与下一件重要事项。** 在视觉上以竖向时间轴、时间与内容的分离表达节奏。

- S：下一项提醒时间及标题。M：最近 2 项。L：当日 3–5 项时间轴，节点颜色克制。
- 明确区分“事件发生时间”“提醒触发时间”“已完成”；跨日事件显示日期，不能仅写“09:30”造成歧义。
- 点击条目可编辑；新增使用小型弹窗或跳入配置页。完成、稍后提醒、删除提供明确反馈。
- 与现有**关怀提醒气泡**的调度/展示机制区分：本组件是桌面摘要与编辑入口，不应未经设计就复制后台调度能力。
- 过期、已完成、全天事件等状态需分别表达；不可因动画频繁移动时间轴。

### 6.5 股票 Stocks

**焦点：标的、价格、涨跌和可靠的数据时间。** 视觉可以采用深墨实体卡片与克制的线图，避免彩色交易终端式堆砌。

- S：单一标的、最新价、涨跌幅。M：主标的 + 简短走势。L：主走势图 + 3–6 个自选股或主要指数摘要。
- 默认中国用户优先提供 A 股三大指数与自选股的视图；证券代码必须包含市场/交易所信息。
- 可切换标的、1D / 1W / 1M / 3M / 1Y 等**实际具备数据的周期**；没有周期数据就禁用选项，绝不编造曲线。
- 显示交易状态（盘中、休市、停牌）、报价时间、行情延迟与数据源；失败保留最后成功值并标明过期。
- A 股默认红涨绿跌，其他市场支持用户可配置；涨跌方向同时用符号、文本与数值表达。
- 组件不会自动滚动多个行情或弹交易建议；刷新应尊重数据供应商频率与许可。详情与数据接入要求见 [information-widgets-research.md](information-widgets-research.md)。

### 6.6 电子木鱼 Wooden Fish

**焦点：木鱼物件本身与敲击反馈。** 推荐暖杏色、温润木质、柔和光照，尽量让它像桌面上的小玩具，而非一排按钮。

- S：木鱼 + 次数。M：增加今日计数和简短文案。L：可增加音效控制、连续敲击统计和主题外观。
- 点击主体完成一次敲击：约 100–180ms 的位移/回弹，短促音效与清晰的计数变化；禁止持续炫光。
- 连续点击不得漏计、乱序或产生重叠爆音；支持静音、音量和关闭动画。
- 尊重系统“减少动态效果”设置；计数和操作必须在关闭声音后仍可用。
- 支持通过鼠标点击和键盘 Enter/Space 敲击；重置功德计数属于破坏性操作，应有确认或撤销。
- 木鱼插画可以由 2D/SVG、高质量图片或轻量 3D 实现，优先画面质量、加载体积和持续性能，而非技术堆砌。

## 7. 通用交互状态与动效

| 状态 | 要求 |
| --- | --- |
| Default | 第一眼能识别组件职责、主要数据和可点击项 |
| Hover | 阴影或操作入口轻微增强，不整体漂浮或移动内容 |
| Pressed | 可选 0.97–0.99 倍的按压反馈；不与拖动手势冲突 |
| Focus | 可见键盘焦点，不只依赖 Hover |
| Loading | 只对正在加载区域显示占位，不改变卡片尺寸 |
| Empty | 明确下一步操作，如“添加待办”“选择城市” |
| Error / Stale | 原位提示原因和恢复入口，绝不把旧数据当实时 |
| Editing | 显示拖拽与设置状态，避免误操作实际功能 |
| Disabled | 说明为什么不可用，不以低透明度作为唯一信息 |

- 常规 Hover / Press：**180–240ms**；状态切换：**180–320ms**；特殊木鱼或天气动画按内容独立设定。
- 动画应服务于“数值变化 / 任务完成 / 敲击反馈”，不为装饰而循环。
- 页面不可见、桌面动画暂停、省电模式或用户选择减少动态效果时，暂停非必要动画和高频刷新。
- 状态变化不应让组件大小、标题位置、按钮区域明显跳动。
- 执行失败时保持原有数据，使用可撤销或重试的反馈机制；不弹出遮挡桌面的长驻警告条。

## 8. 可访问性与跨平台要求

- 文字、图标与背景应满足可读性；普通文字以 **4.5:1**、大型文字以 **3:1** 对比度作为目标。透明材质无法确保对比时使用描边/遮罩或切换实体材质。
- 可操作区域桌面端推荐至少 32×32px；密集内容应保留清晰焦点和足够间距。悬停显现的设置按钮必须能通过键盘获得。
- 支持 Windows/macOS 系统字体、Retina/HiDPI、缩放和多显示器。大小随组件自身逻辑尺寸自适应，不能靠统一缩放压缩全部字体。
- 不用颜色作为唯一状态标识；金额、单位、日期、负号、时区、交易所等语义信息必须完整。
- 数据最小化：没有用户配置城市时不假定定位；敏感令牌不放入小组件 HTML、前端存储或公开资源包。
- 任何悬浮层不得无故拦截非组件区域的桌面点击；与现有置顶/融入桌面策略和交互穿透规则兼容。

## 9. 组件库 / 设置页面规范

- 组件库按“组件是什么”而非“用了什么颜色”分类，卡片预览应接近实际显示效果。
- 每款组件提供：**名称、主要能力、尺寸选择、材质预览、添加到桌面、配置入口**；已经添加的组件提供定位和编辑入口。
- 点击桌面组件应进入**该组件配置页**，而不是直接打开整个应用设置。
- 推荐在弹窗内编辑：尺寸、主题、数据源或城市、刷新策略、交互和动效选项；只有复杂配置才跳转全页。
- 预览可展示样例数据，但必须注明“示例”；真实桌面不允许把样例行情、温度或事件冒充真实数据。
- 自动推荐的材质可被覆盖；选中态和保存反馈明确。主题切换应同时检查插画、文字、图表、占位与错误态。

## 10. 验收检查表（视觉与体验）

- [ ] 小组件在浅色、深色、复杂/浅色/深色壁纸上均可读。
- [ ] 每款组件 2 秒内能识别主功能；大数据不被插画压制。
- [ ] S/M/L 内容按优先级增减，不出现文本挤压或控件截断。
- [ ] 透明 / 柔和 / 实体材质的视觉差异明确，用户选择能保留。
- [ ] 六类组件各有独特气质，圆角、排版、状态反馈仍属同一家族。
- [ ] 拖拽、点击和编辑操作互不冲突，多显示器和 DPI 缩放可用。
- [ ] 所有组件有加载、空、失败和不可用状态；无虚构实时数据。
- [ ] 股票符号、交易时间、红绿方向正确；提醒跨日时间无歧义。
- [ ] 键盘焦点和减少动态效果设置可用；不可见组件停止非必要工作。
- [ ] 不修改壁纸、不强制所有组件有底板、不把小组件令牌影响到控制台。
