# 小伴应用内窗口工具

## 调研结论

- 原有 `widget_update` 已能按 0–1 比例移动组件，但 `widget_list` 没展示位置与显示器信息。
- `companion_set` 只能改显示开关、表情、外壳，不能移动盆栽。
- 超级小伴宿主已有 `collapse`，但模型没有可调用入口，容易把“收起自己”误解为隐藏盆栽。
- 原生层原先固定了窗口层级，桌面组件的定时布局同步也会覆盖临时窗口设置；现在组件的层级直接写进布局，不再被覆盖。

## 新增工具

### `desktop_windows`（只读）

返回可用显示器，以及小伴自身交互窗口的标识、位置、显示状态、层级。操作前用它确认目标；不枚举第三方应用窗口。

目标：

| target | 对象 |
| --- | --- |
| `companion` | 盆栽小伴 |
| `assistant` | 超级小伴悬浮球／悬浮条 |
| `control` | 小伴控制台 |
| `widget:<id>` | 指定桌面组件，id 来自列表 |

### `desktop_window_set`（写操作，串行执行）

- `action`: `show` 显示、`hide` 隐藏；`collapse` 仅超级小伴使用，收起悬浮条并回到球（关闭球时隐藏）。不退出应用，也不取消模型任务。
- `x`、`y`: 同时提供，范围 0–1，表示所选屏幕可放置范围中的比例。`0,0` 左上，`0.5,0.5` 居中，`1,1` 右下，自动考虑窗口大小。
- `monitor`: 可选，必须使用 `desktop_windows` 返回的显示器 id。
- `layer`: `desktop` 贴桌面、`normal` 普通窗口、`topmost` 置顶。控制台不允许嵌入桌面层。
- 隐藏／收起与位置、层级调整不能在同一次调用混用。

示例：

```json
{"target":"assistant","action":"collapse"}
```

```json
{"target":"companion","x":0.0,"y":0.0}
```

```json
{"target":"widget:实际组件id","layer":"topmost"}
```

## 生命周期与边界

- 组件位置沿用原有布局持久化；隐藏盆栽／组件保存显示开关。
- 桌面组件（`widget:<id>`）的层级写入组件布局，重启后保持；宠物实例的层级写入 `pets.json`（用 `pet_update`），同样保持。盆栽、超级小伴、控制台的层级只是本次应用运行内的覆盖值，窗口重建时重新应用，重启恢复默认。工具返回里 `saved: true` 表示已保存，`layerLastsUntilQuit: true` 表示只在本次运行有效。
- 盆栽与控制台的工具移动不新增跨重启位置存储；超级小伴复用现有位置记忆。
- 壁纸、桌面特效、游戏等全屏渲染层不开放任意移动，避免破坏铺满屏幕与桌面分层规则。
- macOS 层级／坐标修改在主线程进行；Windows 区分 Explorer 子窗口和顶层窗口，按屏幕坐标移动。当前已在 macOS 编译和单元测试；Windows 真机、多屏 DPI 切换未实机验收。
