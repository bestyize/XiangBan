# 论坛设计方案（草案）

状态：一期网页论坛已实现于 [services/server-forum](../../services/server-forum/README.md)，历史记录显示 2026-10-11 已部署；当前线上状态需核实。移动端已实现原生社区界面，具体范围以多端 App README 为准。站点名「超级小伴」，域名 `chat.xiangban.xyz`。

## 1. 定位

面向开发者和 AI 用户的综合社区：**技术交流、资源分享、福利羊毛、随便唠唠**。福利羊毛是其中一个板块，不作为主推。

- 和 Linux.do 的区别：福利散在帖子和回复里，很快沉底；这里的福利羊毛是带有效期、到期自动下架的帖子，配合关键词订阅和站内通知。
- 技术交流和资源分享负责内容质量，福利羊毛负责拉新，随便唠唠负责日活和氛围。导航里福利羊毛排在技术交流、资源分享之后。
- 收入目标：月入一两万，主要来自赞助位和推广分成，会员作为补充（见第 9 节）。

## 2. 板块与分类

两级分类（`parent_id` 关联，不做三级），再叠加自由标签（Claude、OpenAI、Gemini、DeepSeek 等）。分类管"是什么类型"，标签管"哪家产品"。

| 一级 | 二级 | 帖子类型 |
| --- | --- | --- |
| 技术交流 | AI 大模型 / AI 提效 / AI 硬件 / AI 创意 | 普通帖 |
| 资源分享 | 精品软件 / 电影资源 / 音乐资源 / 学习资料 | 普通帖 |
| 福利羊毛 | AI 羊毛 / 云服务器·GPU / 开发者福利 / 公益站 / 其他福利 | 羊毛帖 |
| 小伴产品 | 小伴壁纸 / 小伴游戏 / 小伴App | 普通帖，仅守护者可发 |
| 随便唠唠 | 职场 / 下班了 / 亏了吗 / 梦想和人生 / 数码装备 / 副业与独立开发 / 吃喝玩乐 / 闲聊灌水 | 普通帖 |
| 站务 | 公告 / 规则 / 建议反馈 / 举报处理公示 | 普通帖 |

**资源分享只收合法来源的内容**：正版、开源和免费软件，片单影评乐评歌单，公版和授权影音，公开的课程资料和自己的作品。破解版、盗版影音下载和付费课程转存不收，板块说明、发帖页提示和站规里都写明了，并保留版权投诉和 3 个工作日内下架的流程。

**内置标签**：二级分类可以带一组内置标签（`categories.preset_tags`），发帖选了这个分类后，标签栏下面会出现一行"常用标签"，点一下加上、再点取消，满 5 个后其余变灰；用户仍然可以自己输入标签。板块页顶部用同一组标签做筛选（`?tag=`）。目前只有资源分享的四个二级板块配了：精品软件（windows、macos、linux、android、ios、开源、免费、效率工具、开发工具、设计工具），电影资源（片单推荐、影评、纪录片、动画、科幻、悬疑、喜剧、经典老片、公版、授权），音乐资源（歌单推荐、乐评、古典、流行、摇滚、电子、爵士、纯音乐、独立音乐、公版），学习资料（编程、ai、英语、考研、考证、设计、数学、电子书、公开课、笔记）。管理员可以在后台分类表单里修改。

**技术交流的四个板块**：AI 创意（AI 绘画、视频、音乐、写作等创意玩法和作品，也可以分享提示词与工作流）、AI 大模型（本地跑大模型、模型评测、自建 API 中转的技术教程）、AI 提效（用 AI 重塑工作流、加速研发）、AI 硬件（小智机器人、开源蝴蝶飞行器、机器狗、桌宠机器人等）。其中"中转站搭建教程"和第 10 节"禁止运营或推广 API 中转"的关系是：只讲技术的自建教程可以发，运营、出售、推广中转服务，或贴出可用的中转地址、Key、收费入口仍然禁止；在国内面向公众提供生成式 AI 服务有备案要求，所以站方不做、不推广这类服务。

**亏了吗**：随便唠唠下的板块，聊盈亏经验和心态。为避免变成荐股群，板块说明和站规都写明不荐股、不拉群、不带单、不推广投资产品，内容不构成投资建议。

**小伴产品**：站方推广自家产品的官方板块，二级板块按产品分（现在是小伴壁纸、小伴游戏、小伴App，以后加产品就往里加板块，见 README 的"以后加板块"）。最低发帖等级设成守护者，所以只有站方（把自己的账号调成守护者）能发帖，所有人可以回复提问和反馈；和站务的公告、规则一样，用 `min_post_level` 或「仅管理员可发」(`admin_only`，实际指守护者) 限制，管理后台账号发不了帖。站规里写明这是官方板块，不属于"私人推广"，其他板块推广自己的产品仍然禁止。每个板块有内置标签（更新日志、下载、使用教程等），发帖和筛选时用。

不设单独的"羊毛讨论"板块：领取求助、经验和横评发在技术交流或随便唠唠；羊毛已经领不到时，在帖子下面回复说明。AI 羊毛是福利羊毛下的二级版块，具体是哪家产品用"关联产品"和标签区分（Claude、Cursor、DeepSeek 等）。

每个分类有这些开关：最低发帖等级、是否进首页热门、发帖是否加积分。帖子数少于阈值（暂定 20）的二级分类在导航里合并到"其他"，不单独露出。不做匿名发帖。

- 闲聊灌水：不进首页，不加分。
- 站务公告：只有管理员能发。

## 3. 用户与信任等级

登录直接接统一账号中心（邮箱/手机号验证码），论坛不存密码。开放注册，不要邀请码，靠信任等级控制新号权限。

| 等级 | 获得方式 | 能做什么 |
| --- | --- | --- |
| TL0 新人 | 注册 | 浏览、回复（每天限量）、点赞；不能发外链和图片 |
| TL1 成员 | 注册满 3 天，阅读 30 帖，无违规 | 发普通帖和羊毛帖、发外链和图片 |
| TL2 老用户 | 访问 15 天以上，被采纳羊毛 3 条或获赞 30 | 看隐藏回复、发帖免审 |
| TL3 守护者 | 管理员手动授予 | 移帖、处理举报（版主候选） |

升级条件都是可配置的数字，前期可以先放宽。违规扣分或封禁会降级。

**阅读权限**：每个帖子有一个阅读等级——所有人（含游客）、成员以上、老用户以上、守护者。发帖人只能设到不超过自己的信任等级，编辑时可以保持或调低。没有权限的人在列表、搜索、用户主页、收藏夹、搜索引擎里都看不到这个帖子，直接打开链接提示需要什么等级；作者总能读自己的帖子。受限帖子不进 sitemap，搜索引擎页面按不存在处理。

**积分**：羊毛帖被设为精选时加分；随便唠唠、站务不加分。积分前期只做展示，后期接抽奖和兑换码。所有积分变动写流水表，方便查刷分。

## 4. 羊毛帖

羊毛帖 = 普通帖（标题、Markdown 正文）+ 一组**全部选填**的字段，发帖人什么都不填也能发。

| 字段 | 说明 |
| --- | --- |
| 能领到什么 | 选填，自由文本，如"$5 额度""首月 1 元"，会在列表里高亮 |
| 领取条件 | 选填，多选：需要信用卡、需要手机号（国内/海外）、需要 edu 邮箱、需要企业邮箱、需要实名 |
| 有效期 | 选填：截止日期、"长期有效"或"不清楚" |
| 活动页链接 | 选填，官方活动页。个人推广链接（带 ref 参数）默认不允许，见第 9 节 |

不做"羊毛类型"、"地区限制"，也不做有效/失效投票和状态标记。写了截止日期的羊毛，到期后自动不再出现在福利羊毛、首页和分类列表里；用户主页、搜索、标签页和产品页的历史里仍然能看到。

**筛选和排序**：福利羊毛页只有一行二级分类标签，不做条件、类型、地区等筛选；排序有最新、热门、即将过期。接口（`/api/deals`）还保留按产品、条件筛选的参数，页面暂不使用。

不做产品库和产品页：一个羊毛帖是哪家的产品，写在标题里，或者用标签（如 Claude、Cursor）区分。

## 5. 页面清单

前台（移动端优先）：

- 首页：所有板块混排的帖子列表，管理员置顶的帖子排最前并高亮（不含灌水）
- 福利羊毛：分类标签 + 排序 + 列表（标题、能领到什么、领取条件、有效期）
- 分类列表页：普通帖按最新回复排序
- 帖子详情：正文、羊毛信息（羊毛帖，填了哪项显示哪项）、楼层回复、收藏、举报
- 发帖页：选分类，羊毛分类会出现结构化表单；Markdown 编辑和预览、图片上传
- 标签页、搜索页
- 用户主页：发帖、回复、等级、积分
- 消息中心：回复、@、订阅命中、系统通知
- 设置：资料（读账号中心）、订阅管理、屏蔽用户列表、注销入口
- 站规、用户协议、隐私政策

后台（`/admin/`，同进程托管，管理员单独建表，与账号中心后台同样做法）：

- 举报队列、待审内容、删帖/移帖/锁帖/置顶/精选
- 用户：调整等级、禁言、封禁
- 分类、标签、敏感词管理
- 赞助位管理、站点公告
- 操作日志、基础数据（日活、发帖量、羊毛有效率）

## 6. 技术方案

按仓库默认选型，新建 `services/server-forum`：

- 后端：Rust Axum + PostgreSQL（sqlx），结构参考 `server-account` 和 `server-xiangban-wallpaper`
- 前端：Vue 3 + Vite，构建产物用 rust-embed 嵌进二进制，单进程部署
- 鉴权：前端在浏览器里用账号中心验证码登录，拿到 access token 直接调论坛接口；论坛后端用 JWKS 验签（`iss`、`aud = forum-web`），和壁纸站一样。首次登录在本地 `users` 表建档
- 昵称头像：账号中心是权威数据，论坛本地缓存一份用于列表展示，每次登录刷新
- 搜索：前期用 PostgreSQL `pg_trgm` 对标题和标签做模糊搜索，量大了再上 Meilisearch
- 图片：浏览器端先压缩转 WebP，由后端签名后直传腾讯云 COS（香港地域，配 CDN），云服务器本地不存图
- 敏感词：本地词库过滤，命中进待审队列，不直接拒绝

**SEO 要单独处理**：纯 Vue 单页对百度很不友好，论坛的自然流量主要来自搜索。帖子页、分类页由后端直接输出带标题、摘要和正文的 HTML（模板渲染），Vue 在上面接管交互。同时输出 sitemap。

**热度分**（暂定，上线后再调）：

```text
hot = (点赞 × 2 + 回复数) / (发帖小时数 + 2) ^ 1.5
```

定时任务每 10 分钟重算最近 7 天的帖子，并处理羊毛到期。

## 7. 数据表

| 表 | 主要字段 |
| --- | --- |
| `users` | `uid`（账号中心 sub，主键）、昵称/头像缓存、`trust_level`、`points`、`status`（正常/禁言/封禁）、`muted_until`、访问天数、阅读数、注册时间、最后访问 |
| `categories` | `id`、`parent_id`、`slug`、`name`、`kind`（deal/normal）、排序、最低发帖等级、进首页、加积分 |
| `topics` | `id`、`category_id`、`author_uid`、标题、`body_md`、`body_html`、`status`（正常/待审/隐藏/删除）、置顶、精选、锁定、回复/点赞/浏览数、`hot_score`、`last_reply_at`、创建/编辑时间 |
| `deals` | `topic_id`（主键）、`value_text`、`conditions`（位标志）、`link_url`、`expires_at`、`long_term` |
| `posts` | `id`、`topic_id`、`author_uid`、楼层号、`reply_to`、正文、`status` |
| `tags` / `topic_tags` | 标签和关联 |
| `likes` | `(target_type, target_id, uid)` |
| `bookmarks` | `(uid, topic_id)` |
| `user_blocks` | `(uid, blocked_uid)`，被屏蔽的人的帖子和回复不展示 |
| `subscriptions` | `uid`、类型（关键词/分类）、值；命中后只发站内通知 |
| `notifications` | `uid`、类型、关联对象、`read_at` |
| `reports` | 举报对象、举报人、原因、状态、处理人、处理结果 |
| `point_ledger` | `uid`、变动值、原因、关联对象 |
| `uploads` | `uid`、对象存储 key、尺寸、大小、状态 |
| `sponsor_slots` | 位置、标题、链接、图片、起止时间 |
| `admins` / `admin_audit` | 后台管理员和操作日志 |

## 8. 接口（前台）

| 接口 | 说明 |
| --- | --- |
| `GET /api/categories` | 分类树和各分类开关 |
| `GET /api/topics` | 列表，参数：分类、标签、排序、分页 |
| `GET /api/deals` | 福利羊毛，参数：分类、排序 |
| `GET /api/topics/{id}` / `GET /api/topics/{id}/posts` | 详情和楼层 |
| `POST /api/topics` / `PATCH /api/topics/{id}` | 发帖（羊毛帖带 `deal` 字段）/ 编辑 |
| `POST /api/topics/{id}/posts` | 回复 |
| `PUT/DELETE /api/likes`、`/api/bookmarks` | 点赞、收藏 |
| `GET /api/search` | 搜索 |
| `POST /api/uploads/sign` | 获取对象存储上传签名 |
| `POST /api/reports` | 举报 |
| `GET/PUT/DELETE /api/me/subscriptions` | 订阅管理 |
| `GET /api/me/notifications`、`POST .../read` | 消息中心 |
| `GET/PUT/DELETE /api/me/blocks` | 屏蔽用户 |
| `GET /api/users/{uid}` | 用户主页 |

写接口都要登录，并按信任等级做频率限制（TL0 每天 10 条回复，TL1 每天 5 帖等，可配置）。

## 9. 变现

| 方式 | 说明 | 阶段 |
| --- | --- | --- |
| 赞助位 | 首页、福利羊毛列表固定位置，标明"赞助"。卖给 AI 工具、云厂商、开发者服务 | 有稳定日活后 |
| 推广分成 | 站方统一申请云厂商、VPS、AI 工具的推广计划，羊毛帖里的官方链接由站方换成推广链接。用户个人 ref 链接默认禁止，以后可做"邀请链接池"轮换 | MVP 就预留字段 |
| 会员 | 订阅不限条数、更早看到新羊毛、历史库高级筛选、去赞助位 | App 上线后 |

赞助和推广内容必须标明，不能伪装成用户爆料。

## 10. 规则和合规底线

站规明确禁止，命中直接删帖，严重的封号：

- 分享或买卖 API Key、共享账号、卖号、批量注册脚本
- 运营、出售或推广 API 中转服务和付费代理（只讲技术的自建教程可以发，见第 2 节）；公益站只收录信息，站方不担保
- 翻墙教程、机场推广
- 时政、地域、性别引战
- 盗版软件、影视、破解课程
- 人身攻击、开盒、私发推广

配套机制：举报（每个帖子和回复都有入口）、屏蔽用户、新号外链和图片限制、敏感词进审、版权投诉邮箱和下架流程。这些同时也是 Google Play 对 UGC 应用的要求。

## 11. App

复用 `client/xiaoban-multiplatform`：在 `business/` 下新增论坛业务壳，网页套壳，先出 Android APK 官网直装。

原生只补这几项，其他走网页：

- 系统分享：把帖子分享到微信、QQ
- 外链在系统浏览器打开（现有 WebShell 已有站内外链判定）

暂不做系统推送（个推、极光、FCM、APNs 都不接），订阅命中只在站内消息中心提醒，用户打开 App 或网页时看到未读数。以后要做时再评估。

上 Google Play 前要补：账号中心的用户自助注销（目前未实现，Google Play 硬性要求）、12 人 14 天封闭测试、隐私政策和数据安全表单。

## 12. 部署

- 部署在香港机（大陆访问最快，账号中心也在这台），Nginx 反代 `chat.xiangban.xyz`，Let's Encrypt
- 数据库新建 `xiaban_forum` 库，放在已有的 PostgreSQL 容器里
- 本地用 cargo-zigbuild 交叉编译成 Linux 二进制再上传，不在服务器上编译
- 账号中心要做两件事：后台新增应用 `forum-web`，`ACCOUNT_CORS_ORIGINS` 加上 `https://chat.xiangban.xyz`
