# 实施计划：小伴手机版与桌面版互联

状态：讨论稿（2026-10-28）；**2026-10-29 修订：放弃“配对 + 端到端加密”路线，改为同账号登录直连**——用同一个账号登录的手机和电脑自动互相看到，没有二维码、没有设备密钥、没有端到端加密；理由是这只是一个简单的论坛和小工具，不是金融服务，安全边界放在账号和桌面侧的最严格权限上。下文凡涉及配对、二维码、密钥、端到端加密、测试向量的描述均已作废，以 [设备互联协议](../agent/设备互联协议.md) 为准。**当前最高优先级**：先把小伴桌面和小伴手机版接起来，这是语音编程、遥控外部 Agent、手机创作等后续能力的共同底座。对应路线图 [第 2 项](../../client/xiaoban-desktop/docs/assistant-roadmap.md)（手机 App 步骤一）和 [实施计划_内容生态与社区](实施计划_内容生态与社区.md) 里 MB 的第 4 项。

## 1. 目标

**手机上对小伴说一句话，电脑上的小伴去做，手机能实时看到过程，需要确认的操作推到手机，点同意后电脑继续。** 电脑不在线时，手机退回云端纯聊天，并明说电脑不在线。

### 1.1 范围（本计划做）

| 编号 | 能力 | 说明 |
| --- | --- | --- |
| L-1 | 同账号自动发现 | ~~设备配对~~ 已改为：同一账号登录的手机和电脑自动互相看到，电脑在设置里打开“允许手机遥控”才会出现 |
| L-2 | 中转 | 手机与电脑经中转服务通信（~~端到端加密~~ 已取消，中转能看到内容）；电脑不需要公网地址 |
| L-3 | 遥控桌面小伴 | 手机看到电脑上的小伴会话列表，打开一个会话，发消息，实时看流式回复和工具进度 |
| L-4 | 审批转发 | 电脑上小伴要确认的事（动文件、跑命令等）同时出现在手机上，在任一端处理，另一端同步消失 |
| L-5 | 云端纯聊天 | 手机直接与云端模型对话（server-ai，流式，有额度提示），不依赖电脑 |
| L-6 | 在线状态与降级 | 手机上看得到电脑在线/离线；离线时不能遥控，界面明说，不假装能做 |

### 1.2 不在本计划范围

- 外部编程 Agent（Claude Code、Codex）的驱动与语音，见 [目标与实施计划_语音编程](目标与实施计划_语音编程.md)，**排在本计划的主链路跑通之后**。
- 手机上的本地 Agent 内核、手机创作内容包（路线图“手机端的分期”步骤二、三）。
- 离线时在中转里排队执行手机发来的指令：**不做**，避免电脑上线后执行过时的指令。
- 后台推送（国内厂商通道、备案等）：L5 另排；首版靠应用在前台时的长连接和打开时的主动同步。
- 手机上的屏幕/文件远程查看、文件传输（后续再议）。

### 1.3 成功标准

| 指标 | 目标 |
| --- | --- |
| 首次连通用时 | ≤ 1 分钟（电脑打开“允许手机遥控”、手机登录同一账号，到手机“我的电脑”里出现并显示在线） |
| 手机发消息到电脑开始处理 | 在线时 ≤ 1 秒（局域网外、经中转） |
| 流式回复延迟 | 电脑上出现到手机上出现 ≤ 500 ms |
| 审批 | 任一端批准后，另一端 ≤ 1 秒同步；两端同时操作只算先到的 |
| 掉线恢复 | 网络闪断后 ≤ 10 秒自动重连，不丢消息、不重复消息 |
| 中转落盘内容 | 仅设备编号、名称；**不落盘消息**（暂存的离线通知只在内存里） |

## 2. 总体结构

```
手机（Compose）                      中转服务                        电脑（Tauri + Rust）
  │ 云端纯聊天 ────────────► server-ai（已有：对话、额度、流式）
  │
  │ 扫码配对 ◄── 二维码（中转地址 + 一次性码 + 电脑公钥）──── 桌面“连接手机”
  │
  │ WebSocket ──► 设备注册表 + 消息转发 + 在线状态 ◄── WebSocket
  │   端到端加密信封（AES-256-GCM，每方向独立计数器）
  └─────────────── 应用消息（会话列表/快照/发送/事件/审批） ──────────────┘
```

要点：
- **电脑是数据和执行的唯一来源**：会话、记忆、权限都在电脑；手机只缓存最近看过的内容。中转不存历史。
- **账号认证 + 设备认证两层**：账号用统一账号中心的令牌；设备用配对时交换的密钥对。二维码只证明“人在电脑旁边”，不替代账号。
- **云端聊天与遥控是两条线**：云端聊天直接走 server-ai（已有）；遥控走中转。手机的对话页明确标出当前是“云端小伴”还是“我的电脑”。

## 3. 关键设计

### 3.1 中转服务放哪

候选：① 放进 `server-ai`（路线图原先的倾向：账号、额度都在那里）；② 新建独立小服务 `server-link`（仅复用账号中心的令牌验签）。

**建议 ②**：中转是长连接、有状态、不碰模型和额度，扩缩容和故障面与 AI 网关不同；独立后 server-ai 的上线节奏不受影响。技术栈与其他服务一致（Rust Axum + PostgreSQL，离线验签账号令牌）。待你确认（见 §7）。

### 3.2 数据模型（中转侧，只存关系）

| 表 | 字段（要点） |
| --- | --- |
| `devices` | `id`、`uid`、`kind`（desktop/phone）、`name`、`public_key`、`created_at`、`last_seen_at`、`revoked_at` |
| `pairings` | `desktop_id`、`phone_id`、`uid`、`created_at`、`revoked_at`；唯一约束 |
| `pair_codes` | 一次性配对码（哈希存储）、`desktop_id`、`expires_at`（5 分钟）、`used_at` |

不设消息表。转发只在内存里完成，对方不在线就丢弃并回执“对方离线”（通知类消息除外，见 3.5）。

### 3.3 配对

1. 电脑在“设置 → 连接手机”生成设备密钥对（私钥存系统钥匙串/凭据库，不出机器），向中转申请一次性配对码。
2. 电脑显示二维码，内容 = 中转地址 + 配对码 + 电脑设备编号 + 电脑公钥。
3. 手机用同一账号登录，扫码，生成自己的密钥对，把公钥和配对码发给中转；中转校验配对码有效、两端属于同一账号，写入 `pairings`，并通知电脑。
4. 两端各自用对方公钥做 ECDH（P-256）并混入二维码里的一次性密钥派生会话密钥；不需要用户核对任何数字（见 [设备互联协议](../agent/设备互联协议.md)）。
5. 撤销：任一端可“移除设备”，中转标记撤销并断开连接；电脑端删除对应密钥。

### 3.4 消息信封与应用协议

- **信封（中转可见）**：`{v, from, to, seq, nonce, ciphertext}`。`seq` 是每对设备每方向单调递增的序号，用于去重和乱序检测；`nonce` 由方向标记加序号构造，不重复使用。
- **应用消息（加密后）**：带 `type` 和 `id`，首批类型：

| 类型 | 方向 | 作用 |
| --- | --- | --- |
| `hello` | 双向 | 协议版本、能力协商 |
| `sessions.list` / `sessions.changed` | 手机→电脑 / 电脑→手机 | 会话列表与变更 |
| `session.open` / `session.snapshot` | 手机→电脑 / 电脑→手机 | 打开会话、拿到当前完整内容（分页） |
| `message.send` | 手机→电脑 | 发消息（文字，图片后续）；带客户端生成的消息编号做幂等 |
| `event` | 电脑→手机 | 流式回复增量、工具调用开始/结束、状态变化、本轮完成 |
| `approval.request` | 电脑→手机 | 待确认事项（内容、风险等级、选项） |
| `approval.decision` | 手机→电脑 | 手机上的决定；电脑端也处理时向手机发 `approval.resolved` |
| `ping` / `pong` | 双向 | 应用层心跳，量延迟 |

- 协议带版本；未知类型忽略并回 `unsupported`，保证旧版本不崩。
- **安全约束**：手机发来的 `message.send` 视为“远程来源”，权限默认最严格（沿用路线图原则：远程来的任务默认最严格权限，每条留记录，只认本人账号）；高危审批在手机上要二次确认。

### 3.5 在线状态与通知

- 设备连接/断开时，中转向对方推在线状态。
- 电脑离线：手机界面显示“电脑不在线”，输入框改为“发给云端小伴”，不再提供遥控入口。
- 通知类消息（如“任务完成”“等待你批准”）：电脑发给手机时若手机不在线，中转暂存最近 N 条（有上限和 24 小时过期），手机下次上线补发。**只暂存通知，不暂存指令。**

### 3.6 桌面端接入点（已有代码里的缝）

| 需要的能力 | 现有位置 | 做法 |
| --- | --- | --- |
| 会话列表与快照 | `chat/sessions.rs`、`chat_session_snapshot`、`chat_overview` | 直接复用读取接口，转成协议消息 |
| 手机发来的消息进入会话 | `chat/outbox.rs`、`outbox_host.rs`（持久化的会话级用户输入队列，窗口间已共用） | 把远程消息当作一种来源写入同一个队列，复用其持久化、幂等和顺序保证 |
| 流式回复与工具进度 | `chat/mod.rs` 里的 `emit(...)` 事件（`chat-*`） | 在发事件处旁路一份给链接层，映射为协议 `event` |
| 审批 | `chat/broker.rs`、`chat-pending-changed`、`chat-question`、`permission_policy.rs` | 待确认事项同时发给手机；任一端决定后广播已解决 |
| 云端对话入口 | `ai_gateway.rs`、`account.rs` | 手机的云端聊天直接走 server-ai，桌面端无需改 |

### 3.7 手机端结构

- 沿用已建好的 `:common:community-core`（账号、会话令牌）；新增 `:common:link-core`（密钥、信封、重连、协议编解码，不依赖 Compose，JVM 单测）和界面模块。
- 加密实现的选择：Kotlin 侧用成熟库（如 libsodium 的绑定或平台加密 API），**协议规范和测试向量**放在仓库里，桌面（Rust）与手机（Kotlin）都必须通过同一组测试向量，避免两边实现不一致。
- 页面：设备（扫码配对、已配对设备、在线状态）、小伴（顶部切换“云端 / 我的电脑”）、会话列表、会话页（流式、工具进度、审批卡片）。

## 4. 阶段计划

团队按 2–3 人加 AI 估算，周数是范围不是承诺。L1 与 L0 的收尾可重叠；L2 与 L3 并行。

| 任务 | 说明 |
| --- | --- |
| 服务骨架 | Axum + PostgreSQL，离线验签账号令牌，配置与日志沿用其他服务风格 |
| 设备与配对接口 | 注册设备、申请/兑换一次性配对码、列出/撤销已配对设备 |
| WebSocket 转发 | 设备认证、按配对关系转发信封、在线状态、通知暂存（有上限与过期）、心跳 |
| 限流与防滥用 | 每设备带宽/消息数限制、单信封大小上限、配对码尝试次数限制 |
| 测试 | 单元测试加集成测试：两个模拟设备配对、互发、断线重连、撤销后被拒、跨账号被拒 |
| README | 协议、部署、环境变量 |

**退出条件**：两个模拟设备通过真实服务完成“配对 → 互发 → 掉线重连 → 撤销”；中转的数据库和日志里查不到任何正文。

### L2 桌面端接入（3 周，与 L3 并行）

进度（2026-10-28）：**链接层已实现**为独立库 [`libs/link-client`](../../libs/link-client/README.md)——设备身份、配对（验证手机证明）、WebSocket 重连、加解密收发、重放防护、持久化，6 项端到端集成测试通过（真实 server-link）。**剩余**：桌面应用里的接入层（会话桥、审批桥、配对界面、远程来源策略、钥匙串存储），需在 Windows 与 macOS 上编译验证。

| 任务 | 说明 |
| --- | --- |
| 设备身份 | 生成密钥对，私钥进系统钥匙串；设备名称与撤销 |
| 链接层（Rust） | WebSocket 长连接、重连退避、信封加解密、序号与去重、心跳；做成独立库，便于测试 |
| 配对界面 | “设置 → 连接手机”：二维码、倒计时、已连接设备列表、移除 |
| 会话桥 | 会话列表/快照/变更 → 协议；`message.send` → 写入 outbox；事件旁路 → `event` |
| 审批桥 | 待确认事项同步到手机；任一端决定后互相撤销 |
| 远程来源策略 | 标记来源为“手机”，默认最严格权限，写运行记录；设置里可关闭“允许手机遥控” |
| 测试 | 链接层单元测试（含测试向量）；与假手机的集成测试；`src-tauri` 改动必须在 Windows 与 macOS 编译确认 |

**退出条件**：用一个脚本化的“假手机”完成：配对 → 取会话列表 → 发消息 → 收到流式事件 → 处理一次审批。

### L3 手机端（3 周，可与 L2 后半并行）

进度（2026-10-28）：**`link-core` 已实现**——[`:common:link-core`](../../client/xiaoban-multiplatform/common/link-core/README.md)（协议、配对、连接与重连、收发、重放防护、持久化接口）。JVM 上 11 项测试通过（与 Rust 参考实现共用向量，逐字节一致），另有 Kotlin 手机端 ⇄ 真实 server-link ⇄ Rust 桌面端的**跨语言互通测试**通过（配对、双向收发含中文与长消息、重启恢复并换新会话、解除配对）。互通测试顺带暴露并修复了桌面端的一个竞态：启动后立刻配对时，连接循环和 `begin_pairing` 会各登记一台设备，导致二维码里的设备不是连上去的那台（已加串行化和回归测试）。**剩余**：Android 存储（Keystore）、全部界面（设备页与扫码、云端纯聊天页、遥控会话页、审批卡片、离线降级）；Compose 与 Android 目标需在本机编译。

| 任务 | 说明 |
| --- | --- |
| `link-core` | 密钥、信封、重连、协议编解码；JVM 单测通过同一组测试向量 |
| 设备页与扫码 | 相机扫码（权限与失败提示），配对结果、在线状态、移除设备 |
| 云端纯聊天页 | server-ai 流式对话、档位与额度提示、失败重试；这一页**不依赖电脑**，可最先交付 |
| 遥控会话页 | 会话列表、会话页（流式文字、工具进度）、发送、离线降级 |
| 审批卡片 | 展示请求、风险等级、批准/拒绝；高危二次确认；另一端已处理时自动更新 |
| 状态与错误 | 弱网、重连、电脑离线、被撤销、协议版本不匹配的提示 |
| 测试 | 控制器单测（沿用现有风格）；真机联调；Compose 界面需在本机编译 |

**退出条件**：真机上完成第 1 节的完整场景。

### L5 推送与通知（另排）

国内厂商推送通道、备案与上架材料、应用关闭时的“任务完成/等待批准”通知。依赖运营材料，不阻塞 L4。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 两端加密实现不一致 | 无法解密、难排查 | 协议规范加测试向量，两端强制通过 |
| 手机锁屏/后台被系统杀掉 | 看不到实时进度 | 首版明确“前台使用”；打开时主动同步；L5 做推送 |
| 电脑休眠/断网 | 手机遥控不可用 | 在线状态显示；离线明说；提供“保持唤醒”的设置提示 |
| 远程来源执行高危操作 | 安全事故 | 默认最严格权限；高危必须屏幕确认；可一键关闭手机遥控；运行记录 |
| 中转成为单点 | 全体不可用 | 无状态转发为主，可水平扩展；健康检查与监控；云端聊天不依赖它 |
| 桌面 `src-tauri` 改动云端无法编译 | 合入后才发现编译错误 | 每次改动在 Windows、macOS 本机编译；链接层做成独立库，能在沙箱里单测 |
| 国内网络环境 | 连接不稳 | 中转放在国内可达的位置；重连退避；支持自建/自托管地址（后续） |
| 范围蔓延（互联之外又加文件传输、屏幕查看等） | 工期失控 | 本计划范围固定；新需求进下一轮 |

## 7. 已定事项（2026-10-28）

| 事项 | 决定 | 影响 |
| --- | --- | --- |
| 中转服务 | **独立成 `server-link`** | 新建 `services/server-link`；只复用账号中心令牌验签，不依赖 server-ai |
| 手机平台 | **仅 Android** | iOS 的令牌存储、扫码、推送都不做；协议用跨平台算法，留好扩展余地 |
| 配对校验 | **靠登录账号认证，不做用户核对码** | 配对要求两端是同一账号。二维码里另带一个一次性密钥，用来防止中转冒充对端，用户看不到也不用操作 |
| 手机遥控 | **默认关闭**，在电脑上首次配对时明确开启 | 电脑设置里有“允许手机遥控”开关，可随时关 |
| 分发 | **自己分发 APK** | 不做商店材料、备案与软著；推送（L5）因此继续后排 |
| 云端聊天额度 | **沿用 server-ai 现有试用额度** | 手机不单独设额度 |
