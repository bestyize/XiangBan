# 聊天里的卡片：桌面版有什么，手机版缺什么

整理于 2026-10-30。桌面版的聊天页是 `client/xiaoban-desktop-wallpaper/src/ui/pages/ChatPage.vue`，卡片组件在 `src/ui/chat/` 和 `src/ui/components/Chat*.vue`；手机版是 `client/xiaoban-multiplatform/business/community-native` 里的 `RemoteScreens.kt`（设备聊天）和 `AiScreens.kt`（小伴AI 对话），部件在 `Kit.kt`。

| # | 桌面版 | 内容 | 手机 | 手机现状与缺口 |

| 7 | 已回答记录 `ChatAnswered` | 问过的问题和你的回答（或“已跳过”）留在对话里 | ⬜ | 没有；回答后卡片直接消失，对话里不留痕 |
| 8 | 审批卡 | 风险动词（读/写/联网/执行）、工作区外路径提示、高风险提示（完全信任下也要确认）、读过外部网页的提示、命令预览；允许一次 / 本对话都允许 / 拒绝 | ◐ | 有卡片、高危二次确认、允许一次/拒绝。缺：风险类型和“工作区外路径”“读过外部内容”的提示（协议没传）；预览只有一行摘要，不能看全文 |

## 4. 为什么缺：协议只传了一小部分

电脑实际发给手机的东西很少，卡片做不全是因为数据不够，不只是界面没画：

- 实时事件只有：`text.delta`、`reasoning.delta`（手机丢弃）、`tool.start`/`tool.end`、`turn.done`、`error`、`state`。**没有**：工具参数流式进度、资源等待、用量、提示条（重试/继续/撤销）、文件变更、任务状态。
- 审批和选择问题共用一种消息 `approval.request`：风险类型、工作区外路径、读过外部内容、“允许一次/总是允许”以外的信息都没传；选择问题的“可以自己输入”也没传。
- 历史快照（`session.snapshot`）里每条消息只留角色和文字，工具调用只留名字，**不带参数和结果**，所以打开旧对话时看不到任何工具卡片、任务卡片、文件卡片。
- 小伴AI 对话页用的手机内核目前只注册了一个“设提醒”工具，没有 `todo`、没有 `ask_user`，所以任务卡片和选择卡片在云端对话里本来就不会出现。

## 5. 建议的补法（按价值和难度排）

**第一批：对话里最影响观感的**
1. **工具调用组（#5）**：一轮的所有工具合成一张可折叠卡，摘要“N 步 · 用时 · 异常”，进行中显示最新一步，展开后每步可看内容和结果。需要：快照带上工具参数和结果（截断）；手机把 `tool.start/end` 存下来而不是一轮结束就清空。
2. **任务执行卡（#4）**：从 `todo` 工具的调用里还原计划，画步骤和分段进度条、状态、停止。数据已经在工具参数里，主要是手机侧的解析和界面；设备聊天马上能用，云端对话需要先给内核加 `todo` 工具。
3. **选择卡（#6、#7）**：协议新增“问题”消息（问题、选项、是否可自己输入），手机画编号选项加输入框加跳过，回答后留一条“已回答”记录。云端对话需要给内核加 `ask_user`。
4. **Markdown 与代码块（#2）**：手机侧写一个简化的 Markdown 渲染（标题、列表、粗体、行内代码、代码块、链接）。

**第二批：补全细节**
5. 提示条的“重试 / 继续 / 切换模型”（#9）、回复操作栏的“复制 / 重新生成 / 用量”（#11）、思考折叠（#3）。
6. 文件卡片（#10）：从写文件类工具的参数取路径，显示“交付文件 / 文件变更”。
7. 审批卡补风险类型和提示语（#8）：协议里带上 `risk`、`external_path`、`tainted`。
8. 用户气泡带图片和文件（#1）：需要先有手机侧的图片/文件发送。

**第三批：先不做或要先想清楚**
排队消息（#15）、上下文环（#16）、权限模式（#17）、目标面板（#21）、执行面板（#22）：手机屏幕小，可以先用“工具调用组”的展开代替执行面板；排队和权限模式需要协议支持，等第一批做完再看。
