# 手机端设计规范

产品负责人在做手机端设计稿（Claude Design 画布「社区与小伴AI 手机原型」，65 张画板）的过程中，陆续提出的视觉与交互要求，整理成以后画稿和写界面代码时遵守的规范。有冲突时以这里为准；“当前代码”一栏标出还没对齐的地方。

## 1. 总原则

1. **克制、工作风。** 界面要安静、耐看，不吓人。文字是主角，装饰靠边。
2. **红色是点缀，不是底色。** 品牌红只给主按钮、选中态和提醒，不做大面积实心块，也不用来表示“取消”。
3. **不用纯黑块。** 实心黑色按钮、黑色气泡和黑色状态栏都和整体不搭，用浅色底加有色字。
4. **少写字，多用图标。** 工具栏、状态靠图标和形状表达；画板上也一样，不写长解释。
5. **一件事一步完成。** 高危操作在手机上只确认一次，不再弹二次确认。

## 2. 颜色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面底 | `#FAFAFA` | 接近白色的极浅灰（参照小红书信息流的底色），整页看起来是白的 |
| 卡片、弹层、列表 | `#FFFFFF` | 纯白，静态卡片不加阴影；放在页面底上的圆角卡片加一圈细描边，见第 3 节 |
| 卡片描边、分隔线 | `#EDEDED` | 1dp 描边和 0.5px 分隔线共用 |
| 白卡片里的次要控件、输入框、标签 | `#F2F2F2` | 比页面底稍深的灰，只在白色卡片里用 |
| 品牌红 | `#E3203C` | 主按钮、选中态、提醒 |
| 品牌红浅底 | `#FFF3F4` | 浅红底配红字，用于“允许一次”这类主操作 |
| 文字 | `#222222` / `#444444` / `#666666` / `#9A9A9A` | 主要、次要、说明、占位 |
| 成功 | `#2FA36B` | 步骤完成的对号圆圈、“完成” |
| 失败 / 拒绝 | `#E3203C` | 失败步骤、被拒绝的 × 圆圈 |

- 成功用绿色，失败和拒绝用红色，不用黑色或灰色表示结果。
- 试过的灰绿（`#7DA98F`）和实心绿按钮都不采用。
- 不另造新的强调色，需要强调时用品牌红的浅底。

## 3. 层次：极浅底、白卡片加细描边，阴影只给浮层

- 页面底只比白色暗一点（`#FAFAFA`），不要大面积的明显灰底。白色圆角卡片放在页面底上时，加一圈 1dp `#EDEDED` 描边和底色分开（代码里用 `Modifier.outlinedCard()`）；**静态卡片不加阴影**。
- 2026-11-01 起页面底从 `#EDEDED` 改为 `#FAFAFA`：旧的灰底让白卡片像贴在灰墙上，小伴AI、创造这类卡片多的页面大面积发灰。
- 只有**会浮起来的东西**才有阴影：弹出菜单、底部弹层、悬浮的迷你进度条、吸底的输入框卡片。输入框卡片 `0 2px 12px rgba(0,0,0,.06)`，底部弹层 `0 -4px 24px rgba(0,0,0,.08)`，弹出菜单 `0 6px 24px rgba(0,0,0,.14)`，迷你进度条 `0 4px 16px rgba(0,0,0,.12)`。
- 白色卡片里的次要控件（输入框、标签、图标底）用 `#F2F2F2` 灰底，不要白底加描边。
- 保留的线：页面底上圆角卡片的 1dp 描边、列表里的细分隔线（0.5px）、选中态的红色描边、进度圈。顶栏底部不画线。
- 底部弹层只有上圆角。
- **设置、列表这类页面的选项，圆角和通栏二选一，不混用**：我们用通栏——白色列表撑满屏幕宽度、不留左右边距、不要圆角，行之间 0.5px 分隔线，组与组之间露出页面底。通栏列表撑满屏幕，不加描边。不要做“留 16 左右边距又是直角”的样子。需要圆角卡片的地方（聊天卡片、弹层）才留边距并用 16 圆角。

## 4. 按钮

**尺寸（触控目标不能太矮）**

| 类型 | 高度 | 圆角 |
| --- | --- | --- |
| 弹层底部的主要按钮 | 44–48 | 全圆 |
| 卡片里的操作按钮（允许一次、拒绝…） | 40 | 全圆 |
| 药丸、快捷建议、状态入口 | 34 | 全圆 |
| 次要小标签（关注等） | 不低于 32 | 全圆 |

- 卡片里的多个操作按钮**撑满一行、等宽排开**，不缩窄收到右侧；字号 14。
- 按钮配色分三级：**主操作**＝浅红底红字；**次要**＝浅灰底深灰字；**弱操作**（拒绝、取消）＝无底色灰字。
- 高风险卡片两个按钮都是白底：“拒绝”深色字、“允许一次”红字；不提供“本对话都允许”。
- 禁止：实心黑按钮、实心大红按钮、实心绿按钮、圆形灰底的文字按钮。

## 4.1 字号、圆角、间距、图标

| 项目 | 取值 |
| --- | --- |
| 字号 | 六档，字号/行高：大标题 22/30（首页问候、昵称、醒目数字）、页面标题 18/24（顶栏标题、一级 tab、弹层标题）、小节标题 16/22（分区标题、卡片标题）、正文 15/22（列表主文字、输入框、摘要）、次要 13/18（说明、作者和时间、按钮小字）、辅助 12/16（标签、计数、角标）。最小 12，只有底部导航文字用 10。不加字距。代码里写 `style = XType.Body` 这样取（`Theme.kt`），不直接写 fontSize；字重另写 |
| 圆角 | 大卡片和弹层 16；卡片里的内嵌块 8；按钮、药丸、标签全圆 |
| 间距 | 4 的倍数：4 / 8 / 12 / 16 / 24 |
| 图标 | 尺寸 16 / 20 / 24；线宽 1.8，圆头圆角 |

## 4.2 底部导航

- 经典的上图标、下文字：通栏白底，顶部 0.5px 细线，高 56（另加系统手势条），五项平分宽度，位置固定，切换时不跳动。
- 当前项图标和文字用主要文字色、文字加粗；其余用次要文字色。选中态**不用红色**，也不做实心胶囊。
- 中间的“发布”只放图标，是 44×32、圆角 10 的品牌色小方块，白色加号；它是导航里唯一的红色。
- 文字 10，是“最小 12”的例外，只用于底部导航。
- 2026-11-01 起替换原来的悬浮胶囊导航（当前项展开成实心红胶囊），原因是切换时其他图标会挪位、大多数图标没有文字、每页底部都有一大块红色。

## 4.3 小程序运行页

- **全屏背景**：Android 协议 2 作品的背景铺满屏幕，延伸到状态栏和手势区后方。用系统安全区给文字和控件留边距，竖屏保留系统状态图标和手势。
- **宿主菜单**：Android 协议 2 的所有小程序和小游戏共用右上角竖三点。图标为 16 dp，使用中性色和轻微阴影，透明底，无描边。横屏和竖屏的触控区均为 48 × 48 dp；位置以宿主上报的实际矩形为准。只让与矩形相交的控件局部避开，留至少 8 dp 间隔；整页的顶部留白只由系统安全区决定。检查页面滚动、弹窗和横竖屏切换后的实际触控范围。
- **菜单弹层**：点竖三点打开现有宿主弹窗。竖屏从底部弹出，顶部显示应用信息，中间一行显示重新开始、收藏和分享等可用操作，底部单列「退出」。退出由宿主处理，关闭弹窗后继续显示当前页。
- **工具小程序的子页**：左上角放无底色的「‹」返回按钮，图标为 20 dp，触控区为 48 × 48 dp。与右侧竖三点同高，左右距安全区边缘等距。页面标题居中，用 16/22 的小节标题字号，中心与两侧图标同高。首页省略返回按钮，保留首页标题样式。
- **标题行与内容区**：按宿主上报的触控区定位右侧菜单，同一行的内容与左右按钮触控区各留至少 8 dp。居中标题用两侧占位的较大值做对称内边距。菜单下方恢复页面的常规边距，搜索、筛选和步骤条可以通栏。固定栏和滚动后的可点击内容也要避开菜单的实际触控区。预览时检查窄屏长标题及横屏安全区。
- **页内返回**：左上角箭头与 Android 系统返回共用浏览器历史，每次回到上一页。完成添加、保存等流程后，从结果页返回所属列表。Android 协议 2 游戏运行页沿用宿主导航，游戏内层级接入浏览器历史。

设计以[遥控器交互稿](../../client/xiaoban-multiplatform/docs/design-specs/prototypes/universal-remote.html)为例，安全区、历史和退出规则见[运行时协议](../architecture/app-runtime/README.md#63-返回)。

## 5. 对话框（输入卡片）

- 工具栏只放**图标**，**不要圆形灰底，也不要描边**：左边 `＋`、模型、权限（锁），右边麦克风、波形（实时对话）、发送。
- 联网一直开着，**不放联网按钮**；权限收成工具栏里的一个锁图标，输入框上方不再单独放权限胶囊。
- 设备聊天里，模型图标显示为电脑图标（跟随电脑）；指定了模型时图标右上角一个红点。
- 状态靠图标本身：完全信任时锁变红；设备不在线时整条置灰。
- 工具栏在 320 宽的小屏上也要放得下，不用文字按钮。
- 发送键是唯一的实心红圆；不能发送时灰色。

## 6. 聊天里的卡片

- 任务步骤前的圆形标记：完成＝绿底白对号，进行中＝转圈，等待授权/受阻＝红，失败/拒绝＝红底白 ×，暂停＝灰，未开始＝空心圈。
- 权限申请卡：普通申请浅红底红字的“允许一次”＋浅灰“本对话都允许”＋灰字“拒绝”；高风险用浅红底卡片，只有“允许一次”“拒绝”。
- 高危操作只确认一次，没有二次确认弹层。
- 处理之后，卡片收成一行留在对话里。

## 7. 实时对话（语音通话）

- 深色页（深石墨底，不是纯黑），背景只留一圈圈同心圆再加两三个很淡的形状（闪光星、圆角方块），不用点阵，不堆砌。
- **页面主角是文字**：你说的话、小伴的回答。小伴本身是中间一个 **54dp 的圆形品牌头像**（红底白色闪光），状态靠头像外圈表达：聆听＝淡淡呼吸，听到你说话＝随音量扩散，思考＝虚线绕着转，小伴在说＝头像轻跳、外圈起伏。
- 回复最多露出三行，可以上下滑；中间一行正常，上下两行渐渐淡出。
- 底部三个**一样大（68dp）**的圆按钮：静音、打断、挂断；挂断用实心听筒图标，是这一页唯一的红。
- 顶部只有设备名和通话时长，不显示识别引擎、朗读引擎这类标签和小字。
- 收起成胶囊、回答随朗读逐句高亮在设计稿里有，代码还没做。

## 8. 语音输入（按住说话）

- 麦克风切到“按住 说话”条；按住录音，松手识别并发送，上滑取消，滑到右边“转文字”放进输入框再改。
- 按住时页面压暗，上方气泡显示时长和声波；气泡和条都是白或浅红底，**取消状态用白色，不用红色或灰色实心**。
- 最长 20 秒，最后 10 秒倒计时；不到 0.5 秒算太短；被来电等打断直接取消。

## 9. 画设计稿的写法

- 文案能删就删：同一件事不在画板上说两遍，每条说明一句话以内。
- 每个状态上方只写**状态名**（如“运行中 · 展开”“等待授权”），不写操作说明和理由；画板顶栏不写副标题（设备在线状态例外）。
- 画布上的便签只留两类：全局规则（示例数据、配色），以及还没定下来的问题。不做逐画板的解释。
- 界面里真正会出现的文案（隐私提示、错误原因、引导语）是产品文字，保留；设计说明不算。
- 画板按内容高度收紧，不留大片空白；宽 390。
- 先出设计稿，确认后再实现；改设计稿时先读线上最新版本，再在它上面改，不要拿旧副本覆盖。

## 10. 深色模式与主题色

- 设置 → 外观：**主题**（跟随系统 / 浅色 / 深色，三张迷你界面预览，选中的描边加对号）和**主题色**（六套：小伴红、薄荷绿、海湾蓝、暮紫、琥珀、石墨，沿用桌面端；每套有浅色、深色两组色值）。
- 深色配色：页面 `#111111`、卡片 `#1C1C1E`、卡片里的次要块 `#2C2C2E`、主要文字 `#ECECEC`、说明 `#9A9AA0`、分隔线很淡。
- 主题色只影响主按钮、发送键、选中态、开关、用户气泡的浅底和浅底上的文字，**页面底和卡片保持中性灰白，不染色**。
- **成功绿、失败/拒绝/高风险红不跟主题色走**，换了主题色它们也不变。
- 石墨的主按钮接近黑色，和“不用纯黑块”冲突，先和桌面端保持一致，待定。

## 11. 当前代码和这份规范的差距

已按规范改好：设置里的声音页（来源、音色、语速、自动朗读）、`DesignTokens`（`#FAFAFA` 底、深色配色、六套主题色）、主题与主题色页（`ThemeState`，选择保存在手机本地偏好里）、通用部件（页面底上的圆角卡片用 `outlinedCard` 细描边，其余无描边；浅灰底输入框与药丸、次要按钮浅灰底、顶栏不画线、开关勾选用主题色）、用户气泡浅底深色字、聊天卡片（任务步骤绿对号和红叉、授权卡三个等宽 40 高按钮、高风险白底按钮、提醒条浅红底）、输入框工具栏改成图标（芯片/电脑、锁、麦克风、波形、发送，没有联网按钮）、字号收敛到六档 `XType`（2026-11-02 起；小伴AI、创造、社区、我的四个主页面和通用部件已改，其他页面还在直接写字号）、出错文字用固定红色。

还没做：

- 实时对话页（`VoiceCallScreen`）缺逐句高亮、外放切换；通话后留在对话里的“语音通话 04:12 · 6 轮对话 再通话”一行也没做。
- 按住说话（第 8 节）已做主流程；声波现在是示意动画（没接真实音量），来电打断没接系统事件。没有麦克风权限会弹“需要使用麦克风”面板（去设置），第一次切到语音模式有引导提示。
- 圆角已统一成 16 / 8 / 全圆（图标方块 16，输入框 8，提示条和聊天卡片 16）；间距还没逐页对到 4 的倍数。
- `#FAFAFA` 底和卡片描边目前在小伴AI、创造、我的三页上真机看过（小米 14）；社区、设置等其他页面还没逐页检查，有的白卡片可能还缺描边。
- 深色模式没有逐页在真机上看过，封面渐变、代码块等少数地方还是固定颜色。
