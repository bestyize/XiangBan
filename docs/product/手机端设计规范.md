# 手机端设计规范

产品负责人在做手机端设计稿（Claude Design 画布「社区与小伴AI 手机原型」，65 张画板）的过程中，陆续提出的视觉与交互要求，整理成以后画稿和写界面代码时遵守的规范。有冲突时以这里为准；“当前代码”一栏标出还没对齐的地方。

## 1. 总原则

1. **克制、工作风。** 界面要安静、耐看，不吓人。文字是主角，装饰靠边。
2. **红色是点缀，不是底色。** 品牌红只给主按钮、选中态和提醒，不做大面积实心块，也不用来表示“取消”。
3. **不用纯黑块。** 实心黑色按钮、黑色气泡和黑色状态栏都和整体不搭，用浅色底加有色字。
4. **少写字，多用图标。** 工具栏、状态靠图标和形状表达；画板上也一样，不写长解释。
5. **一件事一步完成。** 高危操作在手机上只确认一次，不再弹二次确认。

## 2. 颜色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面底 | `#EDEDED` | 微信式浅灰 |
| 卡片、弹层、列表 | `#FFFFFF` | 纯白，不加描边，静态卡片不加阴影 |
| 白卡片里的次要控件、输入框、标签 | `#F2F2F2` | 比页面底更浅的灰，只在白色卡片里用 |
| 品牌红 | `#E3203C` | 主按钮、选中态、提醒 |
| 品牌红浅底 | `#FFF3F4` | 浅红底配红字，用于“允许一次”这类主操作 |
| 文字 | `#222222` / `#444444` / `#666666` / `#9A9A9A` | 主要、次要、说明、占位 |
| 成功 | `#2FA36B` | 步骤完成的对号圆圈、“完成” |
| 失败 / 拒绝 | `#E3203C` | 失败步骤、被拒绝的 × 圆圈 |

- 成功用绿色，失败和拒绝用红色，不用黑色或灰色表示结果。
- 试过的灰绿（`#7DA98F`）和实心绿按钮都不采用。
- 不另造新的强调色，需要强调时用品牌红的浅底。

## 3. 层次：底灰、卡白，阴影只给浮层

- 层次靠“浅灰底上的纯白卡片”，**不画浅灰描边，静态卡片也不加阴影**。
- 只有**会浮起来的东西**才有阴影：弹出菜单、底部弹层、悬浮的迷你进度条、吸底的输入框卡片。输入框卡片 `0 2px 12px rgba(0,0,0,.06)`，底部弹层 `0 -4px 24px rgba(0,0,0,.08)`，弹出菜单 `0 6px 24px rgba(0,0,0,.14)`，迷你进度条 `0 4px 16px rgba(0,0,0,.12)`。
- 白色元素直接放在灰底上，保持白色；放在白色卡片里时，改成 `#F2F2F2` 灰底，不要白底加描边。
- 保留的线：列表里的细分隔线（0.5px）、选中态的红色描边、进度圈。顶栏底部不画线。
- 底部弹层只有上圆角。

## 4. 按钮

**尺寸（触控目标不能太矮）**

| 类型 | 高度 | 圆角 |
| --- | --- | --- |
| 弹层底部的主要按钮 | 44–48 | 全圆 |
| 卡片里的操作按钮（允许一次、拒绝…） | 40 | 全圆 |
| 药丸、快捷建议、状态入口 | 34 | 全圆 |
| 次要小标签（关注等） | 不低于 32 | 全圆 |

- 卡片里的多个操作按钮**撑满一行、等宽排开**，不缩窄收到右侧；字号 14。
- 按钮配色分三级：**主操作**＝浅红底红字；**次要**＝浅灰底深灰字；**弱操作**（拒绝、取消）＝无底色灰字。
- 高风险卡片两个按钮都是白底：“拒绝”深色字、“允许一次”红字；不提供“本对话都允许”。
- 禁止：实心黑按钮、实心大红按钮、实心绿按钮、圆形灰底的文字按钮。

## 4.1 字号、圆角、间距、图标

| 项目 | 取值 |
| --- | --- |
| 字号 | 12（说明、标签）/ 14（正文、按钮）/ 15（列表主文字、输入）/ 16（标题）；最小 12，不用 13、11 |
| 圆角 | 大卡片和弹层 16；卡片里的内嵌块 8；按钮、药丸、标签全圆 |
| 间距 | 4 的倍数：4 / 8 / 12 / 16 / 24 |
| 图标 | 尺寸 16 / 20 / 24；线宽 1.8，圆头圆角 |

## 5. 对话框（输入卡片）

- 工具栏只放**图标**，**不要圆形灰底，也不要描边**：左边 `＋`、模型、权限（锁），右边麦克风、波形（实时对话）、发送。
- 联网一直开着，**不放联网按钮**；权限收成工具栏里的一个锁图标，输入框上方不再单独放权限胶囊。
- 设备聊天里，模型图标显示为电脑图标（跟随电脑）；指定了模型时图标右上角一个红点。
- 状态靠图标本身：完全信任时锁变红；设备不在线时整条置灰。
- 工具栏在 320 宽的小屏上也要放得下，不用文字按钮。
- 发送键是唯一的实心红圆；不能发送时灰色。

## 6. 聊天里的卡片

- 任务步骤前的圆形标记：完成＝绿底白对号，进行中＝转圈，等待授权/受阻＝红，失败/拒绝＝红底白 ×，暂停＝灰，未开始＝空心圈。
- 权限申请卡：普通申请浅红底红字的“允许一次”＋浅灰“本对话都允许”＋灰字“拒绝”；高风险用浅红底卡片，只有“允许一次”“拒绝”。
- 高危操作只确认一次，没有二次确认弹层。
- 处理之后，卡片收成一行留在对话里。

## 7. 实时对话（语音通话）

- 深色页（深石墨底，不是纯黑），背景只留一圈圈同心圆再加两三个很淡的形状（闪光星、圆角方块），不用点阵，不堆砌。
- **页面主角是文字**：你说的话、小伴的回答。小伴本身是中间一个 **54dp 的圆形品牌头像**（红底白色闪光），状态靠头像外圈表达：聆听＝淡淡呼吸，听到你说话＝随音量扩散，思考＝虚线绕着转，小伴在说＝头像轻跳、外圈起伏。
- 回复最多露出三行，可以上下滑；中间一行正常，上下两行渐渐淡出。
- 底部三个**一样大（68dp）**的圆按钮：静音、打断、挂断；挂断用实心听筒图标，是这一页唯一的红。
- 顶部只有设备名和通话时长，不显示识别引擎、朗读引擎这类标签和小字。
- 收起成胶囊、回答随朗读逐句高亮在设计稿里有，代码还没做。

## 8. 语音输入（按住说话）

- 麦克风切到“按住 说话”条；按住录音，松手识别并发送，上滑取消，滑到右边“转文字”放进输入框再改。
- 按住时页面压暗，上方气泡显示时长和声波；气泡和条都是白或浅红底，**取消状态用白色，不用红色或灰色实心**。
- 最长 20 秒，最后 10 秒倒计时；不到 0.5 秒算太短；被来电等打断直接取消。

## 9. 画设计稿的写法

- 文案能删就删：同一件事不在画板上说两遍，每条说明一句话以内。
- 每个状态上方只写**状态名**（如“运行中 · 展开”“等待授权”），不写操作说明和理由；画板顶栏不写副标题（设备在线状态例外）。
- 画布上的便签只留两类：全局规则（示例数据、配色），以及还没定下来的问题。不做逐画板的解释。
- 界面里真正会出现的文案（隐私提示、错误原因、引导语）是产品文字，保留；设计说明不算。
- 画板按内容高度收紧，不留大片空白；宽 390。
- 先出设计稿，确认后再实现；改设计稿时先读线上最新版本，再在它上面改，不要拿旧副本覆盖。

## 10. 深色模式与主题色

- 设置 → 外观：**主题**（跟随系统 / 浅色 / 深色，三张迷你界面预览，选中的描边加对号）和**主题色**（六套：小伴红、薄荷绿、海湾蓝、暮紫、琥珀、石墨，沿用桌面端；每套有浅色、深色两组色值）。
- 深色配色：页面 `#111111`、卡片 `#1C1C1E`、卡片里的次要块 `#2C2C2E`、主要文字 `#ECECEC`、说明 `#9A9AA0`、分隔线很淡。
- 主题色只影响主按钮、发送键、选中态、开关、用户气泡的浅底和浅底上的文字，**页面底和卡片保持中性灰白，不染色**。
- **成功绿、失败/拒绝/高风险红不跟主题色走**，换了主题色它们也不变。
- 石墨的主按钮接近黑色，和“不用纯黑块”冲突，先和桌面端保持一致，待定。

## 11. 当前代码和这份规范的差距

已按规范改好：`DesignTokens`（`#EDEDED` 底、深色配色、六套主题色）、主题与主题色页（`ThemeState`，选择保存在手机本地偏好里）、通用部件（无描边、浅灰底输入框与药丸、次要按钮浅灰底、顶栏不画线、开关勾选用主题色）、用户气泡浅底深色字、聊天卡片（任务步骤绿对号和红叉、授权卡三个等宽 40 高按钮、高风险白底按钮、提醒条浅红底）、输入框工具栏改成图标（芯片/电脑、锁、麦克风、波形、发送，没有联网按钮）、字号收敛到 12/14/15/16 一档、出错文字用固定红色。

还没做：
- 实时对话页（`VoiceCallScreen`）缺收起胶囊、逐句高亮、外放切换。
- 按住说话（第 8 节）已做主流程；声波现在是示意动画（没接真实音量），没有麦克风权限时只弹提示、没有“去设置”弹层，来电打断没接系统事件，首次切到语音模式的引导气泡也没做。
- 各页的圆角、间距还没逐页对到 16 / 8 / 4 的倍数，卡片阴影也没逐页核对。
- 深色模式没有逐页在真机上看过，封面渐变、代码块等少数地方还是固定颜色。
