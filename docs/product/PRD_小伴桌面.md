## 1. 产品定位与目标

**壁纸里住着一只小伴。** 用户可以把喜欢的图片、动态壁纸和小伴组合成自己的桌面，双击桌面进入游戏空间，也让小伴通过关怀提醒、专注和轻量互动参与日常生活。

**产品取向：玩法形态创新，官方出内容，自定义只做到“轻度”。**

- **竞争方式**：不与 Wallpaper Engine 等成熟产品比内容数量和创作自由度，也不走开放创作者生态。差异放在“桌面陪伴”的整合体验上：特效、互动壁纸、小伴、关怀提醒和游戏空间互相配合，美术统一、安全、轻量、开箱即用。
- **小伴就是互动壁纸**：小伴是壁纸之上的透明角色窗口，能跟随鼠标视线、响应点击与拖动、有空闲与睡眠状态，是本产品互动壁纸的主形态，不另做一套独立的互动壁纸。壁纸画面本身随鼠标变化（水波、视差等）受桌面图标层级限制，难度高，不作为近期方向。
- **创新重点**：下一批投入放在让小伴与环境联动（回应特效、天气和用户状态），以及节日场景（春节红包雨、节日形象）。这些由官方设计运动、层次和手感，保证质量与性能。
- **自定义边界**：多数用户只使用、不创作，因此只保留两种轻度自定义：调参数（密度、速度、大小），以及把特效里的元素换成自己的图片（红包换成自己的图，雪花换成宠物照片）。不提供自由编辑器，不做配置分享，不做第三方内容市场。特效包 JSON 保留为官方内容的生产格式，高级用户可以用，但不作为主入口宣传。
- **开放的假设**：以上是产品判断，尚未经用户研究验证。游戏空间是否有持续需求也未验证，见第 8 节。

本轮目标：

- 用桌面沉浸游戏提供容易感知、容易展示的体验，复用相伴网站已有游戏包。
- 用天气、下班、休息和自定义提醒，建立持续使用价值与小伴的角色特色。
- 让桌面通过雨、雪、花瓣、枫叶、流星、繁星等效果变得有生命感，不论背后是哪张壁纸，并逐步补充专注、互动和场景变化。
- 让壁纸、特效、小伴、信息组件和声音可以独立选择与开关。
- 延续轻量、本地可用的体验，避免为基础功能增加账户或联网门槛。

设计原则：安静陪伴、主动操作有反馈、背景变化克制、不抢占用户正在进行的工作。默认不自动开启新特效、声音、计时任务或关怀规则；游戏空间由用户主动唤起。

## 5. 功能需求

### 5.1 桌面特效层

入口是控制台独立的“桌面特效”页，不再藏在壁纸预览里。特效属于桌面，不属于某张壁纸：用户选了一种，不论之后换哪张壁纸、用系统桌面，还是壁纸是视频或互动动画，它都照常显示。

- **内置七种**：下雨、下雪、萤火虫、花瓣飘落、枫叶飘落、流星划过、繁星，加上“无特效”；每次选一种。页面上每种都是一张实时播放的预览卡片，点一下立即生效，不需要“应用”。
- **三个参数**：密度（0.2 到 2.5 倍）、速度（0.25 到 3 倍）、大小（0.5 到 2 倍），拖动时即时作用到桌面。每种特效各自记住自己的参数，切换后再切回来是上次的样子。参数范围以可见效果和性能实测为准。
- **表现原则**：有远近层次（远的小、慢、淡，近的大、快、亮）；所有特效共用一阵缓慢变化的风，雨随风倾斜，雪、花瓣、枫叶随风飘；花瓣和枫叶会翻转、打旋；流星隔几秒划过一颗；繁星会各自眨眼。形状要大到在 1080p 屏幕上看得清，数量要够出氛围，宁可稍密也不要稀稀落落，但不盖住用户在做的事。
- **叠放位置**：特效是桌面上一层透明、鼠标可穿过的窗口，在桌面图片之上、桌面图标和其他应用窗口之下；不截获桌面输入，保留桌面图标操作。关闭特效后窗口销毁，循环、监听和资源一并释放。
- **和其他功能的关系**：特效与小伴分别开关；全局“暂停桌面动画”和 30/60 帧设置同样适用；游戏空间打开期间隐藏，退出后恢复。特效不改写任何壁纸文件，也不随壁纸保存；应用设置跨重启保留。内置特效离线可用。
- **旧配置**：早期版本把特效存在每张壁纸里，首次启动时把正在使用的那一个迁成桌面的选择（旧的“树叶”变成“枫叶”），之后不再写回壁纸。

**特效是数据，不是代码。** 每种特效是一个 JSON 文件（特效包），写明有几层粒子，每层的数量、大小范围、速度、方向、风的影响、摇摆、自转、翻面、闪烁、颜色和形状（圆点、光斑、拖尾线条或自定义 SVG 路径），由统一的引擎读取并绘制。这样做有三个理由：新增或调整一种特效只改数据，不改程序；内置和用户自己的特效走同一条路；包里没有可执行内容，不需要给它任何权限。

- 内置特效包编译进程序，离线可用；用户自己的放进数据目录的 `effects/` 文件夹，在页面点“重新载入”即可生效，不用重启。文件夹首次从页面打开时会放入一份示例。
- 宿主只检查文件是否是合法 JSON、有可用的 id；真正用之前，绘制端会逐项检查并限制每个数值的范围、颜色必须是十六进制、路径只能是纯路径数据，不合格的整份丢弃。文件大小、数量和粒子总数都有上限。一个坏文件只在页面上提示“文件名：原因”，不影响其他特效。
- 格式、字段、限制和示例见桌面工程的 [特效包格式](../../client/xiaoban-desktop-wallpaper/docs/effects.md)。
- 特效包 JSON 是官方内容的生产格式。文件夹加载保留给高级用户，不作为主入口推广，也不为它做编辑器。
- 暂不做：特效包的在线商店或订阅、可执行的特效脚本、特效配置的分享、按天气或时间自动切换特效。天气驱动与房间昼夜变化需另行立项。

#### 轻度自定义：素材槽位（规划，未实现）

目的：用户不碰 JSON，只选几张图，就能把特效里的元素换成自己的，例如红包雨里的红包、金币雨里的金币，或把家人、宠物的照片当作飘落的雪花。运动、层次和手感仍由官方设计。

- **特效包声明槽位**：特效包里的某一层可以声明“素材槽位”，写明槽位名称、默认图片（官方素材）和用户最多可放几张。形状新增一种“图片”，由槽位提供图像。没有声明槽位的特效不显示素材区。
- **用户的选择不写进特效包**：所选图片保存在应用设置里，与密度、速度、大小并列，每种特效各自记住。特效包文件保持纯数据，可随意重新载入。
- **控制台入口**：选中带槽位的特效后，在三个滑块下方出现“素材”区：添加图片、预览、移除、恢复默认。添加后立即在预览和桌面上生效，不需要“应用”。
- **图片限制**：只接受位图（PNG、WebP、JPG），不接受 SVG；单张体积和尺寸设上限（初值：512 KB、长边 512 像素），每个槽位的张数设上限（初值：8 张）。加载时统一缩放成小尺寸精灵图，保证几百个粒子的绘制开销可控。超限、损坏或格式不支持的图片要给出明确提示，不影响其他图片。
- **存放与隐私**：选中的图片复制到用户数据目录再使用，不引用原路径，原文件被移动或删除也不影响；图片只在本机使用，不上传，不随任何分享流出。
- **权限边界**：特效窗口不能读取文件。图片由可信宿主读取、检查、缩放后交给特效窗口，特效窗口仍只有现有的最小命令集。
- **官方素材**：内置的红包、金币等素材须为原创或已获授权。用户自己选的图片由用户负责，应用不内置版权相关的内容。
- **首个官方模板**：红包雨，用于验证整条链路。节日模板（春节、生日、情人节）按同样方式增加，先验证红包雨的使用情况再决定是否扩充。

素材槽位验收：带槽位的特效在控制台出现素材区，其他特效不出现；添加、移除、恢复默认立即作用于预览和桌面并跨重启保留；原图被删除后特效照常显示；超限、损坏、SVG 和非图片文件被拒绝并提示；特效窗口仍不能调用文件读取或其他控制命令；粒子数较多时帧率与无素材时相比没有明显下降（以实测为准）。

验收：七种特效都能选中，参数变化可辨识并跨重启保留；换壁纸、系统桌面、视频或互动动画壁纸时特效不消失；选“无特效”后窗口关闭、无残留；游戏空间期间隐藏并在退出后恢复；桌面图标和现有桌宠操作正常；自己放进文件夹的特效包重新载入后可选，坏文件有明确提示且不影响其他；旧版保存在壁纸里的特效首次启动时迁移正确。

### 5.2 陪伴专注模式

入口位于“小伴设置”，提供专注时长和“开始专注”。首版默认 25 分钟，允许用户修改；时长范围为待实现时校准的产品参数。

- 状态包括未开始、进行中、已暂停、已完成。提供开始、暂停、继续、提前结束；提前结束不提示“完成”。
- 进行中，小伴进入戴耳机、看书等安静动作，减少随机主动活动；仍允许拖动和打开设置。用户原有大小、位置和壁纸保持有效。
- 计时信息可独立显示或隐藏，不占据屏幕中心。用户可选择柔和的专注氛围；不强制换壁纸。
- 暂停时冻结剩余时间并显示暂停状态。正常运行时关闭设置窗口不会停止计时；应用退出后不继续计时，重启不自动开启新任务。
- 系统锁屏或睡眠时自动暂停，回来后由用户继续，避免离开电脑也被计入专注。计时不依赖动画帧率；动画暂停不等于计时暂停。
- 完成时小伴伸懒腰，并显示一次可关闭的休息提示，不抢焦点、不自动开始下一轮。提醒音独立开关，默认关闭。
- 完成提示复用 5.8 的展示、声音与免打扰能力；同一时刻的休息提醒合并，避免专注结束和周期休息各弹一次。
- 进入游戏空间时自动暂停专注，退出后由用户继续；暂停期间不展示普通关怀提示。
- 开始前保存由专注临时改变的角色与氛围设置，完成或提前结束时恢复。用户在专注期间主动修改的设置以最新选择为准，避免结束时覆盖用户调整。

验收：暂停/继续的剩余时间正确；关闭控制台仍计时；锁屏、睡眠和唤醒行为符合规则；完成只提醒一次；结束恢复临时设置且保留用户主动修改；不影响桌面模式切换。

### 5.3 会变化的小伴房间

入口位于小伴房间设置，提供“跟随时间”和“固定时段”。首版只改变内置房间，不自动给用户照片或视频加色调。

- 基于系统本地时间划分晨间、白天、黄昏、夜晚；建议初值为 06:00–09:00、09:00–17:00、17:00–20:00、20:00–次日 06:00。
- 四个时段对应窗外天空、室内亮度和灯光变化，切换采用平滑过渡。小伴可以看窗外、开灯或进入夜间安静状态。
- 用户可以固定任一时段，固定模式下不被系统时间覆盖。跟随时间为用户主动开启的选项，不改变已有手动主题偏好。
- 启动、唤醒、时区或系统时间变化后重新计算当前时段，不依赖应用持续运行到切换点。
- 夜晚场景只影响氛围与可用的自主动作，不强制覆盖用户手动表情；专注动作优先于房间自主动作。
- 实时天气和季节变化列为后续扩展。首版无需定位、天气服务或网络访问。

验收：四时段可预览与固定；时间边界正确；唤醒后与本地时间一致；手动模式不被自动切换；专注期间动作不冲突。

### 5.4 桌宠玩具和小互动

- 保留现有点击反应，新增明确的“摸头”“投喂”“放球”入口，先通过设置面板或桌宠菜单选择，避免把同一个点击赋予多个含义。
- 摸头与投喂各提供可辨识的动作反馈；放球后小伴在限定区域内追球、碰球，结束后回到原位置与行为。
- 首版同时只存在一个球，用户可随时收起。动作连续触发采用限频或合并，避免无限排队。
- 拖动时提供角色表情反馈；拖动、手动表情和专注状态优先于自主玩耍。暂停动画时不执行玩具动作。
- 壁纸模式中的互动沿用当前桌面层命中判断，不覆盖桌面图标点击；玩具不向窗口外扩张输入区域。具体可操作区域需做两端原生验证。
- 首版不设置饥饿惩罚、照料负担、付费道具或每日任务；用户几天没打开，小伴也不会表现为被惩罚。

验收：三种互动反馈不同；球可出现与收起；连续操作不堆积动作；拖动、专注、暂停可中断玩耍；不阻碍桌面操作。

### 5.5 场景搭配与收藏

- 保存当前壁纸引用、适配参数、桌面特效选择、小伴显示模式/位置/大小、房间时段偏好；首版仅纳入当时已实现的配置项。
- 提供命名、预览、应用、重命名和删除。示例名称包括“雨夜工作”“清晨阅读”“周末放松”。
- 保存的是组合配置，不重复复制已导入媒体。删除组合不删除壁纸资源，组合也不包含正在进行的专注计时。
- 应用前校验所需资源。壁纸缺失时提示重新选择或下载，在资源就绪前保留当前桌面，不出现半套配置。
- 组合保存在本地，重启后仍可使用，无需登录。当前阶段不提供云同步或自动上传媒体。
- 环境音列为后续扩展：声音独立开关、独立音量，默认静音；开启前可试听，切换组合后停止上一组声音，避免叠加播放。

验收：保存后恢复的画面与参数一致；重命名和删除正确；缺失资源可恢复且不破坏当前桌面；离线应用完整组合成功。

### 5.6 音乐联动

- 用户主动开启后，小伴随节奏轻微点头，耳朵或房间灯光变化；提供响应强度与独立开关，避免默认强闪烁。
- 歌曲信息是单独的可选组件。拿不到歌名时只显示可用的动画，不显示伪造曲目；无音频时回到安静状态。
- 开启前说明响应的数据来源。若采用系统输出音频，可能同时响应视频、提示音和通话，不将其描述为仅识别音乐。
- Windows/macOS 分别确认系统输出音频和媒体信息的可用性、授权流程与资源开销。平台不支持时展示真实可用范围，不要求两端同时交付。
- 音频联动只需瞬时节奏/频谱数据，不保存或上传音频，不以麦克风采集替代系统播放数据。
- 专注模式默认暂停节奏动作，用户可单独允许音乐联动；手动互动、拖动和暂停仍优先。

验收：有音频时响应可见，无音频时恢复；开关关闭后停止采样与动画；信息不可用时正确降级；按平台实际权限流程测试。

### 5.7 桌面游戏空间

目标流程：**双击桌面空白处 → 唤起沉浸游戏面板 → 选择游戏 → 游玩/返回面板 → 退出并恢复桌面。**

- 入口只响应真实桌面空白处的双击，不响应图标、小伴、普通应用窗口或已打开游戏内的双击。提供入口开关，同时保留托盘/菜单栏和设置面板中的“玩一玩”入口。
- 沉浸态在主显示器上视觉覆盖桌面图标、桌宠和其他桌面叠加内容，展示干净的游戏面板与背景。不移动或删除桌面文件、不永久修改系统图标显示偏好、不强制最小化其他应用。
- 游戏面板展示游戏名称、封面和启动状态。目标接入现有七款：俄罗斯方块、2048、消失高手、奶茶大师、小伴贪吃蛇、水墨剑客、暮色滑翔。
- 首轮适配用 2048、奶茶大师、水墨剑客验证普通游戏、关卡游戏、横屏和存档，再逐款接入其余游戏；接入目录只展示已验证的内容，不放无法打开的占位卡片。
- 内容来自 [网页游戏包](../../client/xiaban-web/src/games/README.md)。沿用 catalog、manifest 与版本 1 的宿主消息协议；桌面端维护自己的宿主与适配代码，复用发布游戏资源，不直接导入网站 React 页面或私有业务源码。
- 游戏在独立低权限沙箱中运行，宿主验证消息来源、游戏标识和握手 nonce。游戏无法直接调用桌面设置、文件选择器、退出程序等原生命令。
- 支持游戏准备、加载成功、失败重试、返回面板与退出空间。失败时始终保留退出入口，不让用户卡在沉浸态。
- 游戏空间当前是“内置离线游戏库”，不是商店：游戏数量固定为七款，没有下载、更新、评分，也没有第三方接入。同类壁纸与桌面软件里内置游戏的很少，这是差异点，但“用户会不会因为壁纸软件而玩游戏”尚未验证，不能把它当作已证实的需求。是否扩充为官方精选的游戏入口，要以第 8 节的使用观察为依据。
- 首版游戏资源使用可离线访问的本地发布副本，随客户端构建检查目录及共同依赖；资源缺失不影响壁纸和桌宠启动。不在首版引入可任意执行的第三方游戏包市场。
- 支持存档的游戏由桌面宿主读写本地存档，加载完成后再启动；保存失败要告知用户，不以空存档覆盖已有进度。游戏无权直接访问账户或存储。
- 网站账户、排行榜、挑战链接和分享海报不作为首版依赖。现有游戏结算保留结果与重玩动作，网页专属分享入口需适配后隐藏或替换，不能保留失效按钮。
- 游戏内有可见的返回入口；Esc 返回游戏面板，面板中 Esc 退出空间。宿主需保证游戏拿到键盘焦点后仍能接收返回请求，并验证游戏内部暂停等 Esc 行为，避免冲突。退出小伴也会关闭游戏空间。
- 退出、加载失败取消、窗口关闭和应用异常重启后，都恢复此前桌宠/壁纸配置；游戏不会覆盖已应用的长期配置。沉浸态临时停用背景特效、桌宠渲染和音乐响应，退出后恢复，避免重复消耗资源。
- 当前宿主的桌面空白双击仅尝试在 Windows 使用低级鼠标事件与 Explorer 桌面列表命中判断，入口默认关闭；macOS 暂不支持可靠判断，两端都保留显式入口。Windows 的图标双击、窗口层级、焦点、系统切换应用与恢复仍需实机验证。不得把实现存在等同为行为已通过验收。

验收：图标双击与普通应用操作不被误触发；七款游戏逐款完成启动、输入、结算、退出检查；存档游戏重启可续玩；离线启动可用；Esc 与可见返回入口可用；切换应用、失败与退出均不遗留覆盖窗口或损坏桌面状态；进入期间普通关怀提醒不打断游戏。

### 5.8 小伴关怀与自定义提醒

入口位于“小伴设置”的“关怀提醒”，用户选择类型、时间/条件、重复规则、文案与开关。调度和展示相互独立，关闭控制台仍可触发，应用完全退出后不承诺系统后台提醒。

| 类型 | 触发规则 | 文案示例 |
| --- | --- | --- |
| 下班 | 用户设定的下班时间与星期，不假定所有人周一至周五工作 | “到点啦，今天也辛苦了。” |
| 休息 | 用户设定的电脑使用时长，或专注完成；明显空闲、锁屏、睡眠时间不累计为使用时长 | “起来走走，看看远处吧。” |
| 天气 | 首版在用户指定时间检查天气；按降雨等条件触发列为后续扩展 | “今天可能有雨，出门记得带伞。” |
| 自定义 | 一次、每天或指定星期重复；用户填写自己的文案 | “下午三点，记得喝水。” |

- 当前代码提供下班、休息、自定义和天气规则；调度及气泡在原生宿主运行，系统通知尚不可用。各规则独立启停，支持创建、编辑、删除与立即预览；仅预览不生成真实到期任务。
- 天气城市由用户手动选择，不默认获取定位。默认来源关闭；用户选择 Open-Meteo 或配置自定义 HTTPS API 并联网后，按需查询当前温度/天气和当天降水概率。显示来源与更新时间；失败或超过有效期不生成天气提醒。下班、自定义与休息规则本地运行，休息累计要求平台能读取活跃时间。
- 首版天气以指定时间的天气提示为主；降雨、温差等条件提醒作为同模块后续扩展，需明确数据依据、阈值与冷却时间，避免反复推送相同天气。
- 提示默认显示在小伴旁的气泡，配合已有合适表情。提供关闭和稍后提醒；声音单独开关，默认关闭。气泡不抢键盘焦点，不挡住角色拖动，屏幕边缘自动调整位置。
- 用户关闭小伴显示时，默认不弹出关怀气泡；用户可主动选择系统通知作为替代渠道，通知不可用时在设置中显示真实状态。
- 提供免打扰时段与总开关。游戏沉浸态、专注进行中和专注暂停状态延后普通提醒；专注完成提示不被专注自身屏蔽，但仍遵守免打扰。
- 同一规则的同一次到期只展示一次；展示队列合并同类休息提醒。建议初值：气泡展示 10 秒、稍后提醒 10 分钟、到期后 30 分钟内有效；可在试用后校准。
- 免打扰或沉浸态结束后，仅展示仍在有效期内的提醒摘要，不逐条补弹。应用重启或系统唤醒只处理有效期内的遗漏，不重放几天前的提醒。
- 定时规则按系统本地时间执行。时间/时区变化后重算下一次触发；用规则和计划到期标识去重，避免时间回拨造成重复弹出。休息间隔使用实际有效时长计算。
- 配置、稍后提醒和去重状态保存在本地。关闭、编辑或删除规则时同步取消对应待展示任务；不通过本功能向外发送消息或上传用户自定义文案。
- 后续可将已取得的天气映射到房间雨雪表现；该联动独立开关，不作为首版提醒或房间昼夜功能的依赖。

验收：一次/每天/指定星期规则正确；关闭控制台仍触发；离线定时可用；同一次到期不重复；稍后提醒、编辑和删除生效；免打扰、游戏、专注、锁屏与睡眠的延后/过期处理正确；天气失败和过期不产生误导文案；气泡可关闭且不抢焦点。

### 5.9 桌面生活小组件与自包含动态卡片（已实现）

入口位于控制台“桌面组件”页（组件库、我的桌面、互动场景三大标签）。小组件是摆在桌面上的生活小物件：支持自由添加、随手拖拽摆放、调整大小与外观风格，最多支持在桌面上放置 12 个组件。

- **五种内置官方组件**：
  1. **一签好意（求签）**：摇动签筒求取今日祝福，支持展开好签册收藏。
  2. **日有所序（时钟日历）**：高精度时钟、月历视图、农历节气与国务院官方收录的年度法定放假/调休上班标记。
  3. **晴雨之间（天气时钟）**：支持搜索并关注全球任意城市，展示实时天气、温度与关怀文案，半小时自动静默更新。
  4. **心事有处（便签待办）**：纯文本灵感便签与勾选式待办清单，即写即存。
  5. **好日将至（倒数纪念日）**：正数天数（已过去）或倒数天数（期待中），支持每年自动重复。
- **外观与桌面交互**：
  - 每一个桌面组件均为一个独立、无边框、无任务栏图标的原生 Webview 透明窗口（macOS 处于桌面层，Windows 挂载为桌面子窗口）。
  - 支持 **透光玻璃（glass）**、**温润纸张（paper）** 与 **透明无底（transparent）** 三种风格。
  - 支持 **0.75 到 1.5 倍等比缩放**；按住组件任意空白区域即可在多显示器之间随手拖拽摆放，松手自动原子保存坐标，多屏热插拔与分辨率切换自适应重算。
- **自包含 HTML 动态卡片与沙箱隔离**：
  - 突破硬编码限制，支持扩展自定义小组件（`kind: "custom"`），模板保存在 `~/.xiaobanwallpaper/custom_widgets/<id>.json`。
  - 渲染采用严格沙箱 `<iframe sandbox="allow-scripts" class="custom-widget-frame" />`，允许内部运行自主 Canvas 绘图、SVG 动画、事件监听与业务逻辑（番茄钟、极简时钟、每日诗词、健康打卡等），同时切断宿主 Tauri IPC，保证绝对安全。
- **小伴 Agent 现场创作（`widget_create`）**：
  - 小伴作为桌面 Agent，具备 `widget_create` 工具，用户在聊天里描述需求，小伴即刻编写单文件 HTML 代码落盘并默认直接贴上桌面，无需重启。

验收：五种内置组件添加、删除、拖拽、缩放、主题切换正确；位置与便签/倒数日数据重启后完整恢复；多显示器拖拽自适应；自定义组件沙箱运行且无特权泄露；Agent 调用 `widget_create` 能稳定生成并在桌面呈现。

### 5.10 小伴的联动与成长（A、B 已实现，待实机验证；C 到 F 为规划）

实现状态：A（回应特效）和 B（感知本机状态）已在 macOS 开发版实现并通过自动化测试（前端 131 tests、Rust 86 tests、类型检查），总开关是桌面小伴页的“小伴联动”，默认开启。尚未做的验证：表情与符号在小伴上的实际观感（尤其下雨、繁星用到的符号）、两平台完整事件链路、锁屏与睡眠恢复、Windows。B 的实际数值：离开 10 分钟后回来才算“回来”，每天最多 3 次且间隔 30 分钟；每天第一次问候只发一次；深夜指 0 点到 5 点累计活跃 20 分钟，每晚一次。

小伴是本产品的互动壁纸：它在壁纸之上，能看鼠标、被点击会反应、有情绪和睡眠。下一步不是再造一种独立的互动壁纸，而是让小伴回应桌面上正在发生的事，让特效、天气、游戏和用户状态不再各自独立。以下按推进顺序分类，A、B 两类对应优先级表的 3b，其余只作规划，是否推进取决于试用反馈。所有联动都是官方设计的动作和文案，不开放用户编辑。

通用约束：

- 联动默认随对应功能而开：用户没开特效就没有特效联动；总开关关闭“小伴联动”后，小伴只保留现有的基础动作。具体默认值在立项时定，原则是不在用户没选择过的情况下增加新的打扰。
- 联动只改变小伴的动作和表情，不弹窗、不发声、不抢焦点；与关怀气泡、专注、游戏空间同时出现时，按第 6 节的行为冲突优先级处理，联动动作让位。
- 用到的数据只来自本机已有的信息（当前选择的特效、已取得的天气、系统时间与活跃/空闲状态），不新增联网，不记录用户行为内容。
- 动作要有冷却和随机间隔，避免同一个动作反复出现；新增动作沿用现有表情与动画，不要求为每一项都新做素材。

**A. 小伴回应特效（成本最低，优先）**

| 特效 | 小伴的反应（示例） |
| --- | --- |
| 下雨 | 撑伞或缩起来，雨停（切换特效）后抖一抖 |
| 下雪 | 伸手接雪，或缩一缩肩膀 |
| 枫叶、花瓣 | 偶尔抬头看飘过的叶子或花瓣 |
| 流星 | 看向流星划过的方向；点击小伴可以“许愿”，有一个简短反馈 |
| 繁星 | 夜间仰头看星空，偶尔打哈欠 |
| 萤火虫 | 眼睛跟着光点转 |

- 小伴窗口读取当前选中的特效，不需要新权限；特效窗口不向小伴传递控制权。切换或关闭特效时，联动动作自然结束。
- 验收：每种特效都有至少一个可辨识的联动动作；切换、关闭特效后动作停止；动作之间有冷却，不出现连续重复；与专注、游戏空间同时存在时联动让位；联动开关关闭后只保留基础动作。

**B. 小伴感知本机状态（轻提示，复用关怀提醒的数据）**

- 用户离开一段时间后回来，小伴打招呼；每天第一次出现时问候；深夜仍在使用时偶尔提示早点休息。
- 复用关怀提醒已有的空闲、锁屏、活跃时间读取，不新增采集，也不读取用户正在做什么。
- 约束：每类提示每天有次数上限，遵守免打扰与专注；文案保持轻松，不评判、不催促，也不暗示在监视用户。
- 验收：离开再回来、首次出现、深夜三种情形分别触发且不重复；免打扰、专注、游戏空间期间不触发；锁屏、睡眠后的恢复不补发过期的问候。

**C. 节日与季节形象（官方出内容，与素材槽位配合）**

- 春节、生日、情人节、节气等换上对应的造型或小物件，可与红包雨等节日特效模板配合。
- 前提是内容产能：先确定每月能出几套造型再立项，没有产能时不承诺节日清单。造型素材须为原创或已获授权。
- 自动按日期切换时要有手动关闭或固定的选项，避免用户不想要时被替换。

**D. 小伴与游戏空间联动**

- 玩游戏时小伴在角落反应，结算时庆祝或安慰；通关可以解锁造型。
- 这让内置游戏和陪伴连成一体，也能作为观察游戏空间是否有持续需求的入口。联动不改变游戏本身的规则，也不向游戏开放任何桌面权限。

**E. 轻度养成（待用户反馈后再决定）**

- 连续陪伴天数、好感度，解锁新表情、小物件或房间装饰，给“明天再来”一个理由。
- 设计红线：不设惩罚（不来不会变差、不会“生病”），不逼每日打卡，不引入付费加速。好感度只增加不减少。
- 风险：做得重会变成负担，也容易偏离“安静陪伴”的原则，所以放在最后，视留存数据再决定。

**F. 小伴与天气联动**

- 已取得的天气映射到小伴的动作（下雨带伞、高温擦汗等）。天气默认关闭，联动随天气功能一起开关，不为联动单独联网。已在 5.8 记为后续扩展，这里只记录方向。

**G. 小伴外壳换肤（官方外壳，不开放编辑；三款原型已实现，待实机验证）**

实现状态：猫耳、兔耳、盆栽三款已做成原型（熊耳、机器人天线款试做后去掉；盆栽款是白瓷花盆，表情屏嵌在盆身正中，盆口露出泥土，一根茎长出两片叶子，叶子承担耳朵的情绪表达），在“桌面小伴”页的“外壳”里选择，立即生效并保存。外壳只含耳朵形状和配色，屏幕与部件标记不变。自动化测试覆盖三款外壳的全部表情渲染与部件一致性；桌面实机观感，以及兔耳、盆栽下各表情的耳朵动作是否清晰，尚未逐项验证。

小伴的核心是屏幕里的发光表情，外壳（头壳配色、耳朵、侧舱）可以更换。换肤只改外形和配色，表情系统、动作和联动不变。

- **范围**：官方提供的几款外壳，用户在“桌面小伴”页选择，立即生效并保存。首批原型：原来的猫耳和兔耳（长耳，整体缩小一点给耳朵留空间）；熊耳试做后去掉；配色可作为同一外壳的变体。不提供形状编辑器，不接受用户自制外壳，不做分享。
- **耳朵是表情通道**：现有表情用耳朵角度和耳灯传达情绪（兴奋竖起、难过耷拉）。新外壳必须保留耳朵转轴和耳灯，并保证各表情下耳朵可读；不带耳朵的外壳需要用天线或头顶灯补上这条通道，否则不收。
- **统一的外壳约定**：每款外壳使用同一块屏幕区域、同一个符号锚点和同一套部件标记（点击判定与拖动依赖这些标记），外壳之间只差耳朵形状、配色和少量装饰。
- **窗口尺寸**：外壳的整体外轮廓不超出现有视图范围，不因换肤改变小伴窗口的大小和位置。
- **与节日形象的关系**：节日造型是在某款外壳上叠加的装饰或配色（围巾、帽子），不单独做外壳。
- **成本**：主要是美术产能，每款外壳要与现有的一样精致。立项前先确定每月能出几款，没有产能时只保留三款。
- 验收：每款外壳下 25 种表情都能辨认，耳朵动作与耳灯可见；点击、拖动、命中判定与原外壳一致；切换后小伴窗口大小不变；设置跨重启保留；联动动作在每款外壳下正常。

### 5.11 “一核多态”自包含 Web 动态壁纸与桌面轻游戏生态（已实现）

为解决桌面场景下“整屏游戏干扰办公、局部挂件缺乏沉浸感”的体验矛盾，小伴桌面确立了**“自包含 Web 一核多态”**架构规范，打通了小组件、动态壁纸与游戏空间的技术底座：

- **场景取向：双模陪伴与游玩体验**：
  - **日常陪伴态（桌面局部小游戏挂件）**：以小组件（Widget）形式安静常驻桌面一隅（如电子盆栽、放置挂机、打坐修炼、赛博鱼塘、迷你打卡），工作时占一小角，零干扰、低功耗。
  - **沉浸游玩态（全屏专注 / 动态交互壁纸）**：当用户需要深度放松时，支持一键放大展开进入游戏空间或切换为全屏互动桌面。
- **技术底座彻底统一（一核多态）**：
  统一采用标准自包含 Web 规范（单文件 HTML + CSS + JS），支持 Canvas 2D、WebGL、Three.js、CSS 动效、独立事件循环与音频播放。同一次编写的 Web 体验，可无缝流转于三种宿主容器：
  1. **小组件容器（Widget）**：微型独立窗口挂件，支持鼠标点击交互与拖拽摆放。
  2. **动态壁纸容器（Wallpaper）**：新增 `kind: "web"` 类型，通过原生 `wallpaper-asset:` 协议高速加载，铺满桌面全屏底层，享受 SHA-256 本地寻址、离线可用与统一壁纸库管理。
  3. **游戏空间容器（Game Space）**：全屏独立沉浸游戏大厅，享受专属的全屏聚焦、ESC 快捷返回与本地存档隔离。
- **小伴 Agent 现场创作工具矩阵**：
  小伴作为桌面助手，内置三大原生生成工具，允许在聊天中直接将创意落地到真实桌面：
  - `widget_create`：编写并落盘单文件 HTML 自定义桌面组件，默认直接贴上桌面；
  - `wallpaper_create`：编写并落盘自包含 HTML 全屏动态/交互壁纸，默认立即换上；
  - `effect_create`：编写并落盘符合引擎规范的桌面粒子特效包 JSON。

验收：动态壁纸 `kind: "web"` 正确通过 SHA-256 校验并展示；沙箱 iframe 加载完成后上报 `scene_ready` 并平滑切换；同一套单文件 HTML 代码既能作为小组件正常运行，也能作为全屏壁纸铺开；Agent 调用 `wallpaper_create` 与 `widget_create` 能稳定完成创作并即时生效。

## 6. 界面与交互规则

控制台采用清爽的白色与浅灰布局，红色为主色，支持浅色、深色和跟随系统。侧栏分为聊天、壁纸库、桌面组件、桌面特效、桌面小伴、游戏空间、关怀提醒等主分区，设置入口固定在侧栏底部：

- 聊天：内置桌面小伴通用 Agent，支持使用本地工具操作电脑工作目录，以及调用 `widget_create`、`wallpaper_create`、`effect_create` 现场创作并控制小伴桌面。
- 壁纸库：浏览在线与本地内容，在页面内预览；执行“应用到桌面”改变当前桌面。
- 桌面组件：五种官方组件添加与拖拽摆放、管理 Agent 创作的自定义组件，支持多显示器切换与布局微调。
- 桌面特效：选择雨、雪、萤火虫等场景叠加在整个桌面上，与具体壁纸无关；选择立即生效。
- 桌面小伴：角色外观（猫耳、兔耳、盆栽等外壳）、可见状态、表情与小伴联动设置。
- 游戏空间：展示本地游戏资料，使用显式入口进入独立游戏大厅；Windows 桌面双击快捷入口在此单独配置。
- 关怀提醒：编辑提醒规则并通过明确的保存动作提交。
- 设置：管理应用偏好、AI 模型服务接口、版本公告和数据目录入口。

游戏面板为独立沉浸空间，不挤入壁纸预览。桌面双击与托盘/设置入口唤起同一个空间，不重复创建游戏窗口。

开关类即时偏好操作后立即生效，并反馈结果；提醒内容需明确保存。预览调整不直接应用到桌面，用户通过“应用到桌面”确认视觉配置；专注和互动使用独立的开始/执行按钮。壁纸、特效、小伴、计时信息、歌曲信息、声音各自可关闭，不要求整套启用。

行为冲突优先级：动画暂停 > 用户拖动/直接互动 > 专注动作 > 玩具自主动作 > 音乐动作 > 房间自主动作与普通空闲动作。直接互动结束后恢复当前有效状态；专注期间默认不启动自主玩耍。暂停只停止动画，专注计时按 5.2 独立管理。

沉浸态临时隐藏桌宠和关怀气泡，不改变其长期配置；普通提醒按 5.8 延后。游戏音频由游戏空间独立控制，不让音乐联动再次响应游戏自身音效。

## 7. 性能、存储与实现边界

- 桌面特效和新增角色行为优先延续现有 TypeScript、SVG、CSS、Canvas 能力。音频采样、系统状态和桌面输入通过本客户端的原生宿主接入。
- 桌面特效由可信宿主管理，特效页面不能调用桌面控制命令（验证里会检查）；也不向订阅 Canvas 沙箱开放设置、音频采样、自启动等权限。既有低权限壁纸与预览边界继续有效。
- 游戏使用单独的低权限宿主与资源目录，复用游戏包协议但不授予控制台能力；本地存档与规则配置由可信宿主管理。游戏动画与音频不套用桌宠动画暂停开关。
- 提醒调度独立于 WebView 动画和控制台可见性，按系统时间及有效使用时长触发；无需用户登录。若天气数据源要求服务端密钥，密钥和服务端代理策略归后端，不写入游戏包、前端或桌面发布资源。
- 本地配置沿用用户数据目录规则；新增字段兼容旧配置，缺失或无效值回退安全默认值。媒体副本、缓存与场景配置保持各自职责，详见 [用户数据说明](../../client/xiaoban-desktop-wallpaper/docs/user-data.md)。
- 持续动画共享现有 30/60 FPS 和暂停设置；关闭功能时停止对应循环、监听和资源占用。预览关闭后同样释放资源。
- 新增全屏应用、锁屏和电池状态下的动画降频/暂停策略，具体策略可配置；状态恢复后继续显示，不自动重启已结束的专注任务。
- 性能验收需记录设备、系统、分辨率、缩放和帧率，对比无特效/有特效的 CPU、GPU、内存及帧耗时。发布前据实测确定性能阈值，不把未测试的低占用写为承诺。
- 不引用其他客户端私有源码；游戏复用采用发布资源及协议边界。服务端继续负责已有交付业务，本地游戏、提醒规则和特效不依赖新增后端；天气查询由桌面端提供，默认关闭，天气驱动场景属于后续扩展。

| 第八阶段 / 排名 8 | 音乐联动 | 平台能力、权限、音频生命周期、游戏/专注冲突与性能 |
| 第九阶段 / 排名 9（本轮已实现） | 桌面小组件与自包含动态卡片（五款内置组件、自定义 HTML 动态小组件、自包含 Web 壁纸、Agent 创作工具矩阵 `widget_create` / `wallpaper_create`） | 多窗口层级与跨屏拖拽、沙箱 iframe 安全隔离、动态加载与离线运行 |

阶段可分别发布。环境音、更多桌面特效、天气驱动场景与季节变化作为对应模块后续扩展，不抢占上述主线。组件商店只作预留，何时立项取决于天气来源、特效层和桌面窗口管理是否稳定。

开发验证使用子项目 README 的构建、测试与原生 smoke 命令。按新增行为补充有意义的测试：游戏消息校验与存档、提醒调度与去重、计时与时段计算、配置恢复、场景资源校验、动作优先级。Windows 实机检查桌面空白双击与图标操作，macOS 检查设置/菜单栏显式入口；两端均需检查游戏输入与退出、关怀气泡、角色反馈、预览和桌面画面。窗口属性检查不能代替视觉验收。

**风险与待验证**（来自产品取向的自查，不是已发生的问题）：

- **官方内容产能**：不做用户创作，内容全靠自己生产。立项互动壁纸和节日模板前，要先定每月能出多少、谁来做，否则内容会很快见底。
- **互动壁纸不是空白领域**：成熟产品在这块积累很深，只说“有互动壁纸”没有优势。差异必须落在与小伴、关怀、游戏的联动，以及统一美术、低功耗和安全上，并用试用反馈检验。
- **游戏空间的需求**：用户是否会因为壁纸软件而玩游戏尚不清楚。先看本地使用观察（打开次数、单次时长、重复使用，由用户自愿反馈或本地诊断得出），再决定是否扩充为官方精选入口。
- **平台与场景**：多显示器、全屏应用时的暂停、长时间运行的功耗，都还没有验证记录；Windows 上的实测结论需要补进桌面工程的 [feature-validation.md](../../client/xiaoban-desktop-wallpaper/docs/feature-validation.md)，再回写本文的状态说明。
- **版权与合规**：壁纸来源（含第三方图库）、内置素材和图标字体的授权都要在上架前确认；图标里“小伴”的轮廓取自系统字体，需换成可商用字体。
- **竞品信息**：本次取向调整参考了对同类产品的印象，没有联网核实，不写入本文作为事实。需要竞品对比时，先核实再标注日期。

首批试用重点关注：用户能否顺利进入和退出游戏、是否愿意再次使用、是否愿意开启并持续保留关怀提醒、提醒是否打扰、特效是否愿意长期使用，以及长时间运行是否出现明显性能问题。验证结果用于调整排序，不能以本表的判断替代用户反馈。默认通过人工试用反馈和本地诊断评估，不因本 PRD 自动增加遥测或收集用户媒体。
