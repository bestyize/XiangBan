# 语音编程：目标与实施计划

状态：讨论稿（2026-10-28）。把路线图 [2b](../../client/xiaoban-desktop-wallpaper/docs/assistant-roadmap.md)（小伴驱动外部编程 Agent）和手机端的分期合成一份可执行的目标与计划。接口层面的细节（Claude Code、Codex、各桌面版的快捷键与会话文件）都标了“待核实”，第一阶段先核实再动手，不凭记忆开工。

## 1. 一句话目标

**让用户开口就能指挥 Claude Code、Codex 和桌面版 AI 应用干活，并且不改变他们原来的用法。** 小伴是外挂的语音助手：说话的地方可以是电脑或手机，干活的是用户自己装的 Claude / Codex，工程和对话两边通用。

### 1.1 要做到的四件事

| 编号 | 目标 | 用户感受 |
| --- | --- | --- |
| G1 | **一键装好**：检测并代装、代配 Claude Code、Codex、Node、git 等，登录引导到位 | “不用查教程，几分钟能用起来” |
| G2 | **随口指挥**：对悬浮条说话，文字出现在 Claude / ChatGPT 桌面版的对话页，确认后发送；或直接交给命令行 Agent 去做 | “说一句就送进去了，不用切窗口打字” |
| G3 | **双向接续**：小伴开的会话回终端能接着用，终端里的会话小伴也能接；任务做完、等批准时小伴主动开口播报 | “它在后台干活，做完会告诉我” |
| G4 | **不在电脑前也能管**：手机上同样能说、能看进度、能批权限 | “出门也能让它继续” |

### 1.2 不做什么

- 不重新实现 Claude Code / Codex，不替代它们的界面。
- **不读取、不转存、不借用它们的登录令牌**，不拿用户的订阅额度给第三方界面提供服务，不重新分发它们的程序。
- 不用屏幕截图加模型的方式操作别的应用（太慢，且不确定）。
- 首版不读回桌面版应用里的回复，不托管用户已在终端里运行的进程。
- 手机端首版不在本地跑 Agent（见路线图“手机端的分期”）。

### 1.3 成功指标（上线后看）

| 指标 | 目标 |
| --- | --- |
| 首次使用到说出第一句话 | 新用户 ≤ 5 分钟（含安装检测） |
| 悬浮条说话到文字出现在目标应用 | ≤ 1.5 秒（不含语音识别） |
| 委派任务完成后用户收到播报 | ≥ 95% |
| 语音误操作 | 未经确认发出的指令为 0（委派和发送都要确认） |
| 一周留存 | 以首批 100 位用户为样本，≥ 40%（先定基线，再调） |

## 2. 总体结构

```
用户（电脑悬浮条 / 手机；文字、语音、伪实时对话）
                │
        小伴（对话 · 记忆 · 调度 · 语音确认 · 主动播报）
    ┌─────┬─────┴──────┬──────────┐
 自己做  界面层        命令行层       环境层
        把话送进桌面版   观察 → 接续 → 托管   检测·代装·配置
        Claude/ChatGPT   Claude Code / Codex
                │
          中转服务（手机用，端到端加密）
```

融合的四层，由浅到深，每层单独可用：

| 层 | 作用 | 对象 | 控制力 |
| --- | --- | --- | --- |
| 观察 | hooks / notify 回调 + 读会话记录，播报进度与权限请求 | 用户在任何地方开的命令行会话 | 只读 |
| 接续 | 会话空闲时用官方程序的无界面模式按编号恢复，写回同一份记录 | 命令行会话 | 轮次级 |
| 托管 | 经小伴启动，进程由小伴持有 | 命令行会话 | 实时 |
| 界面 | 系统接口（非图像识别）把文字送进桌面版对话页 | Claude / ChatGPT / Codex 桌面版 | 只发不读 |

另有两处不依赖会话文件：本机 **MCP 语音工具**（Agent 中途能开口问用户）、**环境层**（检测与代装配置）。

## 3. 阶段计划

团队按 2–3 人加 AI 估算，周数是工作量的大致范围，不是承诺。P1、P2 可并行。

### P0 核实与技术验证（1–2 周）

进度（2026-10-28）：文档与程序层面的核实已完成，结论见 [外部Agent接口核实_P0](../agent/外部Agent接口核实_P0.md)；需要登录和真机的部分（真实对话样例、Windows 行为、桌面版快捷键与无障碍、三项技术验证）待在你的电脑上做。

目的：把“待核实”都变成已核实，避免后面返工。

| 任务 | 产出 |
| --- | --- |
| Claude Code：hooks 事件与参数、会话记录位置与格式、无界面模式的输入输出与恢复、权限提示机制 | 一页接口摘要，附实测命令与版本号 |
| Codex：notify 回调、会话记录、非交互模式与恢复、服务模式、是否有 ACP 适配器 | 同上 |
| Claude 桌面版、ChatGPT 桌面版：是否有全局快捷键与快速输入、能否用 UI Automation / Accessibility 找到输入框、粘贴并回车的实测 | 每个应用在 Windows、macOS 上的可行性表 |
| 技术验证（各做最小可跑版）：① 装 hooks 后任务结束触发本机回调；② 无界面恢复一个会话并在终端 `resume` 接上；③ 悬浮条文字送进一个桌面版输入框 | 三段录屏与结论：能做 / 有条件 / 不能 |

**退出条件**：三个验证至少两个成功；失败的那个有替代方案或明确放弃。

### P1 环境层 + 观察层（2–3 周）

| 任务 | 说明 |
| --- | --- |
| 环境检测页 | 检测 Node、git、Claude Code、Codex 及版本，列出缺失与可升级 |
| 代装与配置 | 展示官方安装命令，用户确认后执行并显示进度；登录由用户在浏览器完成；可配代理、镜像源、兼容接口地址；失败给出可复制的错误信息 |
| 观察层 | 一键为 Claude Code 装 hooks、为 Codex 配 notify（可撤销，改动前备份用户原配置）；本机收事件；会话列表读取会话记录 |
| 播报 | 任务结束、等待权限、需要输入时通知；先文字，语音朗读一句摘要在 P4 |

**退出条件**：一台干净的 Windows 和一台干净的 macOS 上，从零到“终端里的 Claude Code 做完事小伴提醒我”，全程不看教程。

### P2 界面层（2 周，可与 P1 并行）

| 任务 | 说明 |
| --- | --- |
| 目标应用适配 | 先 Claude 桌面版、ChatGPT 桌面版；每个应用按“自带快捷键 → 无障碍定位输入框 → 激活窗口直接粘贴”三级尝试 |
| 悬浮条流程 | 说话 → 识别 → 文字显示在悬浮条 → 用户说“发送”或点一下 → 回车；前台窗口不对就只提示 |
| 剪贴板保护 | 粘贴前后保存、恢复 |
| 回归脚本 | 每个适配应用一组冒烟脚本，对方改版后能很快发现失效 |

**退出条件**：两个应用在两个平台上各连续 20 次成功，平均耗时 ≤ 1.5 秒；失败时都有明确提示。

### P3 接续层 + 小伴委派工具（3 周）

| 任务 | 说明 |
| --- | --- |
| 外部 Agent 适配层 | 一个统一接口（会话列表、开始一轮、追加引导、打断、权限请求与回答、事件流）。**Codex 走 `codex app-server`（JSON-RPC），Claude Code 走 hooks + stream-json**；P0 核实后不再考虑解析内部会话文件，ACP 作为备选 |
| 会话共用 | 列出本机会话（含用户自己开的），选一个继续；与终端同时占用时告知，不强写 |
| 小伴内核的委派工具 | `agent_delegate`、`agent_status`、`agent_reply`、`agent_approve`、`agent_cancel`；首次对目录委派要确认并记住；权限模式发起时选定，默认最严格 |
| 文字对话跑通 | 在小伴里打字：“用 Claude Code 把这个测试修好”，复述确认，开始，随时问进度，结束后主动汇报 |

**退出条件**：委派后回到终端 `resume` 能看到完整记录并接着聊；反过来亦然；权限请求能在小伴里批准。

### P4 语音（2–3 周）

| 任务 | 说明 |
| --- | --- |
| 语音委派 | 复用现有识别与对话流程；语音触发的委派先复述任务和目录再确认 |
| 语音播报 | 完成、等批准时朗读一句摘要；可关闭、可设免打扰 |
| 权限的口头确认 | 低风险可口头批准；删除、推送、联网安装、写工作目录之外**只能屏幕确认** |
| MCP 语音工具 | 本机 MCP 服务装进 Claude Code / Codex：向用户语音提问、朗读、发通知 |
| 误识别 | 沿用现有识别方案；靠复述确认兜底；技术词汇纠错表等有真实反馈后再做 |

**退出条件**：不碰键盘完成“说任务 → 确认 → 做完被通知 → 口头批准一次低风险权限”。

### P5 小伴内的“语音编程”入口与发布（2 周）

出圈所需的包装，工程量小但决定首印象。

| 任务 | 说明 |
| --- | --- |
| 语音编程入口 | 在小伴里作为一个独立入口/模式：托盘常驻、全局热键说话、一个小窗显示会话；进入这个模式时不展示壁纸与社区；复用 P1–P4 |
| 首次引导 | 安装小伴后从“语音编程”进入，三步：检测环境 → 登录 Agent → 说第一句话；不要求先配置壁纸、模型之外的内容 |
| 演示与落地页 | 30 秒演示视频、官网页、安装包；中文优先 |
| 反馈渠道 | 论坛里设专栏；匿名埋点（已有）加首次使用漏斗 |

**退出条件**：陌生用户按引导 5 分钟内说出第一句话（找 5–10 人实测，Windows 与 macOS 都要有）。

### P6 手机（4–6 周，可与 P3 之后并行）

| 任务 | 说明 |
| --- | --- |
| 中转协议 | 扫码配对，**端到端加密**（密钥在电脑与手机之间协商，中转只转发密文）；断线重连不丢消息；只认本人账号 |
| 小伴 AI 纯聊天页 | 云端模型流式对话；额度提示；电脑离线时明说不能委派 |
| 遥控电脑 | 会话列表（含外部 Agent 会话）、发消息、看进度 |
| 审批推送 | 厂商通道接入；高危操作二次确认 |

**退出条件**：出门用手机说一句话，电脑上的 Claude Code 开始干活，做完推送回来，批准一次权限。

### P7 托管层与手机内核（另排）

托管层（经小伴或薄垫片启动，完全可控）、手机上的轻量 Agent 内核、手机创作内容包。见路线图“手机端的分期”，P0–P6 验证有人用之后再投入。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 上游改接口（hooks、会话记录、无界面模式、桌面版界面） | 功能失效 | 适配层隔离；每个应用/版本有冒烟脚本；检测到未知版本时降级并提示 |
| 违反上游条款（令牌、额度、分发） | 被封号或下架 | 红线写进设计：只拉起用户本机官方程序，不碰令牌；上线前再读一遍各自最新条款 |
| 语音误识别导致误操作 | 删文件、发错指令 | 委派与发送都先确认；高危只允许屏幕确认；默认最严格权限 |
| 桌面版无障碍树不可用 | 界面层定位失败 | 三级退路（快捷键、无障碍、直接粘贴）；个别应用只支持第一级 |
| 系统权限（macOS 无障碍、Windows 管理员窗口） | 无法输入 | 首次引导里逐项申请并给出说明；管理员窗口明确提示 |
| 同类产品抢先（手机遥控类、语音听写类、Claude Code 自带语音输入；**官方已提供远程控制**：Claude Code 的 Remote Control、Codex 的 remote-control；Codex 协议里已有实时语音） | 缺少差异 | 差异点：中文、对话式而非听写、主动播报、口头确认、一键装好环境、**支持 API 密钥与第三方接口的用户（官方 Remote Control 不支持）**、同时覆盖 Claude 与 Codex；上线前逐个复核现状。不开源也不靠独立包传播，需要靠演示内容和论坛社区带来用户 |
| 手机推送国内通道复杂、需备案 | 手机端延期 | P6 放最后；先用应用内通知加轮询 |

## 6. 已定事项（2026-10-28）

| 事项 | 决定 | 影响 |
| --- | --- | --- |
| 平台 | **Windows 与 macOS 都要支持** | P0 的验证、P1 的代装、P2 的适配在两个平台上各做一遍；每个退出条件按两个平台分别验收 |
| 先支持的 Agent | Claude Code 与 Codex 同时做观察层；接续层先做 Claude Code，Codex 随后 | P3 里 Codex 的接续排在 Claude Code 之后 |
| 产品形态 | **不做独立安装包**，“语音编程”是小伴里的一个入口/模式 | P5 改为在小伴内做精简入口与首次引导；安装包体积不单独优化，但首次使用路径要能跳过壁纸、社区等内容 |
| 开源 | **不开源** | 外部 Agent 适配层与桌面应用注入都留在小伴内部仓库 |
| 中文识别 | **沿用现有方案** | P4 不单独做识别优化；复述确认兜底，技术词纠错表等有真实使用反馈后再做 |
