# 小伴网页版：目标、实施计划与验收

状态：本地实现与针对性验收完成，未部署生产。基线 `7391d0ee`，分支 `codex/mobile-web-experience`。本轮按用户要求先同步主分支，再由多个 agent 实现，主 agent 负责交互、集成和验收。本文覆盖此前在线创作提议：**网页体验作品、基础 AI 聊天，生成和修改作品引导客户端**。

## 目标与边界

- 在现有 `services/server-forum/web` 上完成移动优先的完整小伴网页，适配 PC；复用账号、论坛、资源、AI 网关，不新建重复社区。
- 四个主模块：小伴 AI、创造、社区、我的；移动底栏另设发布快捷操作。社区保留首页/讨论/资源及相应二级栏目。
- 社区：发现内容、搜索、阅读、回复、收藏、通知、发布沿用真实服务。首页补齐推荐、开源热榜、排行榜、追踪、导航；资源补齐工具与资料及现有分类入口。
- 创造：发现作品、详情、真实可用的试玩/预览、收藏与分享；在客户端创作/修改。浏览或试玩时不强制下载，不制作虚假生成进度或不可用的操作。
- 小伴 AI：登录后的真实基础文字聊天、模式、停止、重试、历史和额度；不执行网页创作工具、不遥控设备。明确浏览器历史的保存范围，不能把本机记录宣称为云同步。
- 我的：未登录也能进入；登录、资料、收藏、发布作品、通知、额度与客户端入口。
- Android 下载只承诺已经支持的手机创作；桌面装扮指向 Windows/macOS；iOS 不宣称已支持本地创作。
- 桌面社区随后接入新的社区体验，保留现有内容包应用与本地方案能力；远程网页不获得桌面原生命令权限。
- 本轮不部署生产、不发布帖子、不改真实账户或付费配置；不扩展实时语音、云端 Agent、全量聊天同步或原生手机功能。云端部署如后续授权，仍本机构建再上传。

## UI 与交互标准

- 以 `手机端设计规范.md` 和 2026-11-01 社区整理为参考：灰底白卡、品牌红点缀、真实图片、标题优先；没有配图就用文字列表，不画假封面，不恢复官方挑战主入口。
- 复用现有主题变量；主 agent 统一外壳、导航、字体、间距及夜间色。手机 360/390px、平板 768px、PC 1440px 验收；内容不横向溢出，图表可在自身区域滚动。
- 底栏安全区、软键盘与输入区不互相遮挡；返回保留筛选和滚动位置；详情能通过独立 URL 打开。
- PC 保持同样功能，展开导航与合理列宽；不把手机页面无边界拉宽。阅读正文控制宽度。
- 弹层可关闭、支持 Escape/焦点返回；图标有可访问名称；主触控区域至少 44px。
- 加载、无数据、错误、重试、未登录均有可用状态；过期网络响应不覆盖当前筛选；无虚构互动数、账号状态和能力。

## 分工与依赖

| 工作流 | 负责人 | 文件边界与交付 |
| --- | --- | --- |
| A 社区内容 | gpt-6.1-sol | 首页发现/资源/日报/工具页、相应 API/组件与契约测试；保留论坛现有互动 |
| B 小伴 AI | gpt-6.1-terra | 基础聊天页、网关请求/SSE/历史与状态测试；核实论坛账号接入网关的配置条件 |
| C 创造与下载 | gpt-6.1-terra | 创造页、客户端引导、已支持内容的试玩/预览、作品详情交互与针对性测试 |
| D 外壳与集成 | 主 agent | App/顶栏/底栏/路由/全局样式/我的页，桌面接入，文档与最终验收 |

先约定路由与视觉变量，A/B/C 并行；主 agent 不在子任务进行时修改其拥有文件。子 agent 不提交、不推送、不修改无关文件或 lockfile、不跑全仓构建。完成后主 agent 合并同一工作区的结果并处理交叉依赖。

路由：`/` 社区首页，`/discuss` 讨论，`/resources` 资源，`/ai` 小伴 AI，`/create` 创造，`/me` 我的；`/daily/:key` 日报详情，`/tools/:key` 工具详情。保留旧帖子、作品、方案与管理链接；旧首页类型链接映射到创造/周刊/项目入口，不能静默丢失。

## 验收标准

1. 四个模块可由移动底栏和 PC 导航到达，发布快捷操作提供发帖/上传已有作品；直接刷新详情无空白。原有管理员界面不受新外壳影响。
2. 社区栏目请求真实现有 API，榜单来源/时间/示例状态正确；文章正文、工具详情、分类与搜索可到达；接口异常可重试。
3. AI 使用有效账号令牌与后端档位，不在浏览器放服务商密钥；SSE 跨分片、错误、停止、重试、账号切换与历史隔离有针对性检查。未配置网关/额度不足如实提示，不能以 mock 证明线上接通。
4. 创造能体验实际作品；试玩的可见性/版本/完整性和隔离符合资源协议，拒绝越界或不支持的资源。源码/模型调用不在网页生成，创作按钮给出准确平台下载引导，并保留可复制的用户想法。
5. 收藏/发布/通知复用现有权限；未登录操作进入登录流程并保留合理上下文。浏览器验收不向生产写内容或改变收藏。
6. 360/390/768/1440px 和深浅色检查布局、底栏、详情、弹层、AI 输入、错误状态；试玩可退出返回，窄屏触控按钮可用。
7. `npm --prefix services/server-forum/web run build`、现有相关测试及新增行为测试通过；后端如修改则仅跑对应测试。检查 diff、路由、接口与日志敏感信息，不做全仓编译。
8. 交付记录区分：实现、自动化测试、本地浏览器验收、真实服务联调、生产部署。未具备账号/服务配置的部分必须明确记录，不能宣称通过。
9. GitHub Actions 仅允许 `workflow_dispatch`，不新建自动 CI、不监控远端 CI。保留开始时用户的三处桌面设计稿改动。

## 验收记录

### 已完成

- 四模块移动底栏 / PC 侧栏、真实发现 API、作品与工具/日报详情、客户端创作引导、小伴 AI 流式文字聊天实现及桌面社区独立窗口。
- 旧分类 URL 在全局路由守卫转换，保留种类、分页和排序；方案、周刊、项目旧入口保留。登录返回保留目的地。会话过期隐藏受保护内容并保留当前编辑实例，同一账号重登可继续；新账号必须取得资料确认身份后才能显示并重建视图。
- AI 历史按账号隔离，受限存储降级、体积上限、SSE DONE/取消/异常、IME 回车和账号切换请求代际处理。会话 refresh、资料请求和旧 401 不能覆盖新账号。
- 创造列表使用真实数据；按真实已审核列表选择推荐游戏，无虚构示例入口。ZIP 大小、版本、SHA-256、清单、路径与包资源检查；独立宿主传输普通数据对象，作品在内层受限 iframe 执行。

## 用户复核调整：官方内置创造页
