日期：2026-10-31。基线：本地 main `5ec0b93f`，包含发现页发布工作流提交 `43c5068a`。代码基线不代表线上已部署；上线版本在首次部署前另行核实。

## 1. 目标与范围

目标：社区从“页面与示例数据可浏览”成为可持续维护的产品：真实来源定期采集、人工审核发布、手机社区页面功能闭环、网页版与桌面入口兼容、运营可追踪、故障可恢复。

本计划覆盖首页、讨论、资源、搜索、各类详情、社区发布、我的社区内容、互动通知、分享、社区管理台及其资源服务。具体包括模型能力榜、OpenRouter 模型调用量榜、开源热榜、日报、追踪、导航、资料、工具库、作品、方案、项目、周刊、求助和挑战。

小伴 AI 对话、模型网关业务、语音、遥控电脑、独立游戏中心、Agent 记忆和私人资料库不是本次社区开发范围。社区中游戏内容的展示、详情、分享、试玩跳转纳入；开发完整手机游戏宿主另立跨产品工作包。iOS 保持接口兼容，不能以 Android 验收结果替代 iOS 实机结论。

## 3. 解耦方式与接口边界

采用业务模块隔离，初期沿用 `server-forum` 与现有 PostgreSQL，不因页面不同就新增一套独立微服务。论坛读写、账号校验、内容发布仍使用现有服务；采集模块可按需运行在独立 worker 进程，隔离网络超时、下载和内存压力。

```text
官方数据源 / 编辑录入
  ├─ 模型能力榜模块（Artificial Analysis）
  ├─ 模型调用量榜模块（OpenRouter）
  ├─ 开源热榜模块（自有每日快照）
  ├─ 日报与追踪模块
  └─ 工具与版本模块
          ↓ 统一 CandidateBatch / DraftSink
   草稿与来源记录 → 人工终审 → 定时或立即发布 → 社区公开读接口
                                                      ↓
                                             手机 / 网页 / 桌面
```

- 各采集器只拥有自己的数据和任务状态；不能改别的模块草稿，不能写线上内容。失败不能删除、清空或替换上一版已发布内容。
- 统一少量契约：`Collector`、`CandidateBatch`、`DraftSink`、密钥访问接口、任务执行记录。模块自带数据映射、校验、测试和迁移，不建立混杂业务规则的全局 utils。
- 来源元信息至少包含来源标识、URL、源记录 ID、采集时间、内容时间、评分口径版本、内容哈希；榜单额外记录观测区间和完整性。
- 稳定来源 ID 用于幂等。网络重试不增加重复条目；相同内容不反复产生新待审版本；已被人工修改或已审核定时的稿件发生冲突时报告冲突，不无条件覆盖。
- 模型+厂商、同一期热榜等相关内容以一个批次预览、审核和事务发布，不能出现新模型引用不存在的厂商、半期榜单、不同口径混排。沿用现有草稿和版本控制，补批次语义，不另建平行发布通道。
- 旧 `/api/discover/*` 协议保留。新增字段优先兼容扩展；需要改变空值或指标语义时新增版本接口，客户端随对应工作包升级。
- 采集器独立长超时 HTTP client，按来源设置并发、限频、缓存、退避、最大响应和下载体积；校验跳转与目标地址，防止访问内网或泄露密钥。
- 采集调度运行在服务/worker 内，不用 GitHub Actions schedule。自动化到“产生待审草稿”为止；已由人审定的版本才可定时发布。

## 4. 项目分工与验收标准

“负责人”是开发职责，不要求新增用户可见聊天。实施时使用子 Agent 和独立 worktree；集成人同时最多调度 3 个开发 Agent，避免争抢公共入口与本机资源。

### A：采集与编辑公共基础（先行，集成人负责）

交付：第三方密钥后台配置；验证成功后加密入库；只返回尾号/状态；密钥轮换；任务启停、手动执行、运行记录、下次执行时间、失败原因；来源配置与统一草稿写入；批次审核；共享入口和迁移注册。

验收：管理员能配置、更新、禁用来源；无效密钥不覆盖旧密钥；列表/日志/审计不泄露密钥；加密主密钥由部署侧注入而非存入同一数据库，第三方 API key 不写 `.env`；并发执行同一任务至多一个生效；进程中断可重试；采集令牌不能审核发布；批次事务失败全部回滚。

### B：模型能力榜、调用量榜与天梯

#### B1：能力榜（Artificial Analysis）

交付：Artificial Analysis 适配、厂商/模型稳定映射、真实指标和价格单位、来源与更新时间、评分版本、散点图缺失值处理、分档规则；新版管理表单和手机模型榜适配。

频率提议：每天一次，可手动执行，后台可调整。

验收：固定样例与官方响应字段能逐项对照；缺失指标显示“暂无数据”，不当 0；不同评分版本不直接比较；缺失价格的模型不参与价格散点图；保留手录能力；接口故障或额度不足不影响线上旧榜；真实发布内容不带示例标记。

外部核对：AA 当前文档说明旧 Coding/Agentic Index 字段始终为空，空值不表示零。不能把旧设计的 `iq/code/math/agent` 全部强行映射到现有数据。S0 应冻结指标清单；必要时提供模型榜 v2，旧接口保留已发布快照，不向旧字段填造出的零分。

#### B2：调用量榜（OpenRouter，每日采集）

用户于 2026-10-31 新增需求：模型榜增加 OpenRouter 模型调用量排行榜，每天抓取。与 B1 独立实现采集器、数据表、运行记录和公开接口，单个来源失败不影响另一榜单。

来源与口径：优先使用官方 `GET https://openrouter.ai/api/v1/datasets/rankings-daily`，使用后台单独配置并加密保存的 OpenRouter API key。该接口返回每天 Token 用量前 50 个公开模型和 `other` 汇总行，统计为输入+输出 Token。页面展示“调用量榜（Token 用量）”，注明仅代表 OpenRouter 平台流量；不写成请求次数、用户数、花费或全市场份额。[官方接口与口径](https://openrouter.ai/docs/api/api-reference/datasets/daily-token-totals-for-top-50-models)

采集与存储：

- 默认每天北京时间 12:00 执行，目标为最近一个完整 UTC 自然日；依据返回的日期范围和 `as_of` 判定来源实际进度，源数据未就绪时保留旧榜并按限频做有限重试，不以当天不完整数据替代整日榜。
- 指定 `period=day` 与日期范围，使用全平台日榜；不混用周粒度估算的分类/语言榜。默认回查最近三个完整日，补断采与来源修订；首次接入先展示确实取得的历史范围，不造历史。
- 唯一键为来源、UTC 日期与 `model_permaslug`；日期快照保存 `as_of`、采集时间和数据版本。免费等变体保持来源独立标识，不按模型名字模糊合并到 AA 能力榜。
- `total_tokens` 按无损十进制整数解析和保存，API 向客户端以字符串传输，排序/合计不能经过浮点数；测试覆盖大于 JavaScript 安全整数范围的用量。
- 每个日榜作为一个完整批次产生草稿，沿用人工终审和发布流程；重跑相同数据不产生重复草稿，来源修订生成待审版本，不覆盖人工已发布版本。
- `other` 只用于总量/占比分母，不作为模型参与排名。名次按 Token 总量降序、相同值按稳定标识确定展示顺序；前日无数据时不显示涨跌，新进 Top50 与整个前日缺采样须区分。

页面与运营交付：模型榜内增加“能力榜 / 调用量榜”切换；调用量榜展示排名、模型、Token 用量、占比、可计算的日排名变化、统计日、来源更新时间及来源链接，支持查看已发布的往期日榜。管理台可手动补采、查看错误、对比修订和审核整榜。页尾及分享内容按官方要求署名 OpenRouter 并附 `as_of`。入口与当前模型天梯设计对齐，不把 Token 用量作为能力评分。

验收：固定日的 Top50、`other` 与总量能和官方响应逐项核对；整日快照发布原子切换；凭据错误、429、超时、缺日、重复执行和源修订均有测试；保留上一版并正确提示统计日；时区边界正确；整数精度不丢失；未审核内容不可从公开接口读到。接入真实 key 后做一次小规模采集验证，不以样例测试宣称已接通。

### C：开源热榜、项目与周刊

交付：可配置候选仓库；每日 star 总量快照；净增量口径；异常增长标记；周榜生成；往期、项目解读、候选来源和人工编排；项目与周刊关联讨论。

频率提议：每日采快照，每周产出一期待审榜单。候选池有上限，防止全量爬取。

验收：确定七日边界和时区；不足七天标注实际观测天数；缺采样不补造历史曲线；区分累计 star 与期间净增；删除/改名仓库保持稳定身份；异常仅进入复核；同一期重跑幂等；发布整期原子切换；上一期仍可查询。第一份完整七日榜单需要实际积累七天，开发完成不能代替观测时间。

### D：日报、追踪、导航与资料

交付：官方 RSS/公开发布页白名单；URL 去重；每天不超过十条日报候选；模型上新和限免的来源、开始/结束时间；导航、资料分类表单和链接检查；头图继续人工编排。

频率提议：日报与上新每六小时检查；限免到期由服务端时间判定；导航/资料按需录入和低频检查。

验收：只保留标题、来源、链接和允许的摘要，不抓全文；重复来源不重复入稿；修改和取消活动可更新草稿；时间统一存 UTC、按约定时区展示；无可靠公开依据的额度重置保持手录或隐藏，不伪造全局实时进度；不可用来源保留旧内容并显示状态。

### E：AI 工具库与资源镜像

交付：官方项目注册；正式版本、更新记录和多系统/架构安装包；许可证来源；下载体积和 SHA-256；镜像上传、回读核验和下载回退；资源机与论坛元数据关联。

频率提议：每六小时检查正式版本；预发布单独开关，默认不混入稳定版。

验收：同一 release/asset 幂等；操作系统/架构识别不明的条目进入人工确认；源未提供摘要时流式下载计算且不执行安装包；镜像回读校验失败不能登记可用地址；失败保留上一版；无 LICENSE 不能推断为开源；大文件处理不占用论坛请求进程，受带宽、体积和磁盘配额限制。

### F：手机社区闭环（按子包串行或分两个工作轮）

F1：首页与搜索——各栏目加载、空态、重试、分页、来源和更新时间；精选创作；热门搜索后台维护；筛选与返回位置保持。

F2：讨论与求助——创建投票、插图、附件、帖子编辑、回复与回复作品卡；求助发起、采纳、关闭、到期状态；点赞、收藏、关注、屏蔽、举报、站内通知、我的发布与收藏。

F3：资源与内容详情——能力详情、方案详情、项目/周刊、装扮/游戏详情；我的作品、内容包上传/版本/审核状态；创作栏方案筛选。方案继续使用已有 `schemes` 对象，不将 scheme 冒充 zip 内容包类型。

验收：逐页列出“入口→读接口→写操作→成功状态→失败恢复”；用户完成真实发布/回复/投票/采纳后重新进入状态仍一致；未登录、权限不足、重复点击、令牌刷新、上传失败均有结果；下架内容不可通过收藏、旧链接绕过；Android 真机验收图片选择、键盘、返回栈、长列表、深浅主题。JVM 单测通过不能替代真机交互验收。

### G：分享、桌面衔接与云端沉淀

交付：手机统一分享面板、复制链接、系统分享、海报保存；H5 落地页和深链；社区收藏跨端读取；桌面“保存当前桌面为方案”、方案发布/复刻；已支持内容的一键应用回归；资源备份和恢复演练。

验收：分享链接未登录也能打开；下架内容不泄露；未安装 App 有可用网页/下载路径；未接微信/QQ 等平台 SDK 时不宣称能直发指定平台，保留系统分享；权限拒绝可恢复；深链、哈希校验、确认后应用在实际桌面打包版本验证；云同步默认关闭且只同步明确选择的社区对象，不上传 Agent 记忆、私人资料库或模型密钥；备份做实际恢复核验。

### H：编辑运营、挑战与最终集成（集成人统筹）

交付：精选作品排序、项目/周刊编排、挑战的发起/投稿/截止/精选；管理台类型化表单、差异预览和待审状态；按栏目聚合的数据；采集新鲜度、失败重试、停用与过期提示；示例数据替换与归档；必要的索引和针对性限流。

验收：精选和下架立即影响公开入口；截止后不能重复投稿；运营数字来自真实聚合、不造点赞或使用数；首个真实快照发布时仅替换对应示例，不影响手录内容；一次单模块采集失败不影响其他模块和社区读写；生产升级有备份、回滚产物及冒烟记录。

## 7. 共同验收与完成定义

- 真实数据闭环：接通已获授权的一手来源，生成草稿，人工终审后手机/网页可读；来源、时间和采样口径可核对。
- 数据正确性：缺失不伪造、重复不增条、失败不覆盖、人工修改不被采集覆盖；跨条目的榜单批次原子发布。
- 权限与内容状态：未登录、普通用户、采集令牌、管理员边界清楚；草稿、下架、封禁内容不通过详情、分享、搜索或收藏旁路泄露。
- 页面覆盖：每个约定页面的入口、主操作、空态、失败重试和返回状态均在矩阵中签收，不能以“接口返回 200”替代交互完成。
- 服务测试：Rust 纯逻辑与隔离 PostgreSQL 集成测试；必须显式设置 `TEST_DATABASE_URL`，跳过的数据库测试不能记为通过。
- 网页验证：受影响的 TypeScript 检查、前端构建和浏览器实际操作；不全仓格式化或编译。
- 手机验证：community-core 针对性 JVM 测试、Android 调试包及真机流程；涉及系统分享/文件/深链时使用实际系统能力验收。
- 运维验证：真实来源最小规模试跑、限频与超时、重启恢复、单模块故障隔离、备份恢复；密钥不出现在接口正文、日志或审计中。
- 交付报告逐项区分：代码完成/本地验证/真实来源验证/已部署/待运营观察。缺 API 授权、缺设备或未积累七天快照时明确未完成部分，不能用样例测试替代。
