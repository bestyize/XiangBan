# 内容生态与社区：分阶段实施计划

状态：讨论稿。对应 [PRD_内容生态与社区.md](PRD_内容生态与社区.md)（下称“PRD”），把 PRD §9 的路线拆成可开工的工作包。手机应用的界面范围以可点击原型为准（共 30 余张画板，覆盖社区、小伴AI、游戏、我的、模型与额度、资料库、分享）。

本文只排顺序、依赖、交付物和验收。**工期是初估**：按 2–3 人加 AI 编码协作估算，单位是“日历周”，只用来判断先后和量级，开工后每个阶段末回看一次，不当承诺。进入下一阶段看信号（PRD §8.4），不按日期自动进入。

## 1. 原则

1. **先内容，后工具，最后平台。** 先用周刊和官方内容证明“有人来、有人用”，再开放用户发布，最后做手机原生。
2. **官方内容先行，不依赖论坛用户量。** M2a 的价值要靠官方内容和桌面端存量用户成立。
3. **每个阶段单独可交付、可下线。** 任何一阶段停下，前面的东西仍然是完整产品。
4. **复用现有机制，不另起一套。** 论坛后端、资源包 zip 与 `manifest.json`、`xiaoban://` 深链、关怀提醒、长期目标、市场审查流程、账号中心、`server-ai` 网关。
5. **高风险的放后面。** 用户上传的可运行内容（HTML 类）、云端同步、遥控电脑、实时对话。
6. **新增标识不带品牌词**，改名时不返工（PRD §2.4）。

## 5. 各阶段详细计划

### M0 前置与基线（约 2 周）

**目标**：验证关键假设，让后面不返工。

| 工作流 | 交付物 |
| --- | --- |
| A | 周刊流水线定稿：AI 采集 → 初筛 → 解读 → 人工终审的步骤与检查清单；GitHub 与网页检索来源实测（可用性、频率、授权）；首期选题样例 |
| B | 桌面与论坛匿名埋点（事件定义见 PRD §8.3）；表结构设计评审（PRD §10） |
| D | **`xiaoban://` 深链真机验证**（Windows、macOS 各一台）；确认窗口与哈希校验的交互稿 |
| E | 手机应用技术路线定稿：原生（KMP + Compose）还是混合；设计规范变量化（颜色、字号、圆角、间距，见原型的视觉规则）；MA 网页壳的范围 |
| F | 决定 `server-ai` 的部署时点与环境；H5 域名、通用链接方案选型；对象存储选型（存放内容包 zip） |
| 全局 | 品牌字串集中管理（PRD §2.4）；原型定稿并通过评审；PRD §13 待确认项逐条回复 |

**退出条件**：埋点上线；数据源可用；流水线和清单就绪；深链真机结论明确；原型确认。

**风险**：深链在某系统不可用 → 退回“下载 zip 后手动导入”作为一键应用的降级路径（M2a 仍可成立）。

### M1 周刊与前台改版（约 5–6 周）

**目标**：连续发布周刊，前台换成新的信息架构，拿到第一批访客信号。

| 工作流 | 交付物 |
| --- | --- |
| A | 连续 4 周发布周刊（Markdown 帖，基于 `forum-post-studio`）；每期手工海报与站外分发；项目解读帖 |
| B | 新增 `projects`、`weekly_issues` 表与 `GET /projects`、`GET /weekly/{week}`；清理福利羊毛（羊毛帖类型、`/deals`、到期下架任务）；分类按新结构重排（资源、讨论、公告）；分享链接生成与落地页所需的公开接口 |
| C | 前台改版第一版：社区首页（内容流 + 二级 Tab，含周刊）、资源、讨论、帖子详情、搜索；分享落地页（H5，含“打开 App / 下载”）；顶部一行结构（标识、一级栏目、搜索图标） |
| D | 桌面端“社区”页（只读，打开周刊与首页内容） |
| E | **MA：网页壳**——手机应用加载新前台，只读浏览；分享先支持“复制链接” |

**退出条件**：连续 4 周发布；有 PRD §8.4 所列的访问信号（独立访客、注册、项目页回复、桌面“社区”页点开率）。

**不做**：结构化项目页的“试用”按钮（周刊稳定后再加）；用户发布；一键应用。

### M2a 官方内容一键应用（约 6 周）

**目标**：桌面用户一键应用官方 `effect`、`scheme`，一键试用官方任务模板，不依赖论坛用户量。

| 工作流 | 交付物 |
| --- | --- |
| B | `packs`、`pack_versions`、`schemes`、`pack_applies` 表；`POST /packs`（服务端校验 zip、`manifest.json`、大小 32 MB 上限）、`GET /packs`、`GET /packs/{id}`、`GET /packs/{id}/download`（计数，仅聚合）；官方发布的后台页；信任分级字段（T0 / T1 / T2） |
| D | `xiaoban://community/apply/{kind}/{pack_id}?version=&sha256=`：确认窗口、哈希校验、导入、二次确认才应用；**提醒规则、例行事项、任务模板、目标模板的导入入口**（桌面现无，需新增，格式沿用 zip + `kind` 并抬高 `schemaVersion`）；桌面方案“保存 / 复刻”本地版（逐项下载并确认，下架项给替代） |
| A | 官方 `effect`、`scheme` 首批；官方能力卡（提醒规则、例行事项、任务模板各数条，先做提醒和例行，目标模板放后面）；每条写清“能做 / 不能做 / 运行位置 / 安全说明” |
| C | 内容包卡片与详情页（装扮详情、能力详情、桌面方案详情）、“发到电脑”说明面板 |
| E | MA 增加“发到电脑”的系统分享（导出 zip 经微信等发出，首版方式，后期换云端收件箱） |

**退出条件**：桌面用户能一键应用官方内容、一键试用官方任务模板。看信号：官方内容包的一键应用次数、应用后 7 日是否仍在使用。

**安全底线（不可妥协）**：导入不自动应用；任务模板和例行事项创建前展示完整提示词与权限并要求确认；用户不在场时只开放只读；HTML 类不在这一阶段开放。

### M2b 开放用户发布（约 5–6 周）

**交付物**

| 工作流 | 交付物 |
| --- | --- |

### M3 放开与沉淀（约 10 周，可拆）

| 方向 | 交付物 |
| --- | --- |

## 6. 手机应用分步（MA / MB / MC）

手机应用是新工程，**不并入壁纸 App**。拆成三步，每步可上架。

| 步骤 | 对应阶段 | 范围 | 前置 |
| --- | --- | --- | --- |
| **MA 网页壳** | M1 之后 | 加载新前台，只读浏览；复制链接；跳转登录 | 前台改版完成 |
| **MB 原生社区 + 小伴AI** | 与 M2 并行，M2a 之后启动更稳 | 底栏五格；原生社区（信息流、详情、搜索、发帖）；小伴AI 首页与对话页；**模型与额度**（小伴AI 列表、兑换、自有服务）；**资料库**（我的文档、收藏，本机）；分享面板与海报；我的、设置 | `server-ai` 部署；MA 已上线；M2b 的合规项（发帖回复需要） |
| **MC 能力补全** | M3 之后 | 游戏试玩（独立沙箱域名）与排行榜；在线创作；实时对话；联网搜索；拍照提问；“我的电脑”配对与遥控 | 实时网关部署；沙箱域名；Agent 遥控方案 |

**MB 的拆分建议**（每项独立可测）

1. 工程骨架与设计规范变量（颜色、字号、圆角、间距、底栏胶囊、顶部一行）。
2. 账号登录与我的页。
3. 社区信息流与详情（先读后写）。
4. 小伴AI 对话页（文字问答，走 `server-ai` 的响应协议，流式显示）。
5. 模型与额度（档位列表、兑换码、思考强度；自有服务的密钥只存本机）。
6. 资料库（本机存储；发给小伴AI 前明确提示“将发送到云端”）。
7. 发布与发帖（等 M2b 合规项）。
8. 分享（复制链接、海报、系统分享；各平台 SDK 另排）。

| 对象 | 验证方式 |

## 9. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 范围蔓延（装扮、Agent、社区、手机同时铺开） | 严格按阶段顺序；每阶段末回看；MB 前不开 MC 的任何内容 |
| 周刊靠一个人终审，断更 | 先固定每周一期、10 条以内；断更两周自动降级为“精选合集” |
| 论坛没有用户，开放过早没人用 | M2a 不依赖论坛用户量；M2b 看信号，没有信号不开放 |
| 用户上传内容引入安全问题 | T2 只开放纯数据类；HTML 类须审核；游戏只在独立沙箱运行；导入从不自动应用 |
| `server-ai` 上线晚拖住手机端 | M1 内部署并联调；MA 不依赖它 |
| 分享 SDK 审核周期长 | 首版以复制链接、海报、系统分享为主 |
| 与桌面端、壁纸 App 的数据模型不一致 | 新增表追加不改旧表；数据目录不迁移；跨端的 `manifest.json` 版本显式 |
