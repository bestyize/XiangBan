## 3. 数据流

```
 （你要做的采集 / 编辑）
        │  PUT /api/admin/discover/{kind}/{key}      管理员令牌
        ▼
 discover_items 表 ── 写入时按 kind 校验、只留已知字段
        │
        ▼
 GET /api/discover/*  /api/tools  /api/help/stats    公开，无需登录
        ▼
 手机端 ForumApi → Controller/Loader → Compose 页面
```

- 所有发现页内容统一存 `discover_items(kind, key, sort_order, status, published_at, data JSONB)`，主键 `(kind, key)`。`status` 为 `draft` 的不对外。
- 读接口只返回已发布的；`data` 里的 `sample` 字段决定手机端是否标“示例数据”。
- 校验和种子在 `services/server-forum/src/discover.rs`，读取和管理接口在 `src/handlers/discover.rs`，集成测试在 `src/handlers/discover_tests.rs`。
- 排序：日报、模型上新按 `published_at` 倒序；其余按 `sort_order` 升序；限时免费按 `ends_at`。

## 4. 后端接口与数据形状

公开读接口（`/api` 前缀）：

| 路径 | 用途 |
| --- | --- |
| `GET /discover/home` | 首页推荐：头图、当天日报前 5 条、精选创作（目前取“使用次数”最高的内容包）、热榜前 3 |
| `GET /discover/daily?page=` | 往期日报 |
| `GET /discover/repos[?issue=key]`、`GET /discover/repos/issues` | 开源热榜某一期、往期列表 |
| `GET /discover/models` | 模型榜：厂商、模型、分档阈值 `tiers`（服务端给，客户端不写死） |
| `GET /discover/tracker` | 额度重置、模型上新、限时免费（进度和剩余天数服务端算） |
| `GET /discover/nav`、`/discover/docs`、`/discover/hot-search` | 导航、资料导读、热门搜索词 |
| `GET /tools`、`GET /tools/{key}` | AI 工具及各系统安装包、更新记录 |
| `GET /help/stats` | 求助悬赏页顶部三个数（全站值） |
| `PUT /topics/{id}/poll/vote {option}` | 投票，每人一票，需登录 |

管理接口（管理员令牌，`POST /api/admin/login` 取）：

- `GET /admin/discover/{kind}`：列出（含草稿）。
- `PUT /admin/discover/{kind}/{key}`，请求体 `{data, sort_order?, status?, published_at?, sample?}`：新增或覆盖。`key` 只能是小写字母、数字、`-`、`_`。**`sample` 不传就是 `false`**，真实内容别传 `true`。
- `DELETE /admin/discover/{kind}/{key}`。

`kind` 与 `data` 的字段（写入时严格校验，字段名以 `discover.rs` 里的结构体为准）：

| kind | 字段 |
| --- | --- |
| `banner` | `tag, title, byline, link`（`link` 可写 `topic:12` / `pack:3` / `tool:key` / `weekly:2026-W44` 或 https 外链） |
| `news` | `title, source, url, cover_url, accent`（日报一条；只存标题、来源、链接，不存全文） |
| `repo_issue` | `issue_no, week_start, week_end, total_gain, wow_pct, daily_gain[7], ranks[{full_name, description, language, language_color, star_total, star_gain, spark[], icon, tint}]`；写入时 `ranks` 按 `star_gain` 倒序，最多 50 条；`key` 用期数字符串，最新期按 `issue_no` 判定 |
| `vendor` | `name, brand_color, tint` |
| `model` | `name, vendor(厂商 key), iq, code, math, agent(0–100), price(美元/百万 token), speed(token/秒), latency(秒), context, open, reasoning, cn` |
| `quota` | `progress_pct, next_reset_at, recent_intervals[]`；页面只取排序第一条；**用 `published_at` 表示“N 分钟前更新”** |
| `launch` | `title, tags[]`（时间取 `published_at`） |
| `promo` | `text, started_at, ends_at` |
| `nav` | `group, name, vendor, url, brand_color, tint` |
| `doc` | `product, title, subtitle, label(guide/index), url` |
| `tool` | `name, developer, type_label, license(open/closed/unknown), platforms[], description, homepage_url, icon_url, discussion_tag, releases[{version,date,items[{kind(new/improve/fix),text}]}], artifacts[{os(windows/macos/linux), desc, size, sha256, mirror_url, github_url}]` |
| `hotword` | `text, tag`（“热”“新”之类的小标记） |

帖子相关（已有论坛接口，手机端用到的新增部分）：发帖可带 `poll: {options: 2–6 项, days?}`；列表和详情返回 `images`（正文里前 3 张站内图）、`poll`、`view_count`；`GET /topics?category=a,b` 可同时指定几个分类；`help_status` 筛选求助。

## 6. 剩下的活：可以并行的几块

每块都独立：落点不同，互不依赖。**共同约束**：

- 事实性内容只取一手来源；日报只存标题、来源、链接；**不做自动发布**，AI 采集和写草稿，由产品负责人终审后发布（PRD §6.1）。抖音、公众号等封闭平台不抓。
- 第三方令牌（Artificial Analysis、GitHub 等）**不要放 `.env`**：产品负责人明确要求做成管理后台里“只写不读”的设置——保存前先验证、加密存库、页面只显示尾号、写审计日志但不记令牌。参考 `services/server-ai` 的 `settings.rs` 和后台“网关连接”页。
- 采集器不要用管理员账号密码长期登录。建议新增一种**只能写发现页的作用域令牌**，做法照搬已有的 `editor_tokens`（`handlers/editor.rs`、管理台“编辑账号”）。
- 采集结果写的是**草稿**（`status: draft`）还是直接发布，由第 6.F 块的流程决定；在那之前，采集器默认写草稿。
- 写入必须带 `sample: false`（默认就是），并保证幂等：同一来源同一周期重复跑不能产生重复条目（用稳定的 `key`，如 `repo_issue` 用期数，`news` 用 URL 的哈希）。

### A. 模型榜自动同步（`model`、`vendor`）
- 目标：每天一次从 Artificial Analysis 同步模型的智能/编程/数学/智能体指数、价格、速度、延迟，页面注明出处（已有“数据来源 Artificial Analysis”文案）。
- 注意：**接口和字段名我没有核实**，先查官方文档；要 API key。拿不到 key 时保留手录。
- 落点：`services/server-forum` 里加定时任务（`src/jobs.rs` 目前是 600 秒一轮、`AppState.http` 的超时只有 5 秒，采集要另建长超时的 client）。同步失败时保留上一版数据，只记日志。
- 验收：本地 `cargo test`；线上 `GET /api/discover/models` 的 `updated_at` 更新、`sample` 变 `false`。

### B. 开源热榜采集（`repo_issue`）
- 目标：每周生成一期：按 7 日新增 star 排序的 AI 相关项目，附每日新增、趋势、语言、简介。
- 注意：GitHub 没有官方 Trending。用 Search API 近似，要自己存每日 star 快照来算增量（需要新表，如 `repo_snapshots`）。**star 增速异常的标“疑似刷量”，只进人工复核，不自动上榜**。需要 GitHub token（见共同约束）。
- 落点：后端定时任务或一个本地技能（PRD 建议先做本地技能，再考虑服务端采集器）；产出调用 `PUT /admin/discover/repo_issue/{期数}`。

### C. AI 日报采集（`news`、`banner`）
- 目标：每天十条以内：标题、来源、链接、可选封面。来源建议 RSS 和公开站点。
- 注意：去重（按 URL）；不存全文；来源名要真实可核对；`accent` 是没有封面时的缩略图颜色。
- 头图 `banner` 是本周原创内容的入口，保持手工编辑，不自动化。

### D. 追踪（`quota`、`launch`、`promo`）
- Codex 额度重置的时间来源需要先找到可靠的口径（官方文档或公开页面），找不到就保持手工。模型上新、限时免费同理，先定数据源再谈自动化。
- “提醒我”目前只是本地闹钟（`Env.reminders`），不是推送。

### E. AI 工具库（`tool`）
- 目标：版本、更新记录、各系统安装包从 GitHub Releases 同步，计算 `sha256` 和大小。
- “小伴镜像”：把安装包传到资源机后，在 `artifacts[].mirror_url` 填地址；**没有镜像时手机端会隐藏“小伴镜像”分段**。资源机和镜像机制见 `services/server-resource` 和 `pack_versions.mirrors`。
- 注意：许可证以仓库 LICENSE 为准，核实不了就写 `unknown`（显示“待确认”）。

### F. 发布与编辑工作流
- 现状：管理台“发现页”是 JSON 文本框，只能一条条改。
- 目标：草稿、预览、批量导入、定时发布；热门搜索词（`hotword`）。参考现有的 `tools/claude-skills/forum-post-studio`（批量发帖流程）。
- 已知缺口：管理台 `DiscoverPanel.vue` 的类型下拉里**没有 `hotword`**，现在只能用接口写入。

### G. 手机端还缺的页面和入口
- 能力详情、方案详情（创作栏的能力卡现在点进去用的是内容包详情页）。
- 分享弹层（微信、朋友圈、QQ、微博、海报），目前只有“复制链接 / 系统分享”。
- 求助帖里回答附带作品卡；创作栏的“方案”筛选（论坛里没有这个内容包类型，需先定义）。
- 发帖页：发起投票、插入图片；帖子详情里的点赞数、评论等互动。
- ChatGPT 的官方图标（设计稿本身也是占位）。

### H. 运营数据
- “精选创作”目前取使用次数最高的内容包；要人工精选需要一个编辑入口。线上现在还没有已发布的内容包，这一栏是空的。

## 8. 怎么读设计稿的标注

`社区与小伴AI 手机原型.html` 是打包文件：里面 `__bundler/manifest` 存着每个画板（base64 + gzip 的 HTML），`__bundler/page_order` 是顺序，`__bundler/template` 里按标题对应画板。解开后每个画板是 `<x-dc>` 加一段 `class Component extends DCLogic`，**数据、交互、颜色、尺寸、示例文案都在这段脚本和 inline style 里**。用 Python 读出来、把长 SVG 路径折叠掉就能看。PNG 压缩包只是渲染图，细节不全。
