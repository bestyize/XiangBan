# 可独立交付的任务单

这里的任务单都是**自包含**的：整份贴给任何能写代码的 AI 或工程师就能开工，不需要读仓库其余部分。每份对应仓库里一个新建的目录，彼此不重叠，可以并行。

| 任务单 | 产出 | 目录 | 需要什么环境 |
| --- | --- | --- | --- |
| [任务单_本机语音服务库](任务单_本机语音服务库.md) | OpenAI 兼容语音接口加 MCP 服务 | `libs/voice-service` | 已交付并合入 |
| [任务单_A_外部Agent适配层](任务单_A_外部Agent适配层.md) | 统一接口驱动 Codex 与 Claude Code | `libs/agent-bridge` | Rust；有 Codex CLI 与 Claude Code 更好（可选真实测试） |
| [任务单_B_hooks安装器与事件接收](任务单_B_hooks安装器与事件接收.md) | 往 Claude Code 配置里装 hooks、本机接收事件、向运行中的会话注入指令 | `libs/agent-hooks` | Rust |
| [任务单_D_模糊测试与加固](任务单_D_模糊测试与加固.md) | 对已合入的三个组件的输入解析做模糊/属性测试，实测高采样率音频的 CPU 预算和 WebSocket 帧上限，并最小修复 | 各库的 `tests/` | Rust；Postgres（部分用例需要） |

## 贴给 AI 的开场白

```
下面是一份完整的任务单。请严格按它交付：
- 不确定的接口细节先查官方文档或用本机命令核实，查不到就在交付说明里列为“待确认”，不要凭记忆编造；
- 只修改任务单允许的目录；
- 能运行测试就运行，并贴出原始输出；没有执行环境就明确写“未运行”，不要写“应该通过”；
- 交付时按任务单最后一节的格式说明。

（把任务单全文贴在这里）
```

## 谁来验证

AI 自己写的“通过”不能直接信。交付后让本地有 Rust 工具链的人（或本地 AI）在干净的检出里跑一遍 `cargo test` 和 `cargo clippy --all-targets -- -D warnings`，再对照任务单的验收标准逐条核对。
