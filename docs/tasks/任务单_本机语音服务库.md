# 任务单：本机语音服务库（`xiaoban-voice-service`）

这份任务单**自包含**：交给任何能写 Rust 的 AI 或工程师，不需要读仓库其余部分。产出是一个独立的 Rust 库，放在 `libs/voice-service/`。识别、朗读、麦克风、播放都通过 trait 注入，所以全部功能可以用假实现完整测试，不需要 Tauri、GTK、麦克风或网络。

## 1. 背景（只需要知道这些）

“小伴”是一个桌面应用，已经有两项本地能力：

- **识别**：SenseVoice Small（中文效果好），输入是 **16 kHz、单声道、f32 采样（范围 -1.0..1.0）**，单段最长 **20 秒**（320000 个采样），输出一段文字。
- **朗读**：Edge 朗读服务，输入文字、音色名（如 `zh-CN-XiaoxiaoNeural`）、语速，输出 **mp3** 字节；另有系统语音等备选。

目标：把它们通过**本机 HTTP 服务**开放给 Claude Code、Codex、VoiceMode 之类的工具使用。这个库就是那层 HTTP/MCP 服务，不含识别和朗读本身。

## 3. 需要实现的核心类型与 trait（签名可微调，但语义不变）

```rust
pub enum VoiceError { Busy, Unavailable(String), Unsupported(String), TooLong, InvalidInput(String), Cancelled, Internal(String) }

/// 16 kHz 单声道 f32。
pub struct Pcm { pub samples: Vec<f32> }

pub struct AudioBytes { pub bytes: Vec<u8>, pub mime: String }   // 例如 "audio/mpeg"

pub struct VoiceInfo { pub id: String, pub name: String, pub locale: String, pub gender: String }

#[async_trait::async_trait]
pub trait Transcriber: Send + Sync {
    /// 一次最多这么多采样，库会负责分段。
    fn max_samples(&self) -> usize { 20 * 16_000 }
    async fn transcribe(&self, pcm: &Pcm, language: Option<&str>) -> Result<String, VoiceError>;
}

#[async_trait::async_trait]
pub trait Synthesizer: Send + Sync {
    async fn synthesize(&self, text: &str, voice: Option<&str>, speed: Option<f32>) -> Result<AudioBytes, VoiceError>; // 返回 mp3
    async fn voices(&self) -> Result<Vec<VoiceInfo>, VoiceError>;
}

#[async_trait::async_trait]
pub trait Microphone: Send + Sync {
    /// 开麦，直到判断用户说完（由实现决定）或超过 max_secs，返回这段话的音频。
    /// 麦克风被占用时返回 Busy。
    async fn listen(&self, max_secs: u32) -> Result<Pcm, VoiceError>;
}

#[async_trait::async_trait]
pub trait Speaker: Send + Sync {
    /// 在本机播放一段音频，播完才返回。
    async fn play(&self, audio: AudioBytes) -> Result<(), VoiceError>;
}

#[async_trait::async_trait]
pub trait Consent: Send + Sync {
    /// 某个客户端第一次使用某项能力时询问用户。库会缓存“已允许”的结果（按客户端标识+能力）。
    async fn allow(&self, client: &ClientInfo, capability: Capability) -> bool;
}
pub enum Capability { Transcribe, Synthesize, Listen, Speak }
pub struct ClientInfo { pub name: String, pub user_agent: Option<String> }

pub struct Backends { pub transcriber: Arc<dyn Transcriber>, pub synthesizer: Arc<dyn Synthesizer>,
                      pub microphone: Option<Arc<dyn Microphone>>, pub speaker: Option<Arc<dyn Speaker>>, pub consent: Arc<dyn Consent> }
pub struct ServerConfig { pub bind: SocketAddr /* 默认 127.0.0.1:0 */, pub token: String, pub allowed_origins: Vec<String>, pub max_body_bytes: usize /* 默认 25 MiB */ }
pub struct RunningServer { pub addr: SocketAddr, /* shutdown() 优雅关闭 */ }
pub async fn start(config: ServerConfig, backends: Backends) -> Result<RunningServer, std::io::Error>;
```

## 4. 第一阶段：OpenAI 兼容接口

与 OpenAI 的音频接口格式一致，使现成工具把 `base_url` 指过来就能用。所有请求都要通过 §6 的鉴权。

### `POST /v1/audio/transcriptions`
- `multipart/form-data`：`file`（必填，音频）、`model`（必填，**任意字符串都接受并忽略**）、`language`（可选，如 `zh`）、`prompt`（可选，忽略）、`response_format`（可选：`json` 默认、`text`；`verbose_json`/`srt`/`vtt` 返回 400 `unsupported_response_format`）。
- 音频解码：**必须支持 WAV（PCM16、PCM24、float32）、MP3、FLAC、OGG Vorbis**（推荐 `symphonia`）。不支持的格式（如 WebM/Opus、M4A）返回 **415**，错误信息里列出支持的格式。转成 16 kHz 单声道 f32（多声道取平均，重采样用 `rubato` 或自己实现并测试）。
- 长音频：超过 `transcriber.max_samples()` 时分段，**切点选在邻近的能量最低处**（在目标边界前后各 1.5 秒内找），依次识别后用空格或不加分隔（中文）拼接——按 `language` 决定：`zh*` 不加空格，其余加空格。总时长上限 10 分钟，超过返回 413 `audio_too_long`。
- 空音频或时长不足 0.1 秒：返回 400 `audio_too_short`。
- 成功：`json` → `{"text": "..."}`；`text` → `text/plain; charset=utf-8`。

### `POST /v1/audio/speech`
- JSON：`{"model": 任意, "input": 文字, "voice": 音色, "response_format": "mp3"(默认)|"wav", "speed": 0.25..4.0 可选}`。
- `input` 为空返回 400；超过 4000 字符返回 400 `input_too_long`。
- `voice` 不传用 `voices()` 的第一项；传了但不在列表里返回 400 `unknown_voice`，并在错误里列出前 10 个可用音色。OpenAI 的内置音色名（`alloy`、`nova` 等）统一映射成默认音色，不报错。
- 成功：`mp3` 直接转发合成器的字节，`Content-Type: audio/mpeg`；`wav` 需要把 mp3 解码再封成 PCM16 WAV，`Content-Type: audio/wav`。

### `GET /v1/audio/voices`（非标准，便于查看）
返回 `{"voices": [{"id","name","locale","gender"}]}`。

### 错误格式
OpenAI 风格：`{"error": {"message": "...", "type": "invalid_request_error", "code": "..."}}`，HTTP 状态码：400 参数错、401 缺令牌或令牌错、403 Origin/Host/拒绝授权、413 太大/太长、415 格式不支持、429 忙（`VoiceError::Busy`，带 `Retry-After: 2`）、503 后端不可用。

### `GET /health`
不需要令牌，只返回 `{"ok": true}`，用于客户端探测服务是否在。

## 5. 第二阶段：MCP

第一阶段完成并通过验收后再做。先**查官方 MCP 规范的最新版本**（modelcontextprotocol.io），确认 Streamable HTTP 传输的细节，不要凭记忆写。要求：

- 在同一个服务上提供 `POST /mcp`（Streamable HTTP，JSON-RPC 2.0）：`initialize`、`tools/list`、`tools/call`，以及规范要求的 `notifications/initialized`、`ping`。令牌鉴权同 §6。
- 工具：
  - `speak { text, voice? }`：用合成器生成并用 `Speaker` 本机播放，播完返回 `{"spoken": true}`。
  - `listen { max_seconds? (默认 15，最大 30) }`：`Microphone::listen` 后识别，返回 `{"text": "..."}`；没说话返回空字符串，不报错。
  - `converse { text, voice?, max_seconds? }`：先 `speak` 再 `listen`。
  - `notify { text }`：播放一句提示，不等待回答，立即返回。
- 麦克风或扬声器没提供（`None`）时，对应工具在 `tools/list` 里不出现。
- 另提供一个很薄的二进制 `xiaoban-voice-mcp-stdio`（`src/bin/`）：把 stdio 上的 JSON-RPC 转发到上面的 HTTP 端点，给只支持 stdio 的客户端用；通过命令行参数或环境变量 `XIAOBAN_VOICE_URL`、`XIAOBAN_VOICE_TOKEN` 取地址和令牌。
- `Busy` 映射成工具错误（`isError: true`，文字说明“麦克风正被占用”），不要让调用卡住；每个工具调用有超时。

## 6. 安全要求（必须全部做到并有测试）

1. **只绑本机**：`ServerConfig.bind` 若不是回环地址（127.0.0.0/8 或 ::1），`start` 直接返回错误。
2. **令牌**：除 `/health` 外，所有接口要 `Authorization: Bearer <token>`；用常量时间比较；令牌少于 24 个字符时 `start` 返回错误。没有令牌或不对返回 401，不泄露细节。
3. **防网页攻击（DNS 重绑定与跨站）**：
   - 校验 `Host`：只接受 `127.0.0.1`、`localhost`、`[::1]`（带或不带端口）；
   - 有 `Origin` 头的请求，只有在 `allowed_origins` 里才放行，否则 403；没有 `Origin`（命令行工具）放行；
   - 不加 `Access-Control-Allow-Origin: *`；预检（OPTIONS）默认拒绝，除非 Origin 在白名单里。
4. **同意**：每个新的 `ClientInfo`（以 User-Agent 或 `X-Client-Name` 头区分，取不到就记为 `unknown`）第一次使用某项能力，调用 `Consent::allow`；拒绝返回 403 `consent_denied`；允许后在内存里缓存（进程重启失效）。`allow` 超过 30 秒没回答按拒绝处理。
5. **限制**：请求体上限 `max_body_bytes`；同时进行的识别最多 2 个，超出返回 429；`listen` 同一时间只允许 1 个，其余返回 429 `busy`。
6. **不落盘、不外传**：库本身不写任何音频到磁盘，不发起任何出站网络请求；日志里不记录请求体、令牌和识别出的文字（只记路径、状态码、耗时、大小）。

## 7. 测试要求（都用假实现，`cargo test` 一条命令跑完）

至少覆盖：
- 鉴权：无令牌、错令牌、对的令牌；`/health` 免令牌。
- `Host` 非法（如 `evil.com`）→ 403；`Origin` 不在白名单 → 403；无 `Origin` 放行；OPTIONS 预检默认拒绝。
- 绑定非回环地址、令牌太短 → `start` 报错。
- 转写：WAV（PCM16、float32）、MP3、FLAC、OGG 各一个**程序生成的**小样本（不要提交大文件，可在测试里用 `hound` 等生成 WAV，其他格式用小的内嵌字节）；立体声转单声道；44.1 kHz 重采样到 16 kHz（用正弦波验证频率和时长，不要只验证“没报错”）；不支持的格式返回 415；过短、过长的音频；`response_format` 的 `json`/`text`/不支持。
- 分段：用假转写器记录收到的每段长度，验证每段 ≤ `max_samples`、总采样数守恒、切点落在能量低处（构造“中间有静音”的信号）、中文拼接不加空格。
- 朗读：默认音色、指定音色、未知音色、OpenAI 内置音色名映射、空文本、超长文本、`wav` 输出能被解码回采样。
- 同意：第一次拒绝、第一次允许后缓存、超时按拒绝。
- 并发限制：同时发起超过 2 个识别 → 第 3 个 429；`listen` 并发。
- 错误映射：`VoiceError` 各变体对应的状态码与 JSON 格式。
- MCP（第二阶段）：`initialize`/`tools/list`/`tools/call` 的完整流程；无麦克风时 `listen` 不在工具列表里；`Busy` 的工具错误；stdio 转发二进制的往返。
- 日志不含敏感内容（可以用一个收集日志的 subscriber 断言）。
