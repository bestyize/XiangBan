# Android 执行性能优化：第一阶段

## 问题与本轮范围

原实现每次语义点击约6–7次 ADB 客户端调用，多次设备枚举、前台查询和 UI dump，加上每步模型往返，无法据首次联调证明生产可用。

本轮先实现任务内每设备常驻 ADB Shell，以及包内结构化工作流的本地执行。用户后续要求暂不使用小米17测试，因此以下新机制仅进行本地单元、内存设备模型及 Python 标准库协议模拟；未测真实手机耗时，也未安装或切换任何手机软件。

## 交付

- 非PTY Shell按设备绑定，随机请求标记区分响应，逐设备串行。显式设备通道替代每次 devices -l；错误后关闭，不回放已派发请求。截图/配对/文件传输仍独立运行。
- YAML DSL 放在既有 basic/tasks/，同路径 patch/ 可修正，版本和有效期继续生效。审查后固定内容摘要，执行时核对真实 APP 版本；更改后必须重新审查。
- typed steps 限定为 launch、wait、tap、fill、verify_fields、yield。没有任意 Shell、插件脚本或重放循环。
- 已知页面在一次工具调用内运行，不逐步调用模型。等待目标状态、复用新鲜观察、输入前检查前台、确认编辑焦点、字段回读及最终整体核对继续执行。异常返回 checkpoint 给模型，动作结果未知不自动继续。
- 小红书分为“从首页到相册”与“选图后准备正文”两段。相册缩略图缺乏可靠语义标记，主动交回模型识别，避免把未知素材选择硬编码为第一张。
- 记录整体/每步耗时、命令数、启动数和复用数，便于后续测量；模型调用数0仅指本地执行器内部，不包含审查、选图和异常处理。

## 验证与后续验收

本地测试验证4条模拟 Shell 命令只启动1个本地客户端；导航流程复用相邻 wait/tap 观察；准备工作流完成中文标题、长正文及换行填写核对，未触发提交。覆盖错误版本、摘要变化、前台切换、断连与取消。

仍待后续授权真机测量：冷启动/热执行 P50/P95，单步读取/输入及整体图文准备耗时、图片索引与选图延迟、取消到停止延迟、不同网络条件和系统版本。

uiautomator 的进程启动与空闲等待、完整截图编码/传输、视觉模型及游戏棋盘识别开销尚未消除。下一阶段可评估常驻 UiAutomator/无障碍服务与画面流，在保留前台和目标状态检查的同时减少跨层往返。
