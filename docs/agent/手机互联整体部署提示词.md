# 手机互联整体部署提示词

手机互联会用到四个线上服务：账号中心、AI 网关（server-ai）、论坛（server-forum）、新增的中转（server-link）。把下面“提示词”整段交给负责部署的 AI（需要它能 SSH 到服务器、能用 Docker、systemd 和 Nginx）。只部署中转时用 [server-link部署提示词](server-link部署提示词.md)。

部署前你准备好：服务器 SSH 访问、域名解析、（可选）测试账号的访问令牌——没有也能完成部署，带令牌的验证项会标成“跳过”，由你最后用真机验证；令牌只有约 30 分钟有效，要给的话等 AI 报告“已部署，等待验证”时再给，最好连同 refresh_token 一起；不要给密码；AI 网关管理后台的管理员登录方式（你自己登录，或把后台操作交给 AI 前先确认）。

## 提示词

```text
你是一名运维工程师。任务：为“小伴手机端 + 手机与桌面互联”这个功能，把四个线上服务调整到可用状态。仓库是 bestyize/XiangBan（main 分支）。先读这几份文件再动手，以它们为准：
- docs/deployment/MOBILE_LINK_ROLLOUT.md（整体顺序、每一步的要求与检查方法）
- docs/deployment/LINK_DEPLOYMENT.md、docs/deployment/ACCOUNT_CENTER_DEPLOYMENT.md
- services/server-link/README.md、services/server-forum/README.md（末尾“部署”一节）、services/server-ai/README.md
- infra/link/（compose、环境模板、Nginx 示例）

总原则：
1. 先盘点，再动手。先用 docker ps、systemctl、ss -ltnp、nginx -T 查清服务器上这四个服务现在各自是什么状态（是否已部署、版本、端口、域名、部署方式）。注意 server-ai、server-forum、小伴市场的默认端口都是 55010，同机时不能冲突。盘点结果先整理成表发给我，不确定的地方问我，不要猜。
2. 每个服务独立处理，互不改动对方的数据卷、数据库和配置。动已有服务（账号中心、论坛、AI 网关）之前，先备份它的数据库和 .env（或 systemd 环境文件），并告诉我会重启哪个服务、预计中断多久，等我确认后再执行。
3. 任何密钥、令牌、密码都不要打印到日志、聊天记录或提交到仓库；验证用的令牌只在我主动提供时使用（测试账号的访问令牌，aud 为 xiaoban-android），贴结果时打码。
令牌说明：访问令牌只有约 30 分钟有效，且由用户登录后手工提供，默认不提供。没有令牌时，所有“带令牌”的验证项一律标记为“跳过，由用户用真机验证”，不要向我索取，也不要自己创建账号或想办法绕过；只做不需要令牌的验证。如果我主动给了令牌（可能连同 refresh_token），那就在一次连续操作里把带令牌的验证项跑完；令牌过期时，若我给了 refresh_token，就用 POST https://account.xiangban.xyz/api/auth/refresh（{"refresh_token":"…","client_id":"xiaoban-android"}）换新的，没给就停下来告诉我，不要反复催。
4. 不要改仓库代码。发现文档与现实不一致，只记录并报告。

按下面顺序做，每一步验证通过再进行下一步：

步骤 1 账号中心：线上版本必须登记了客户端 xiaoban-android（新版本默认内置；旧版本升级，或在其 .env 的 ACCOUNT_CLIENTS 里补 xiaoban-android:小伴手机应用 后重启）。ACCOUNT_ISSUER 绝不能改。检查：POST /api/auth/password/login，client_id=xiaoban-android，用一个不存在的账号：返回 401 说明已登记，返回 400 说明没登记。
步骤 2 AI 网关（server-ai）：先确认 https://ai.xiangban.xyz 线上是否真的有这个服务。如果有：在管理后台“产品与档位”里把 xiaoban-android 加进现有小伴产品的 client_ids（与 xiaoban-desktop-wallpaper 同一个产品；一个客户端只能属于一个产品，加之前确认它没出现在别的产品里）。这一步是后台数据操作，请我登录后台或在我确认后用管理接口完成。如果线上没有这个服务：停下来告诉我，不要自行部署（它依赖 New API 网关和一整套后台配置）。检查：用 aud=xiaoban-android 的令牌调用 GET /api/ai/tiers 和 GET /api/ai/balance 返回 200，而不是 403。
步骤 3 论坛（server-forum）：发布包含 FORUM_ACCOUNT_EXTRA_CLIENT_IDS 的新版本（默认值已是 xiaoban-android，不需要改环境变量）。部署方式见其 README 末尾：香港机 /home/ubuntu/xiangban-forum，systemd 服务 server-forum，本地或构建机交叉编译后替换二进制和 web/dist，再重启服务。二进制必须在与服务器匹配的 Linux x64 环境编译，不要上传 Windows/macOS 的产物。检查：启动日志里有 extra_clients=["xiaoban-android"]；用 aud=xiaoban-android 的令牌调用 GET /api/me/points 返回 200；网页端登录和发帖仍然正常；aud 为其他值的令牌仍返回 401。
步骤 4 互联中转（server-link，新服务）：严格按 docs/agent/server-link部署提示词.md 里的“提示词”执行，包含它的全部验证项。镜像来自 GitHub Actions “BuildXiaoBanWallpaper”（勾选 package_server_link，可取消 build_release）产出的 xiangban-link-<标签>.tar.gz。
步骤 5 汇总：把四个服务的最终状态、版本/镜像标签、端口、Nginx 文件路径、备份与回滚方法整理成一页发给我，并列出你发现的所有与文档不一致之处。

约束：只做以上事项；不要重启或改动与此无关的服务；任何一步失败，先回滚到该步骤开始前的状态再报告，不要带着半成品继续。
```

## 部署完成之后

按 [MOBILE_LINK_ROLLOUT.md](../deployment/MOBILE_LINK_ROLLOUT.md) 第 5 节做真机联调：手机登录同一账号，云端聊天、社区登录操作、在“我的电脑”里遥控电脑、批准一次权限。
