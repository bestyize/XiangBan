# 小伴 Agent 第二阶段开发与验收清单

> 规划基线：2026-10-21。下文的已有/待建、任务勾选和建议指标保留当时语境，未持续同步为当前进度；当前实现入口见 [目录 README](README.md#当前实现入口)。

> **用途**：可复制到 GitHub Issue、交给编码 AI 或作为每次 PR 的完成检查。  
> **状态说明**：下列 `- [ ]` 表示**待核实/待交付**，不意味着当前代码完全不存在该能力。开工前先核实仓库现状。  
> **原则**：不把“代码实现完成”当作“任务效果通过验收”。

## A. 先建立一条能被验证的任务链（P0）

- [ ] 核对当前主分支及 `agent-kernel`、`agent-tools`、`chat/mod.rs`，记录版本与已有接线。
- [ ] 选择首个用户场景：建议 PDF 发票整理或批量文件命名，固定输入和预期输出。
- [ ] 构建首批可重复任务样本，并明确哪些任务会真实修改文件。
- [ ] 确立 `task_id`、`run_id`、`session_id` 和父子关联关系；复用 Kernel 既有 `RunEvent`。（已开始接入 `run_id`/`session_id` 运行日志；`task_id` 尚待设计和验收）
- [ ] 在桌面 Runtime 贯通结构化运行事件、ToolDispatched、ToolResult、结束状态及错误分类。
- [ ] 记录执行意图和实际业务结果，不能把已派发动作等同完成。
- [ ] 引入 `TaskOutcome`：`succeeded / failed / partial / cancelled / unknown`。
- [ ] 首批任务实现外部 Validator 和证据链接；失败、未知、用户取消状态可正确重现。
- [ ] 测试已派发未落盘、进程崩溃、重复尝试、用户撤回授权等边界。

**A 的验收**：同一任务能复现运行、获取可读轨迹、正确分类最终结果；未知外部写操作不会自动重放。

## B. 结构化经验数据基础（P0）

- [ ] 选择 Rust SQLite 集成方式，核实构建依赖与目标平台兼容性。
- [ ] SQLite 使用用户数据目录；初次启动初始化，已有用户升级执行有版本的迁移。
- [ ] 验证 FTS5 编译选项与中文检索效果；必要时引入明确的中文分词/预处理策略。
- [ ] 仅将必要元数据放 SQLite，原始历史和 Skill 保持既有格式。
- [ ] 创建最小任务结果、经验候选与评测数据结构；加入作用域、来源、状态和更新时间。
- [ ] 支持撤销、删除、失效知识清理，以及索引与派生缓存同步更新。
- [ ] 实测并记录 macOS ARM64 / Windows x64 安装包与主程序体积差异。
- [ ] 记录 SQLite 文件权限、备份、恢复、WAL 与存储大小限制。

**B 的验收**：旧用户数据不丢失，升级/回滚行为有说明；跨会话查询正确；卸载/撤销经验不会遗留可检索副本。

## C. Find Skills（P1，第二阶段的可见价值）

- [ ] 对每个来源核验真实公开接口和许可，不使用猜测的 API。
- [ ] 完成搜索、详情检查、安装批准、安装、加载、更新和卸载。
- [ ] 在安装前显示文件清单、来源、版本、校验及权限风险。
- [ ] 校验路径穿越、符号链接、外部脚本及隐式依赖下载。
- [ ] 任何新 Skill 不因安装而获得权限放行。
- [ ] 安装元数据存于可信位置，Skill 内自述 origin 不作为信任凭据。
- [ ] 记录安装失败与用户拒绝时的清理/回滚行为。

**C 的验收**：从真实来源安装一个无害 Skill 并成功调用；危险样本被阻止，拒绝安装不留下半成品。

## D. Experience Learning 与 Memory Retrieval（P1）

- [ ] 经验候选必须关联任务来源、外部证据及适用范围。
- [ ] 区分观察、假设、已验证、已否决，不把所有对话总结自动存入长期记忆。
- [ ] 从用户纠正生成候选规则，并提供查看、修改和拒绝入口。
- [ ] 检索只装入相关记忆，不自动跨工作区泄露。
- [ ] 合并重复项；检测冲突、过时信息以及用户已否定信息。
- [ ] 后台 Reflection 有独立资源预算，不阻塞前台主对话。
- [ ] 用户关闭学习后不再触发新的学习任务，并能管理已留存资产。

**D 的验收**：在新会话中准确复用一条已确认规则；无关规则不影响任务；撤销后不可继续检索到旧规则。

## E. Skill Evolution 与严格评测（P1）

- [ ] 建立同模型、同工具、相同任务条件下的 baseline。
- [ ] 候选 Skill 保留原版和所有变更理由。
- [ ] 固定回归集、独立留出集，避免用训练样本自证成长。
- [ ] 评测结果包含任务成功率、耗时、Token 成本、安全行为和人工干预。
- [ ] 候选退化、证据不足或触发越权时不得晋升。
- [ ] 通过后按策略批准升级；确保一键回滚到最后稳定版。
- [ ] 每次模型升级后重新评测相关 Skill 的适用性。

**E 的验收**：提供一份 A/B 实验记录；至少一个真实任务集证明学习资产产生可重复的正向收益，且没有严重回归。

## F. 安全与体验（贯穿 A–E）

- [ ] 展示和管理 Skill 安装、模型联网、长期记忆和后台学习权限。
- [ ] 远程 Skill、网页、文件与工具输出均按不可信来源处理。
- [ ] 高风险文件/系统变更事前预览，支持取消或补偿操作。
- [ ] 敏感内容遵守最小保存、最小外发和最小显示原则；SQLite 默认不是加密存储。
- [ ] 学习任务有最大频率、队列长度、Token/费用、CPU/存储预算。
- [ ] 可通过 UI 查看“成长记录”：来源、变化、是否生效、撤销入口。
- [ ] 不把“模型称自己学会了”作为成功文案；展示可验证结果。

## G. 阶段 II 退出评审（必须全过）

- [ ] **新能力**：找得到、审得清、装得安全、用得起来。
- [ ] **任务结果**：有独立证据证明成功；无法证明就不宣称完成。
- [ ] **历史经验**：跨会话检索正确、作用域清晰、可修改和撤销。
- [ ] **学习效果**：一项真实场景的独立任务集呈现稳定收益。
- [ ] **受控进化**：新 Skill 经评测才晋升；坏版本可以回滚。
- [ ] **安全成本**：无严重越权，后台成本处于预定预算内。

## H. 后续阶段实验（不阻塞第二阶段交付）

### 阶段 III — 主动式 AI

- [ ] 只在授权范围内接收低成本事件（文件变动、任务中断等）。
- [ ] 先实现 L2 主动建议，而不是默认自动执行或持续全屏观察。
- [ ] 统计建议接受率、误打扰率、实际节省时间与关闭率。

### 阶段 IV — Evolving Expert / AOE

- [ ] 为一个窄领域专家建立能力图谱与独立评测集。
- [ ] 对比通用 Agent 与带有专业资产的单专家；衡量真实成长。
- [ ] 单专家确实优于基线后，再测试多专家协作收益。

> **执行顺序建议**：先 A，再 B；C 与 D 可小范围并行，E 必须建立在 A/D 的证据之上。不要先为尚未验证的专家团建立过多基础设施。
