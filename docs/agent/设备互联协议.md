# 设备互联协议 v2（同账号直连）

状态：2026-10-29。对应 [实施计划_手机桌面互联](../product/实施计划_手机桌面互联.md)。

**一句话**：用同一个小伴账号登录的手机和电脑，自动互相看到对方，经中转服务转发文本消息。**没有配对、没有二维码、没有设备密钥、没有端到端加密。**

这是一个简单的论坛和小工具，不是金融服务，所以把安全边界放在账号上：能拿到你账号令牌的人，本来就能登录你的论坛账号；能登录你电脑上的小伴，才能遥控电脑。我们不再另外设计一套密钥体系（旧版 v1 的配对 + P-256 + AES-GCM 方案已整体删除）。需要注意的代价见 §6。

## 1. 角色

| 角色 | 说明 |
| --- | --- |
| 桌面（desktop） | 电脑上的小伴。会话、记忆、权限的唯一来源，也是执行者。用户在设置里打开“允许手机遥控”才会连上中转（默认关闭） |
| 手机（phone） | Android 小伴。登录后自动连上中转，遥控同账号下的电脑 |
| 中转（server-link） | 独立服务。校验账号令牌、记同账号下有哪些设备、转发文本消息、报在线状态。**能看到消息内容**，但不存历史 |

规则：

1. **同账号、不同类型互为对端**：同一个 `uid` 下，电脑的对端是手机，手机的对端是电脑。不同账号永远互相看不到。
2. 手机发来的指令视为“远程来源”：**开发阶段便利优先**：手机新建的对话默认就是“完全信任”（执行不再逐项问），用户可以在手机上随时切回“默认权限”（见 `session.permission`）；无论哪种，高风险操作（删文件、危险命令等）仍然每次都问。上线前要改回默认权限，并考虑在桌面加总开关。已有对话的模式不会因为手机发了消息而被改动。
3. 任何未知字段、未知消息类型一律忽略（回 `unsupported`），保证新旧版本互不崩溃。

## 2. 设备登记

认证：`Authorization: Bearer <账号访问令牌>`，服务离线验签（与 server-ai 同一套 JWKS 方式）。WebSocket 设不了请求头时，令牌可放在子协议里：`["xb-link", "xiaoban-token.<令牌>"]`。

| 接口 | 说明 |
| --- | --- |
| `POST /api/link/devices` | `{kind: "desktop"\|"phone", name, install_id}` → `{device_id, created}`。`install_id` 是客户端首次运行时随机生成的 16–64 位字母数字（可含 `-` `_`）串并持久化，**同一账号同一 `install_id` 幂等**，所以重启、重装后重新登记拿回的是同一个设备编号 |
| `GET /api/link/devices` | 自己名下未移除的设备与在线状态 |
| `GET /api/link/peers?device_id=` | 这台设备的对端列表（含在线状态）；设备不属于当前账号或已移除时 404 |
| `DELETE /api/link/devices/{id}` | 移除设备：通知对端 `peer.removed`，并向该设备推 `error{device_revoked}` 后断开 |
| `GET /api/link/ws?device_id=` | WebSocket，见 §3 |
| `GET /api/link/health` | 健康检查 |

错误统一 `{ "code": "…", "message": "…" }`：`unauthorized`、`not_found`、`too_many_devices`（每账号默认最多 20 台）、`bad_request`。

**设备被移除或换了账号**：设备拿旧编号请求会得到 404（或收到 `device_revoked`）。客户端此时清除本地设备编号、换一个新的 `install_id`，重新登记成一台新设备——不会把被移除的设备“复活”。

## 3. WebSocket

连接后服务端先发 `ready`，再发一次完整的 `peers` 列表，随后按变化增量通知。

服务端 → 设备：

| `op` | 内容 |
| --- | --- |
| `ready` | `{device_id, server_time}` |
| `peers` | `{items:[{id, kind, name, online}]}` 连接后发一次：同账号下全部对端 |
| `peer.added` | `{device:{id, kind, name, online}}` 有新对端登记或改名（不需要重连就能看到） |
| `peer.removed` | `{device}` 对端被移除 |
| `presence` | `{device, online}` 对端上线/下线 |
| `deliver` | `{from, data}` 对端发来的文本；`from` 由中转按认证后的设备填写，不能伪造 |
| `undelivered` | `{to, reason}` 你发的消息没送达（对端离线且没标 `notify`） |
| `error` | `{code}`：`replaced`（同一设备在别处连接，本连接被顶替，不要自动重连）、`device_revoked`、`unknown_peer`、`payload_too_large`、`rate_limited`、`bad_frame`、`text_only`；严重的随后断开 |
| `pong` | 回应 `ping` |

设备 → 服务端：

| `op` | 内容 |
| --- | --- |
| `send` | `{to, data, notify?}`：`data` 是文本（JSON 字符串即可），不超过 256 KiB；`to` 必须是自己的对端 |
| `ping` | 保活；服务端回 `pong`。空闲 25 秒发一次 |

连接上只接受文本帧，单帧上限 512 KiB。

### 3.1 离线与限流

- 对端离线时，只有 `notify: true` 的消息会暂存，每个对端最多 50 条、24 小时过期；对端上线后按序补发。其他消息直接回 `undelivered`。**指令类消息不要加 `notify`**，避免电脑上线后执行过时的指令。
- 限流（可配置，初值）：每连接 30 条/秒、1 MiB/秒。
- 中转的日志和数据库不记录消息内容，只记设备编号、大小、时间、结果。

## 4. 应用消息（`data` 字段里的文本）

UTF-8 JSON 对象，公共字段：`t`（类型）、`id`（发送方生成的消息编号，用于幂等和回执）。

| `t` | 方向 | 字段（要点） | 说明 |
| --- | --- | --- | --- |
| `hello` | 双向 | `v`（协议版本）、`caps`（能力列表）、`app`（应用版本） | 连接后各发一次；协商取共同能力 |
| `sessions.list` | 手机→桌面 | `limit`、`cursor?` | 请求会话列表 |
| `sessions.page` | 桌面→手机 | `items:[{id,title,updated_at,state,workspace}]`、`cursor?` | 回应。`workspace` 是这个对话在电脑上的工作文件夹（手机上叫“项目”），老对话可能为空串；`updated_at` 是秒 |
| `sessions.changed` | 桌面→手机 | `items`（增量，字段同上） | 列表变化 |
| `projects.list` | 手机→桌面 | — | 要电脑上最近用过的文件夹（能力 `projects`） |
| `projects.page` | 桌面→手机 | `recent:[{path,name}]` | 只含仍存在、范围不算太宽（不是磁盘根目录、主目录这类）的文件夹。手机浏览不了电脑上的文件，新项目只能从这里选 |
| `session.open` | 手机→桌面 | `session`、`after?`（已有的最后一条消息编号） | 打开会话并订阅事件 |
| `session.snapshot` | 桌面→手机 | `session`、`messages`（精简投影：角色+文本；助手消息带 `reasoning`（思考文字）和 `tool_calls`（含 `id`、`name`、参数，截断）；工具结果消息带 `tool_call_id`、`is_error` 和结果文字（截断）。不含系统提示词/图片地址）、`state`、`pending`、`after`（本页起点）、`cursor`（下一页起点）、`has_more` | 当前内容，按字节预算分页（每页约 120 KiB，单条文本最多 20000 字）。`has_more` 为真时手机用 `session.open{after: cursor}` 取下一页；`pending` 只在最后一页作准（没有待审批即收起手机上的旧卡片） |
| `session.close` | 手机→桌面 | `session` | 取消订阅 |
| `run.undo` | 双向 | 手机→桌面：`session`、`run_id`（来自事件 `checkpoint`）；桌面→手机（回应）：`ok`、`restored`/`removed`/`failed` 或 `error` | 撤销某一轮回答用文件工具改过的文件（和桌面“撤销这些改动”一样；对话还在回答时、已撤销过都会失败） |
| `models.list` | 双向 | 手机→桌面：`session?`；桌面→手机：`ok`、`models`（`provider`、`provider_name`、`id`、`name`）、`current`（`provider`、`model`） | 电脑上各个已配置服务商的可选模型，加当前对话在用的 |
| `session.model` | 双向 | 手机→桌面：`session`、`provider`、`model`；回应：`ok` 或 `error` | 切换这个对话的模型；只允许 `models.list` 列出来的，对话还在回答时不行 |
| `library.save` | 双向 | 手机→桌面：`text`、`title?`、`session?`、`session_title?`；回应：`ok`、`item` 或 `error` | 把一条回复存到电脑的资料库（来源记为 phone；同一段文字同一对话只存一份） |
| `message.cancel` | 手机→桌面 | `session` | 停止这个对话正在跑的一轮（和电脑上点“停止”一样）；没有在跑就什么也不做。没有回复，结果通过事件 `state: cancelled` / `turn.done` 看到 |
| `session.permission` | 双向 | 手机→桌面：`session`、`mode`（`ask` 默认权限 / `auto` 完全信任）；桌面→手机（回应）：`session`、`ok`、`mode` 或 `error` | 切换这个对话的权限，和桌面聊天页上的开关是同一个。外部 Agent 任务（`del-` 开头）不能切换，对话已删除也会失败。桌面上改了权限或手机改成功后，桌面还会给订阅了该对话的手机发 `event{kind:"permission", data:{mode}}`；`session.snapshot` 里也带 `permission` |
| `message.send` | 手机→桌面 | `session?`（空则新建）、`workspace?`、`permission?`、`text`、`client_id` | `client_id` 用于幂等；桌面回 `message.accepted`。`workspace` 只在新建对话（没带 `session`）时有效，是新对话的项目文件夹，必须是电脑已知的文件夹（最近用过的，或已有对话在用的），否则回一条 `error` 事件；已有对话的文件夹不能从手机改。`permission`（`ask`/`auto`）同样只在新建对话时有效，是新对话的权限模式，缺省 `auto`（开发阶段） |
| `message.accepted` | 桌面→手机 | `client_id`、`session`、`message_id` | 已写入队列 |
| `event` | 桌面→手机 | `session`、`kind`（`text.delta`/`reasoning.delta`/`tool.start`/`tool.end`/`usage`（`prompt`、`completion`）/`truncated`（回答达到单次输出上限）/`checkpoint`（`run_id`、`files`、`count`：这一轮改了文件，可用 `run.undo` 撤销）/`state`/`turn.done`/`error`/`permission`）、`data` | 流式回复与进度 |
| `approval.request` | 桌面→手机 | `approval_id`、`session`、`title`、`detail`、`risk`（`low`/`high`）、`options`；授权类另带 `tool`、`risk_kind`（`read`/`write`/`network`/`exec`）、`external_path`、`tainted`、`danger?`；提问类带 `kind:"question"`、`question`、`choices`、`free_text`、`connectors?`（连接服务后继续任务，手机上只能跳过） | 待确认。提问的答案走 `approval.decision{choice}`（可以是自己输入的文字；`__dismiss__` 表示跳过） |
| `approval.decision` | 手机→桌面 | `approval_id`、`choice` | 手机的决定；`risk=high` 的卡片红色提示风险并给出完整命令，手机上只给“允许一次”（开发阶段不再额外弹二次确认，上线前要重新评估） |
| `approval.resolved` | 桌面→手机 | `approval_id`、`by`（`desktop`/`phone`/`timeout`/`expired`）、`reason?` | 任一端处理后广播；手机的 `approval.decision` 无法执行（已被处理、已过期、需在电脑上处理）时只回给该手机，`by=expired` |
| `unsupported` | 双向 | `ref`（对应消息编号）、`t` | 不认识的类型 |

约定：
- `text.delta` 之类流式事件无需回执；丢失靠 `session.open` 带 `after` 重新对齐。
- 单条消息上限 256 KiB（`MAX_DATA`），桌面发出前按 240 KiB 控制。事件里的工具参数/输出各截到 8000 字；仍然超限的事件会被换成一条简短的 `error` 事件，不会静默丢弃。
- 只有打开过某会话（`session.open` / `message.send`）的手机才会收到该会话的内容事件；`turn.done` / `error` 这类 `notify` 事件对未打开的手机和离线手机仍会送达，但内容脱敏。
- 所有“手机→桌面”的写操作带 `client_id` 或 `approval_id`，桌面据此幂等。
- 应用层心跳不需要（连接上有 `ping`）；延迟可用 `hello` 往返估计。

## 5. 异常与恢复

| 情况 | 处理 |
| --- | --- |
| 连接断开 | 指数退避重连（1、2、4…最多 30 秒，加抖动）；重连后重新 `hello`，手机对打开的会话重发 `session.open{after}` |
| 没登录 / 令牌取不到 | 不连接，持续重试；登录后自动连上 |
| 被顶替（`replaced`） | 同一台设备在别处连接，停止重连，提示用户 |
| 协议版本不匹配 | `hello` 里 `v` 不兼容时，两端各自提示升级，不继续 |
| 电脑休眠/离线 | 手机收到 `presence{online:false}`，隐藏遥控入口，输入框切回云端小伴 |

## 6. 安全取舍（要知道的）

| 情况 | 结论 |
| --- | --- |
| 中转看得到内容 | 是。中转由我们自己运营，不落盘、不记日志，但被入侵时内容可见，也可能被伪造指令。这是为了简单做的取舍 |
| 账号令牌被盗 | 攻击者能以你的身份登记设备、向你的电脑发指令。**缓解**：桌面“允许手机遥控”默认关闭；手机新建的对话默认逐项确认，高风险操作要在手机上二次确认；用户在手机上主动切到“完全信任”也会写入审计日志（`session.permission`），完全信任下高风险操作（删文件、危险命令等）仍然每次都问；令牌有有效期，账号中心可退出所有设备 |
| 手机丢失 | 在电脑端的手机列表里移除它，或账号中心“退出所有设备”（令牌失效，中转拒绝连接） |
| 拒绝服务 | 中转按连接限流；单条 256 KiB 上限；每账号设备数上限 |
| 同设备被占用 | 持令牌者可用设备编号连上来顶掉真连接造成骚扰 |

如果以后要做付费、支付这类更敏感的功能，再单独评估是否需要端到端加密；那会是新的协议版本，不在本版范围内。
