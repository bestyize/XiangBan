### 3.1 互联 v2 要点

- 注册设备：`POST /api/link/devices {kind,name,install_id}`（`kind` 为 desktop/phone）；同一账号下“另一种设备”互为 peer。
- WebSocket `/api/link/ws`：服务端帧 `ready / peers / peer.added / peer.removed / presence / deliver / undelivered / error / pong`；客户端发 `send{to,data,notify?}`。
- 单条数据上限 256KiB；对端离线只暂存“有新消息”的通知（最多 50 条 / 24 小时），**不暂存内容**。
- **旧客户端不兼容**：server-link、桌面端、手机端必须一起更新（服务端会迁移 `devices` 表、加 `install_id`、作废旧设备；旧的配对表留着不删）。
- 桌面端：设置里“允许手机遥控”开关，默认关；开启必须已登录。远程来源走最严格的权限策略，审批要在手机上点。
- 代码位置：
  - Rust：`services/server-link`（中转）、`libs/link-client`（桌面链接层，`Link`/`LinkConfig`/`FileStore`/`MemoryStore`）、`client/xiaoban-desktop-wallpaper/src-tauri/src/phone_link.rs` + `phone_wire.rs`、前端 `src/ui/components/settings/PhoneLinkCard.vue`。
  - Kotlin：`client/xiaoban-multiplatform/common/link-core`（`PhoneLink.kt`、`RemoteChat.kt`、`LinkState.kt`、`androidMain/SharedPrefsLinkStorage.kt`）。

### 4.1 怎么验证界面（重要）

云端沙箱访问不了 Google Maven，**编译不了 Compose**。两道防线：

1. `tools/compose-typecheck/sync.sh`：用仿制的 Compose/Material3/Coil 接口加真实源码做类型检查，能抓未定义的名字、参数写错、类型不符。**没有输出 = 通过**。局限与首次准备见该目录 README。新用到某个 Compose API 时先在 `stubs/` 里补上真实签名。这个检查通过只说明“按这些签名写是对的”，不等于能编译。
2. 真正的验证：手动运行工作流 `BuildXiaoBanWallpaper`，只勾 `android`（其余关掉），下载 Release `xiaoban-wallpaper-v<桌面版本>` 里的 APK，让用户装机截图。**这一轮的手机界面还没有人在真机上看过。** 预期会有零星的编译错误（导入、实验性 API 标注、Compose 编译器规则）和版面问题，第一次 CI 出错时直接看 `gh run view --log-failed` 对应的步骤修。

## 6. 打包发布

- 入口：GitHub Actions 的 `BuildXiaoBanWallpaper`，**只能手动运行**。输入 `windows`、`macos`、`android`（都默认开）、`servers`（空 / 逗号分隔的服务编号 / `all`）。
- 服务清单与端口、健康检查、部署栈：[`infra/images/services.json`](../infra/images/services.json)；Dockerfile 由 `infra/images/gen-dockerfiles.py` 生成（改了清单后重新生成，`--check` 只检查），单个镜像的本地打包用 `infra/images/build-image.sh <id> <out>`。
- 客户端产物放进 Release `xiaoban-wallpaper-v<桌面版本>`；服务端镜像放进**单独的** Release `server-<UTC时间>-<提交前7位>`（只留最近 5 个）。
- 让本地 AI 通过 SSH 更新线上服务：把 [`docs/agent/发布与更新服务端提示词.md`](agent/发布与更新服务端提示词.md) 交给它。
- Android 签名：配了 `XIAOBAN_ANDROID_KEYSTORE_*` 的 Actions 密钥才出发布签名包；没配出的是 `…-Android-debug.apk`（未签名的 release 包装不上手机）。

## 10. 易踩的坑（本轮新增）

- **Compose 在云端编不了**：不要在沙箱里等 `./gradlew :androidApp:assembleDebug`，它会因 Google Maven 不可达卡住；用 `tools/compose-typecheck`。
- **类型检查抓到过的真错误**：把尾随 lambda 当成 `onAction` 写成了 `modifier`；在带 `statusBarsPadding()` 的顶栏上又加 `height(52.dp)` 会把内容压扁（要套一层 Column，内层 Row 才固定高度）。
- **桌面收件箱的编号字符集**：只允许字母数字和 `-_`，用 `remote_request_id` 生成，不要自己拼冒号。
- **server-link 测试**：`TEST_DATABASE_URL=postgres://用户:密码@localhost:5432/库名 cargo test`（`services/server-link`、`libs/link-client`）；没设会静默跳过，别当成通过。
- **Kotlin 互通测试**：手机 Kotlin ⇄ 真实 server-link ⇄ Rust 桌面端的 `InteropTest` 需要先 `cargo build --example interop_desktop`，再设 `LINK_INTEROP_BIN` 与 `TEST_DATABASE_URL`。云端是在临时 JVM 工程里跑通的，真实 Gradle 工程没跑过。
- **FakeServer 路由顺序**：测试里后注册的路由优先，通用路由要先注册。
- **`rm -rf` 带通配符会被沙箱安全检查拦住**：换个新目录。
