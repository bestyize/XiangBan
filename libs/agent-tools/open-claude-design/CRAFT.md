# 设计稿创作手册（质量要求）

`format` 规定了文件怎么写才能运行，这份手册决定设计稿是否专业、精美。交付的是一份能拿去评审的设计稿，不是线框图。

## 1. create 之前先定方向

用户不必确认，但你要先想清楚，并写进 `canvas.designSystems` 的 tokens：

- **定位**：产品是给谁用的、在什么场景用，由此决定气质（专业克制、温暖亲切、活泼年轻、高端精致）。
- **色板**：一个品牌主色及其浅、深两档；页面背景、卡片表面两级中性色；文字三级（主要、次要、弱化）；边框色；成功、警告、错误三种状态色。
- **字号阶梯**：12 / 14 / 16 / 20 / 24 / 32 / 48，正文 14–16。
- **间距**：4 的倍数（4 / 8 / 12 / 16 / 24 / 32 / 48 / 64）。
- **圆角与阴影**：圆角一到两档，阴影两档（浮起、弹层）。

所有画板都通过 `var(--ds-*)` 使用这些 tokens，不要在各处随手写新颜色和新尺寸。

## 2. 版式

- 桌面画板常用 1440×900 或 1280×800，按 12 栏栅格排布，页面左右边距 64–80px；移动端用 390×844，左右边距 16–20px。
- 每屏只有一个视觉焦点：最重要的数据、主操作或主视觉最大、最醒目，其余内容退后。
- 用间距分组（组内间距小、组间间距大），少用边框和分隔线。
- 对齐要严格：同一列的元素左边缘对齐，同一行的按钮、图标、文字垂直居中对齐。
- 留白要舍得：拥挤是最常见的不专业感来源。

## 3. 内容要真实

- 写贴合产品的真实中文文案和合理数据（真实的人名、价格、日期、数量），不要用 Lorem ipsum、“标题一”、“这是一段描述”。
- 列表和表格要有足够多、各不相同的条目（5–8 条），体现真实的数据密度，长短不一的文本也要排得好看。
- 图片位置用有意图的 SVG 插画、几何构图或品牌色渐变，不要用灰色方块打叉；头像用姓名首字配不同底色。
- 图标用内联 SVG，统一线宽和尺寸，不要用 emoji 代替。

## 4. 组件要完整

- 导航、页头、主体、页脚结构完整；当前所在页面在导航里有选中态。
- 重要组件要画出状态：按钮的默认、悬停、按下、禁用；输入框的默认、聚焦、错误、禁用；列表的空状态、加载中、出错。可以单独做一张组件画板，配合 `@dsCard` 输出设计系统卡片。
- 要求可交互时，控件必须真的能用：切换 Tab、展开收起、计数、跳转画板，用 DCLogic 状态实现，`style-hover` 和 `style-active` 给出反馈。
- 重复使用的组件抽成 `dc-import`，保证跨画板一致。

## 5. 画板编排

- 按用户流程从左到右排列画板，同一流程放在同一 page，画板标题写清是哪个页面或状态（例如“首页 · 已登录”“设置 · 编辑头像”）。
- 画板之间用相对链接串成可点击的原型流程。
- 一个页面有明显不同的状态（空、满、错误）时，并排放成几张画板对比，而不是只画理想状态。

## 6. 可读性

- 正文与背景对比度至少 4.5:1，弱化文字也不要淡到看不清。
- 正文字号不小于 14px，行高 1.5–1.7；数字列右对齐并使用等宽数字（tabular-nums）。
- 不只用颜色传达信息：状态同时配图标或文字。

## 7. 要避开的“AI 味”

- 大面积紫蓝渐变背景、玻璃拟态和霓虹光晕滥用。
- 所有内容居中堆叠，三张一模一样的特性卡片横排了事。
- 卡片套卡片、处处都是圆角和阴影，层级混乱。
- 用 emoji 当图标，按钮文字是“点击这里”“了解更多”。
- 每个画板的颜色、圆角、字号各不相同。

## 8. complete 之前自查

逐条过一遍，有不满足的先 save 修改：
1. 所有画板只用了 designSystems 里的颜色和尺寸，风格一致。
2. 每屏都有明确的视觉焦点，对齐整齐，留白充足。
3. 没有占位文字和灰色占位块，数据真实、条目足够。
4. 关键组件画出了交互状态，要求可交互的控件确实能用，画板之间的跳转能走通。
5. 文字对比度和字号满足可读性要求。
