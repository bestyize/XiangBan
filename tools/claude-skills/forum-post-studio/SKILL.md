# 论坛图文创作

使用本 Skill 目录下的 `scripts/forum_posts.py`。将下文的 `<skill>` 替换为本目录的实际绝对路径。先读 `references/workflow.md` 中的格式和调用说明。

## 工作流程

1. 检查 `FORUM_URL` 与 `FORUM_EDITOR_TOKEN` 环境变量是否已配置，只检查是否存在，不输出令牌。首次使用按引用文档安装 Python 依赖。缺少凭据时仍可继续本地创作与离线校验。
2. 运行 `python <skill>/scripts/forum_posts.py context`，读取真实板块 slug、说明、标签、公开帖子数、绑定作者和发布权限。不要编造 slug。结合用户目标和近期帖子，优先填补内容少的板块；运行 `recent --category <slug>` 检查已有主题。
3. 明确篇数、读者和主题方向；未指定时先准备 5 篇，避免相同内容换标题重复发。将选题清单另存到稿件目录外，避免被当作帖子导入。
4. 按用户要求检索资料；版本、价格、配额、活动有效期等时效内容必须核实。记录真实来源，无法核实的内容说明不确定或换题。不要编造亲测、用户评价、截图、链接、参数、浏览量或对话。
5. 每篇生成一个 `.md`，配图放在该 Markdown 所在目录下的 `images/`。具体格式见引用文档。教程按场景、步骤、结果组织；推荐帖按用途、差异、限制组织；讨论帖简短，提出具体可回答的问题。用短段落、合适的小标题、列表和代码块；避免整批都套同一种长文章结构。
6. 通过本地可用的浏览器、截图或生图工具生成并保存真实图片。优先使用实际界面截图、原创示意图及允许使用的素材，写清图注和必要来源。若工具不可用，继续可完成的文字工作并报告缺图，不虚构资产文件。提交的每一张图片必须有本地文件；不要使用外部热链、HTML img、SVG、Base64 图片正文或需要父目录跳转的路径。
7. 运行 `validate <目录>`。这一步检查文件结构和元信息；服务端导入会进一步校验缺图、真实图片格式、作者权限和正文。修复错误，按需运行 `pack <目录> --output <路径.zip>` 供用户上传后台。
8. 用户要求导入时运行 `import <目录或ZIP> --report <目录外的report.json>`。默认只生成待发布稿。根据 JSON 结果修复失败项，保留原 id；只有用户要求更新已有待发布稿时才加 `--overwrite`。服务端拒绝覆盖已经发布的同编号稿件。
9. 用户授权发布这批稿件时，运行 `publish --report <report.json>` 或按明确的稿件 ID 发布。用户已要求直接发布则继续完成，无需重复索取确认；如果只要求创作或导入，不自行发布。无发布权限的令牌将稿件交给后台处理。
10. 返回选题/文件位置、导入成功失败数量和正式帖子链接。失败只能报告失败，不把导入成功称为发布成功。保留报告，重试发布使用原稿件 ID，以利用服务端幂等处理。

## 内容边界

遵守读取到的板块说明。使用站方指定的编辑账号，尊重其权限。不要创建假用户互动或虚构个人经历。参考第三方内容时自行组织和补充价值，保留必要的来源链接。
